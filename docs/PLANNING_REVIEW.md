# 最新 기획 통합 검토 — 2026-11-11

## 검토 범위와 증거의 한계

사용자가 첨부한 10개 문서를 모두 반영하고 기존 문서와 비교했다. UI 전용 명세, 프로토타입 시행착오, 통합 개선안을 추가했다. 최초 반영 커밋은 `d82d796`이다. 이 문서는 **설계 정합성 분석**이며, 다른 프로토타입의 플레이 테스트를 UE5 본작의 실행 검증으로 간주하지 않는다. 클라우드에는 최신 로컬 게임 소스·엔진·프로토타입 원본 실행 로그가 없다.

읽기 순서와 실행 기준은 [UE5 구현 기준](UE5_IMPLEMENTATION_CONTRACT.md), 단계별 범위는 [2단계 계획](PHASE2_PLAN.md)을 따른다. 이 문서의 대안은 사용자가 확정한 규칙으로 취급하지 않는다.

## 구현 전에 선택할 설계 충돌

### R09. 요격 명중률 뺄셈이 함재기 완전 면역을 만듦 — 요격 구현 전

[함대 전투](FLEET_COMBAT.md)의 최신 명시식대로 `명중률 - 회피율`을 적용하면 다음 값이다.

| 요격 | 함재기 회피 62% | 포드 회피 40% | 미사일 회피 25% |
| --- | --- | --- | --- |
| 레이저 72% | 10% | 32% | 47% |
| 실탄 62% | **0%** | 22% | 37% |

이 값은 정적 산술 검산이며 실제 플레이 측정이 아니다. 확률을 0~1로 제한하는 것만으로 0% 문제는 해결되지 않는다. 회피 성장 시 레이저도 0%가 될 수 있다. `명중 × (1-회피)`를 쓰면 함재기에 각각 27.36% / 23.56%지만 **확정된 뺄셈 규칙을 바꾸는 대안**이므로 자동 채택하지 않았다. 뺄셈 유지+최소 명중률 보장 또는 확률 결합식 변경 중 선택이 필요하다. 한 번 회피를 뺀 뒤 다시 회피 주사위를 굴리는 중복 패널티도 피해야 한다.

### R10. 일반 미사일의 VLS 곡선과 발사 후 경로 수정 금지 — 무장 구현 전

일반 미사일은 경로 수정 불가지만 연출은 VLS 곡선 비행이다. **발사 순간 고정한 초기 곡선·탄도**와 **움직이는 표적을 따라 바꾸는 유도 경로**를 분리하면 둘을 양립시킬 수 있다. 이 방식이 추천안이다. 곡선 연출을 이유로 모든 미사일을 유도 무장으로 바꾸지 않는다. 살보 도중 표적 상실·시설 파괴 시 미발사 잔여탄 처리도 결정해야 한다.

### R11. 쉴드의 수동 완충과 비전투 복구 — 피해 시뮬레이션 전

활성 전투 중 회복 금지, 파괴 후 딜레이·3%/s·50% 재가동, 비피격 15초 이후 완충 예외를 하나의 상태 전이로 구현해야 한다. ‘15초 후 즉시 100%’인지 ‘15초 후 같은 속도로 100%까지 회복’인지는 미정이다. 수동 재충전 중 쉴드가 꺼지는지와 피격 중단 여부도 미정이다. 최대치·회복률·승무원·중복 버프 적용 전 기본값을 명시해야 한다. 기본 3%/s, 딜레이 6.5초를 가정하면 0→50% 재가동은 **약 23.17 게임 초**다. 이 가정은 효율 보정 전 시험값이다.

### R12. 정지·자세 유지·충돌 분리·FTL의 충돌 — 이동 수정 전

기존 ‘도착 자세 유지’와 새 ‘자동 도착 후 수평·편대 정렬’은 조건을 나누면 양립한다. 하지만 수동 Pitch/Roll까지 강제로 수평 복원하면 상하 사격과 장갑 회전 명령을 덮어쓴다. 수동 자세·교전 자세·자동 도착 정렬을 별도 상태로 둬야 한다. 하드 충돌 분리가 엔진 파괴·FTL 고정 함선을 수동 이동시키는 결과를 허용할지, 접촉한 다른 함선을 대신 밀지 역시 명시해야 한다. 추진 이동 금지와 접촉 침투 해소를 같은 이동 명령으로 처리하지 않는다.

### R13. UI 입력 충돌과 창 수명 — UI 기초 구현 전

- 새 부대 선택 `1~9`와 무장 그룹 `1~3`이 충돌한다. **부대 키는 최신 확정 유지**, 무장 그룹은 별도 리바인드 액션으로 분리하며 대체 기본키는 미정이다.
- 기존 F1/F2 함선 선택·1/2/3 배속·R 이동 입력은 최신 F1~F4 배속·R 수리 지정과 충돌한다. 구 바인딩을 함께 켜 두지 않는다.
- ‘미선택 시 전체 창 숨김’과 ‘최대 2개 창 핀 유지’의 관계, 창 닫기와 함선 선택 유지의 관계를 정해야 한다. 초기 검증에서는 미선택 시 비고정 상세창 숨김을 보장하고 핀 동작은 별도로 검증한다. 핀 예외를 확정한 것으로 간주하지 않는다.
- 우클릭 적함 타겟 우선 20~25px와 8px 고도 드래그 임계값은 입력 모드별로 분기해야 한다. UI 위 드래그·공격 지정·이동 확정·선택 해제를 같은 클릭으로 중복 실행하지 않는다.
- `ESC` 선택 해제는 PIE 기본 종료키와 충돌한다. 에디터의 기본 동작과 실제 게임 입력 검증을 구분한다.

### R14. 개별 무장 내구도와 기존 피해 경로 — 무장 피격 구현 전

WeaponMount HP가 새로 생겼지만 외장 포탑 피격이 장갑·시설·전체 HP와 어떤 비율로 연결되는지 아직 없다. 같은 한 발을 포탑 HP·시설 HP·전체 HP에 각각 원래 피해로 적용하면 피해가 증식한다. **충돌 위치에 따른 한 피해 사건의 수신 대상과 전달량**을 정해야 한다. 포탑 자체 파괴, 무기제어실 전체 정지, 탄종 공급 정지는 서로 다른 발사 불가 원인으로 유지한다. 하나를 수리했다고 나머지 고장이 풀려서는 안 된다.

### R15. 격납고 1:20과 최대 100대의 범위 — 격납고 구현 전

이전의 항모 설치 제한 없음과 프로토타입의 ‘최대 100대’는 적용 범위가 불명확하다. 100대가 테스트 예산인지 모함당 게임 규칙인지 정해야 한다. 1:20은 소형함 수용 슬롯과 함재기 수용량의 환산으로 기록하고, 전장 액터 수에 맞추어 임의로 게임 소유량을 자르지 않는다. 동일 기체 ID가 보관·출격·귀환·파괴에 중복 계상되지 않아야 하며 ‘출격 재고 차감’과 ‘완파 영구 차감’을 둘 다 총 소유량에서 빼면 이중 손실이다.

### R16. 1:5 전투력과 상대 수치의 기준 — 밸런스 조정 전

1:5는 평균 전투 결과 목표이며 HP·DPS·무장 수 모두를 각각 5배 하는 공식이 아니다. 각 칸에 기존 면 장갑 100%를 부여하면 전체 장갑 총량도 증가하므로 현재 프로토타입 기준 HP·DPS·유효 장갑·비용·동일 자원 편대의 실측을 함께 봐야 한다. ‘이동 50% 하향’, ‘무장 HP 2배’, ‘수리속도 2배’는 원래 절대값과 버전이 없어 재현할 수 없다. 프로필에 **최종 절대값·단위·기준 버전**을 저장하고 매 실행 때 0.5/2.0을 누적 적용하지 않는다.

### R17. 6면 구획과 층별 슬롯은 서로 다른 식별자 — 레이아웃 구현 전

전/후 단일 면은 여러 내부 슬롯에 걸치므로 `장갑 구획=방`으로 구현하면 방 하나 파괴로 전면이 증발한다. 6면 좌표·칸 선택 → 내부 층/슬롯 매핑 → 시설 피해를 분리한다. 2층 총합 26은 산술 정정했지만 행·열 방향과 경계의 귀속은 각 함체 데이터에서 명시해야 한다. 구 문서의 ‘외부 파괴 시 해당 장갑 파괴’에는 최신 전/후면 예외가 우선한다. 사보타주 장갑 보존도 유지한다.

### R18. 생존·나포·관제 상실·연출의 동시 사건 — 강습·함재기 구현 전

완파가 결정된 즉시 발사·점령·도킹·수리·포획을 종료하고 내부 인원 사망을 판정한다. 2~4초 침몰 연출은 이 판정을 늦추지 않는다. 모함 나포로 기체 소속은 바뀌어도, 이미 고장 난 함재기 운용 시설이나 파괴된 기체를 복구하지 않는다. 포드 웨이브 합류 지점이 파괴되거나 선도 포드가 격추될 때 후속 포드의 재선정, 귀환 목적지 변경, 포드별 탑승자 추적은 별도 상태가 필요하다. ‘분대 유닛 1개당 포드 1개’가 확정 표현이므로 제목의 ‘병력당’을 병사 1명당으로 확대 해석하지 않는다.

### R19. 격리 뷰어가 두 번째 전투 시뮬레이션이 되면 안 됨 — 뷰어 구현 전

`SubViewport`, `own_world_3d`, `accept_event`, `MOUSE_FILTER_STOP`, `MultiMesh`, `basis`는 다른 엔진 프로토타입 표현이다. UE5 런타임 구현 방법은 별도다. 프리뷰 액터가 무기를 발사하거나 Tick으로 피해를 계산하면 원본과 합쳐 이중 피해가 발생한다. 표시용 상태·이펙트만 동기화하고 마우스 입력을 별도 소비한다. 숨긴 창의 캡처·Tick을 중단하며 적함 내부·승무원·시설 HP는 강습 전 공개하지 않는다. 전장 디버그와 실제 플레이 정보 접근을 구분한다.

## 회귀 검증과 제작 순서

실행할 시험 항목·단계 배치는 [UE5 구현 기준](UE5_IMPLEMENTATION_CONTRACT.md)과 [2단계 계획](PHASE2_PLAN.md)에 연결했다. **지금은 2A의 입력·기동 기반, 다층·6면 피해 데이터와 최소 UI를 진행할 수 있다.** R09의 확률식은 요격을 완성하기 전에, R11은 정식 쉴드 회복을 확정하기 전에, R13은 단축키·핀 기능을 고정하기 전에 결정해야 한다. 미결정 사항 때문에 관련 없는 단계까지 모두 멈출 필요는 없다.
