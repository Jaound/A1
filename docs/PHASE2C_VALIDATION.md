## 검증한 동작

PD 자동 검사는 실거리·시설 인원/점령/파괴·장착점 HP, 주변 아군 방어, 우선순위, `명중률 × (1−회피율)` 한 번의 판정, 한 발사 기회의 중복 사용 방지와 요격된 미사일의 후속 피해 차단을 검사한다. 강습선을 포함한 일반 함선은 PD 대상이 아니다. PIE의 `2C-PD-ACTUAL-MISSILES`와 `2C-AIRDEFENSE-LIVE`는 실제 적 발사체를 요격한다. 같은 18게임초에서 일반 호위의 7기 격추와 방공함 호위의 38기 격추를 관찰했으며 이는 해당 편성·시드의 사례이고 최종 밸런스 비교가 아니다.

함재기는 재고 ID·HP 보존, 용량 증가 시 무료 생성 금지, 20대/소형함 1척 배타 용도, 출격·명시 복귀·재출격, 격납고/관제 정지, 대체 격납고 도킹, 모함 완파·소속 변경·기발사 공격의 원 소속 유지, FTL 회수 대기·명시 포기를 확인했다. 실제 기체 탄은 함선 충돌과 적 함재기 충돌을 처리한다. 첫 공중전 검사 실패는 선행 조준과 상대 이동 sweep을 수정한 뒤 통과했다. `2C-RECALL-SAME-IDS-NO-HEAL`, `2C-REDEPLOY-NO-RESURRECTION`, `2C-CARRIER-CAPTURE-AFFILIATION` 등은 수량 표시만이 아니라 실제 레코드를 검사한다.

운송은 개인당 원 포드 1기, 개별 발사 시간과 시설 재확인, 활성 쉴드 차단, 실제 도착과 로컬 면·높이·층 정보, 세력별 내부 잔류 보호, 원 포드 귀환과 잔여 HP, 목적지 이탈/완파 및 대체 귀환을 확인했다. `2C-POD-LIVE-PARTIAL-PD`에서는 실제 PD가 10기 중 6기를 격추하고 4명이 진입했다. 강습선의 접근·이송·같은 수송선 회수, 진입 전/후 수송선 상실, 무료 탈출 포드 생성 금지와 수동 XYZ/Hold 우선도 검사했다. 토큰 도착은 작전 성공이나 함교 나포를 실행하지 않는다.

시간 검사는 동일 시드 `260112`, 동일 초기 편성에서 18게임초 동안 1·2·3배속의 발사·명중·PD·함재기·포드·승객·선체/쉴드 결과를 비교했다. `2C-PD-CLOCK-123`, `2C-MIXED-CLOCK-123`의 상태가 일치했다. 혼성 사례에서는 기체 80개 중 68개 출격·12개 완파, 기체 발사 748회·명중 700회, 내부 승객 10명이 같았다. 정지 중 시계 불변과 기존 카메라 실제 시간 동작은 C++/2A 회귀 검사로 확인했다. `2C-LOWFPS-SWEPT`는 60Hz 호출과 250ms 게임시간 묶음을 비교한다. 이것은 저FPS 상당의 큰 델타와 빠른 탄의 통과 방지 검사이며, 실제 OS 프레임률을 4fps로 고정해 직접 조작한 결과는 아니다.

장면 전환·재시작과 3/5/9척 확장 뒤 F5/F6/F7 복구, UI 새로 그리기 시 재고 무변경, 상세 창 입력 소비, 월드 표식과 목록의 고유 ID, 표식 위 카메라 제스처 소유권을 확인했다. `GetActionCenter` 등 안정적인 조회 경로로 버튼을 찾아 API를 호출하므로 화면 좌표와 문구 변경에 대한 의존을 줄였다. `2C-RENDERED-FRAMES-ADVANCE`는 API 묶음만 실행하지 않고 실제 렌더 프레임에서 전투 시간이 진행되는지도 확인한다.

## 플레이 화면 보완과 직접 입력 경계

기본 DEV/상세 창을 닫고 한국어 핵심 명령, 아군/적/선택 표식과 목록, 표적·이동/고도·명령 접수·발사 차단 이유를 분리했다. F6 초기 카메라를 교전 축에 맞추고 Home 전체 보기/F 선택 추적을 유지했다. 함종별 임시 선체·함교·엔진 형상과 선택 충돌을 보완했고 탄도·포구·명중·쉴드 반응은 읽기 전용 표시로 연결했다. 함선 이름이 선체에 겹치던 문제와 연속 명중 문구가 중첩되던 문제도 보완했다. 개발 도구는 UE의 F8 eject와 충돌하지 않는 **Insert**에 남겼다.

- [개선 전 F6](validation/Phase2C-Before-F6.png), [개선 후 F6](validation/Phase2C-After-F6.png), [960×640 화면](validation/Phase2C-960.png).
- F5/F6 × DEV 켜짐/꺼짐 × 상세 창 열림/닫힘의 개선 후 8조합은 [화면 증거 폴더](validation/Phase2C-Screens)에 저장한다.
- [짧은 혼성 교전 영상](validation/Phase2C-Combat-API.mp4)은 엔진 프레임 72장을 12fps로 묶은 **6게임초의 API 진행 영상**이다. 실제 사람이 6초 동안 조작한 녹화나 입력 지연 측정이 아니다.

개선 전 캡처에서는 기존 상세 창 닫기 API가 없어 모든 조합이 **상세 창 열린 상태**였다. 이후 읽기 전용 속성 설정 시도도 실패했으며, 그 결과를 ‘개선 전 닫힌 화면’으로 사용하지 않았다. 새 `SetDetailsOpen`으로 개선 후 전체 조합을 캡처한다. 캡처는 외형/배치 증거이며 정지 화면으로 조작감·타격감의 최종 합격을 주장하지 않는다.

Windows 화면 제어는 `window capture timed out: timed out waiting on channel`로 실패했다. 창을 다시 선택하고 활성화한 뒤 1회 재시도해도 같은 결과여서 반복을 멈췄다. OS 클릭/키 입력은 수행하지 않았다. [가이드의 짧은 직접 플레이 확인](PHASE2C_GUIDE.md#재검증과-직접-플레이-확인)에서 선택 → 이동·고도 → 공격 → 복귀, 창 여러 개, 일시정지/배속, 장면 복귀를 사용자가 확인할 수 있다. 최종 검사를 실행한 Editor는 혼성 교전 PIE·일시정지·DEV/상세 창 닫힘으로 남겼다.

## 성능 측정

독립 Editor 한 프로세스, DX11, NVIDIA GeForce RTX 5070, 논리 CPU 12개, viewport **1133×936**, 1배속, 시드 `260112`를 사용했다. 장면마다 3초 준비 후 실제 Slate 프레임을 8초 측정했다. 엔진 기본 VSync/프레임 제한을 사용했으며 설정을 바꾸지 않았다. 기능 검사의 API 빠른 실행 시간과 구분한다. 성능 실행은 `127c6a6` 기준이며 최종 이름표/명중 문구/회수 실패 메시지 보완 이후의 성능을 다시 측정한 것은 아니다.

9척 조건은 평균 약 **55fps**다. 더 큰 규모나 장시간 안정성을 보장하지 않으며, 10~15분 전투 시간을 강제하거나 이를 맞추려고 화력을 낮추지 않았다. 마지막 공격 수는 측정 종료 시점의 살아 있는 객체 수이며 전체 구간 최대치가 아니다.

## 데이터·임시 정책과 미지원 범위

기존 `Calibration_D116_v06`과 `OVCalibrationData.inl`은 보존했다. `GenerateD116Calibration.py --check` 통과. `reference/IntegratedCombat/profile.json`의 Git LF 바이트 SHA-256은 **`639f0a233a3c0ed6bf97edc407754c304c3a4ff8499f1b75ec383a78d5f60d4b`**, CRLF 체크아웃 바이트는 `7ca9baca06f9f295d887445d3e1a4f34e77bb485be685281ccc10419551ddc22`다. 필드 매핑·단위 변환은 [기존 교정 기록](PHASE2BR_D116_CALIBRATION.md), 2C 채택값과 담당 R번호는 [2C 데이터/정책 표](PHASE2C_GUIDE.md#데이터-출처와-남은-정책)를 따른다. Python 집계 명중 근사·관통 계수나 승률을 UE 충돌 규칙으로 복사하지 않았다.

확정 경계는 PD의 곱셈 확률·대상 제한, 격납고 배타 용량, 개인당 1포드, 활성 쉴드 진입 차단, 원 운송수단 재사용이다. PD 기본 피해 12/주기 0.5초, 혼합 장착 순서, 함재기 탄속/사거리/충돌 크기, 도킹 시간·여유, FTL 10초 등은 교체 가능한 시험값이다. 포드 부분 격추 장면만 PD 피해 160, 운송 시험 장면만 적 쉴드 DEV 정지를 사용하며 이를 일반 규칙이나 실제 경제 결과로 숨기지 않는다.

미지원 항목은 실제 영웅 스킬/성장, 선내 이동·자동전투·함교 나포 전체, 연구/경제 UI와 자원 수리, 다른 모함의 회수, 독립 소형함의 실제 격납/출격/수리/나포 운용, 대체 강습선 회수·포로/비상탈출 상세, 성계 여행, 환경 4종, 최종 3D 에셋과 초대형 혼합 티어 해결이다. DEV 승객/진입점 복귀 확인/시험 공급 수리는 각각 운송·이벤트·공급 인터페이스 검증이며 미지원 기능의 성공 처리가 아니다.

## 실행과 재개

실행·검사 명령은 [가이드](PHASE2C_GUIDE.md), 단계별 커밋과 정확한 재개 상태는 [PHASE2C_PROGRESS](PHASE2C_PROGRESS.md), 전체 프로젝트 최신 상태는 [WORK_STATUS](WORK_STATUS.md)를 따른다. `RunPlay.ps1 -Scene 5 -Width 1280 -Height 800` 또는 ControlRange PIE → F7로 시험하고 F1로 진행한다. 기존 F5/F6은 유지한다. 실행 바이너리·Intermediate·Saved 전체는 커밋하지 않고 필요한 검증 증거만 별도 보존한다.
