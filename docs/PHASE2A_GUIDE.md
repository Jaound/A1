위 이동·선회는 **기본값**이다. 실제 이동·선회에는 엔진 효율이 곱해진다. 현재 시험 레이아웃은 중복 시설 손실을 비교하기 위해 엔진 3기를 넣었으므로 전원이 정상일 때 효율은 200%다. 시험 데이터의 규모·속도는 정식 밸런스가 아니며 다른 프로토타입의 상대 감소율을 다시 곱하지 않는다. UE 좌표는 cm, 위쪽은 +Z, 함선 전방은 로컬 +X다.

레이아웃은 `UShipLayoutDataAsset`, 선체·시설·장갑·개별 무장의 현재 HP와 인원·점령은 함선별 `UOVShipSystemsComponent`가 보유한다. `Content/Layouts`에 14/26/38 장갑 구획의 `DA_Test1Deck`, `DA_Test2Deck`, `DA_Test3Deck` 자산을 포함한다. 컨트롤러는 이 자산을 먼저 읽고, 누락됐으면 `MakeTestLayout`으로 같은 규격의 시험 레이아웃을 메모리에 만든다. 테스트 함선의 접근 가능 여부는 정식 해금 순서와 무관하다.

장갑 ID와 내부 슬롯 ID는 별개다. 전면·후면은 각각 한 구획이며 여러 내부 방으로 연결된다. 좌·우·상·하면은 각각 `3×층수` 구획이다. 슬롯 ID는 `D층_X열_Y행`, 장갑 ID는 `Armor_F면_R행_C열`, 무장 ID는 `Weapon_번호` 형식이다. 현재 상·하면에서 선택한 장갑이 여러 방에 걸칠 때 피해 지점으로 내부 방을 결정한다.

| 입력 | PlayGame3 동작 |
| --- | --- |

| `Backspace` | 진행 중인 이동 입력 취소 |

회전 중 커서가 화면 경계를 넘어도 시작 화면이 회전을 계속 소유한다. 버튼 해제 또는 포커스 상실 시 종료하며, Alt+왼쪽 드래그 중 Alt를 먼저 놓아도 종료한다. 버튼을 새로 누르면 현재 위치에서 다시 시작한다.

PlayGame3의 보정 기준은 원본 거리 단위당 UE 14cm다. 시험장 함선의 대략적인 화면 점유율을 기준으로 선택한 값이다. 기본 UE 시선은 yaw +32°, pitch −38°, 거리 4060cm다. 세로 FOV는 52°이며 현재 뷰포트 종횡비로 수평 FOV를 계산한다(16:9에서 약 81.86°). 거리 범위는 490~9520cm이며, 줌 시 선택 함선 레이아웃의 스케일 적용 반크기 벡터 길이 ×1.45를 하한에 반영한다. 휠 한 단계는 거리 ×0.88 또는 ×1.13이다. 평면 이동은 `2520 × clamp(거리/3360, 0.45, 2.5)` cm/s, 추적은 시간 상수 0.1초의 지수 보간을 적용한다.

회전은 UE 뷰포트 픽셀 이동량에 yaw +0.32°/px, pitch −0.28°/px를 적용한다. pitch 범위는 −84°~−12°다. 포인터 픽셀 차를 쓰므로 MouseX/Y 감도 0.07 및 FOV 축 배율은 PlayGame3 회전에 적용되지 않는다. 고도는 8px 이상 끌면 7.7cm/px, 시작점 대비 ±2520cm 범위로 바뀌며 기존 시험장 Z 제한(−1500~4000cm)도 적용한다. Legacy 회전은 기존 UE 마우스 축 델타와 0.3 배율을 사용한다.

직접 확인 순서

1. `P`로 프로필을 번갈아 켜고 `Home`, 휠, WASD, `F`를 비교한다. 정지 및 1/2/3배속에서 동일하게 움직이는지 본다.
2. 전장과 외부 프리뷰 양쪽에서 MMB 및 Alt+왼쪽 드래그를 시작해 경계를 건넌다. 시작 화면만 회전하는지 확인한다. Alt 먼저 해제, 창 밖 해제, 다른 창으로 전환 후 복귀도 확인한다.
3. 아군을 고르고 전장 우클릭으로 즉시 이동, 상하 드래그 이동을 각각 해본다. 노란 미리보기와 초록 목적지가 일치하는지, UI 위에 놓으면 취소되는지 확인한다.
4. 적 짧은 우클릭, Shift 강제 이동, Ctrl 방향, V/Shift/Enter 정밀 이동을 각각 확인한다. `R`, `Ctrl+숫자`, `F1~F4`도 확인한다.

## XYZ 이동·정지·자세·표적

1. 아군을 선택하고 `V`, `V MOVE` 또는 전장 오른쪽 마우스로 이동 입력을 시작한다.
2. 커서로 X·Y 목적지를 정한다. 전술 디스크와 마우스 광선 투영은 입력 시작 시 대표 함선의 Z 평면을 함께 사용한다.
3. `Shift` 또는 오른쪽 마우스를 누른 채 위아래로 드래그하면 X·Y를 유지하며 Z를 바꾼다. 최초 8픽셀 이동부터 고도 표시가 나타난다. 휠도 Z를 250 cm씩 바꾸는 보조 입력이다.
4. 키/버튼을 놓으면 고도를 유지하며 X·Y를 계속 조정한다. 고도 조작이나 UI 통과 후 첫 재진입에서는 커서 기준을 다시 잡아 목적지 점프를 줄인다.
5. 전장 왼쪽 클릭 또는 `Enter`로 확정한다. 오른쪽 버튼을 놓는 것만으로 이동을 확정하지 않는다. `Backspace` / `CANCEL`은 아직 확정하지 않은 명령만 취소한다.

노란 구·연결선은 미리보기, 확정 뒤 초록 선은 실제 목적지다. 현재 임시 입력 범위는 X·Y 각각 −6000~6000 cm, Z −1500~4000 cm다. 거의 수평인 광선이나 카메라 바로 앞의 불안정한 교점은 받아들이지 않는다. 상세 창 위에서는 전장 목적지 갱신을 멈춘다.

다중 이동은 대표 함선과 각 함선의 현재 위치 차이를 유지한 목적지를 보낸다. 완성된 편대 속도 동기화나 경로 큐는 없다. 확정한 이동은 해당 아군을 MANUAL로 전환한다. 이동은 가속과 도착 전 감속을 거치며, 느린 선회 중에는 정렬 정도에 따라 전진을 줄인다.

| 입력/버튼 | 동작과 경계 |
| --- | --- |
| `X` / `X STOP` | 현재 이동을 취소하고 관성 감속 후 Hold 유지. 진행 중인 수동 방향 회전도 현재 각도에서 멈춤 |
| `MANUAL` | 대표 함선의 지속 모드를 수동으로 설정 |
| `AUTO` | 대표 함선의 모드만 자동으로 설정. Hold·수동 자세를 보존하며 자동 전투 AI는 아직 없음 |
| `H` / `H FACING`, 이후 전장 클릭 | 클릭 방향으로 요 각도를 지정. 현재 Pitch/Roll 보존 |
| `PORT` / `STBD` | 대표 함선에 현재 각도 기준 −90° / +90° 요 방향 명령 |
| `T` / `T TARGET`, 이후 적 클릭 | 별도 공격 표적 설정. 이동 목적지·선택·수동/자동 상태와 분리 |
| 적 위 짧은 오른쪽 클릭 | 25픽셀 이내 움직인 클릭을 표적 지정으로 처리 |
| `CLEAR` | 대표 함선의 공격 표적 해제 |
| `R` | 보급수리 키 예약 안내. 이 단계에서는 실제 수리 주문 없음 |

새 이동 명령은 Hold를 해제하지만 명시한 수동 자세를 지우지 않는다. 따라서 측면을 향한 채 이동할 수 있다. 수동 자세는 제한된 회전 속도로 적용하며 정지 후 자동 표적 추적이 덮어쓰지 않는다. UI 방향 명령은 현재 요 회전만 제공하고, 임의 Pitch/Roll은 개발 API `SetManualAttitude`로 시험한다. 일반 이동 완료 후 수평·편대 정렬은 아직 후속 작업이다.

빨간 표적 선은 표적 지정 표시다. 사격·자동 공격·발사 효과는 2B 범위이므로 이 단계에서는 표적을 정해도 발사하지 않는다. 엔진 기능 상실·중립·완파는 이동을 제한하며, 함교 기능 상실은 직접 명령을 막는다. FTL은 충전 플래그의 이동 고정·주문 거부 경계만 있으며 충전 시간·실제 이동·UI는 없다.

충돌 분리는 각 함선 쌍을 한 번씩 처리하는 기초 구현이다. 현재는 크기 배율 기반 구형 반경, 약한 속도 회피와 위치 겹침 보정이며, 정밀 함체 충돌·체급 우선권·충각 피해는 구현하지 않았다. 엔진 정지 또는 FTL 고정 함선은 직접 밀지 않고 움직일 수 있는 상대를 보정한다. 둘 다 움직일 수 없을 때는 보정을 하지 않는다.

## 상세 창과 관측 화면

함선 선택 시 상세 플로팅 창이 열린다. 창 제목을 드래그해 이동하고 오른쪽 아래 모서리로 크기를 조절한다. `_`/`+`는 최소화/복원, `[]`는 두 가지 창 크기 전환, `X`는 닫기다. 다시 열 때는 `DETAILS`를 누른다. 선택을 해제하면 창도 숨긴다.

- `ARMOR / WEAPONS`: 독립 장갑 구획과 무장 위치를 선·도형으로 투영한다. 작은 장갑 표시점 또는 무장 사각형을 클릭하면 해당 ID와 HP를 선택한다. 가운데 버튼/휠은 이 프리뷰만 회전/확대한다.
- `1F` / `2F` / `3F`: 실제 존재하는 층의 슬롯을 표시한다. 슬롯을 클릭하면 시설 종류·HP·인원·Operational/Destroyed/Occupied/Uncrewed 상태를 확인한다.
- HP·쉴드·장갑·무장 READY/OFF·엔진/쉴드/레이더 효율은 실제 함선 런타임 상태를 읽는다. 무장 READY는 조건 판정이며 실제 발사를 뜻하지 않는다.
- 외부에서 선택한 장갑은 전장에 주황 상자로도 표시한다. 개발 피격 지점은 자홍색 구·내부 방 연결선과 마지막 Event/ID/선체 피해 기록으로 확인한다.
- `DEV: ON/OFF`는 시험 도구와 적 내부 공개를 전환한다. OFF일 때 적 내부 층·시설은 숨긴다. 현재 강습을 통한 정식 정보 공개는 없다.

이 프리뷰는 **상태를 읽는 간단한 3D 도형 투영**이다. 별도 함선 액터·AI·무기·피해 시뮬레이션을 만들지 않는다. 실제 전장 카메라의 SceneCapture/RenderTarget, 실제 자세·포탑·효과의 완전한 재현, 두 창 핀, 전술 센서 LOD, 피해 그래프·은하 줌은 후속 범위다. 숨김/최소화 시 프리뷰를 그리지 않으며 캡처 작업 자체는 아직 없다.

## 개발용 피해·복구 도구

`DEV: ON`에서 상세 창 아래 도구를 사용한다. 외부 뷰의 장갑/무장 선택과 내부 뷰의 시설 선택은 별도다. 시설을 바꾸려면 층 탭에서 대상 슬롯을 먼저 선택한다. 다음 도구는 보급수리·강습·무기 발사의 완성 기능이 아니다.

| 버튼 | 적용 대상·효과 |
| --- | --- |
| `HIT 150` (현재 피해량 표시) | 선택 장갑 중심에 외부 시험 피격. 쉴드가 남아 있으면 먼저 쉴드가 받음 |
| `ARMOR 0` / `FIX ARMOR` | 선택 장갑 HP를 0 / 해당 최대값으로 설정 |
| `DESTROY` | 선택 시설에 외부 파괴 시험. 연결 장갑 파괴·유폭·코어 완파 규칙 적용 |
| `SABOTAGE` | 선택 시설 공작 파괴 시험. 해당 시설의 장갑 직접 제거는 하지 않음. 유폭은 발생 가능 |
| `FIX ROOM` | 선택 시설의 물리 HP만 복구. 장갑·인원·점령·개별 무장·현재 쉴드·선체 HP는 별개 |
| `OCCUPY` | 선택 시설의 적 점령 상태 켜기/해제 |
| `CREW -2` / `CREW +2` | 선택 시설 인원을 2명씩 감소/보충, 필요 인원 범위로 제한 |
| `HIT GUN` / `FIX GUN` | 선택 개별 무장만 시험 피해/물리 HP 복구. 선체로 중복 피해를 주지 않는 R14 임시 경계 |
| `RESET` | 선택 함선의 시스템·이동 속도·목적지·표적·수동 자세 주문을 초기화하고 Hold 상태로 설정. 위치·카메라는 초기화하지 않음 |

3층 함체의 시설 외부 파괴는 3층→연결 상면, 2층→연결 좌우면, 1층→연결 하면 장갑을 제거한다. **전면·후면 장갑은 보존**한다. 1·2층 함체는 연결된 전후면 이외 구획을 제거하는 임시 시험 규칙을 사용하며, 이 연결 정책을 최종 확정으로 보지 않는다. 공작은 원래 장갑을 직접 제거하지 않으며, 뒤따른 유폭은 별도 피해 원인으로 처리한다. 3층의 상·하부 장갑이 0이고 그 아래 외곽 슬롯이 비었거나 파괴됐다면 중앙층 관통을 시험할 수 있다. 앞·뒤·측면에 같은 관통 규칙을 적용하지 않는다.

중복 시설 효율은 정상 가동률이 가장 높은 시설 100%와 나머지 각 50%의 합이다. 인원 부족·적 점령·물리 파괴를 구분하며, 무인 예외인 코어·보안은 인원 0만으로 꺼지지 않는다. 중복 레이더는 탐지 거리를 늘리지 않는다. 코어 파괴나 선체 HP 0은 완파이며 일반 복구 도구로 부활하지 않는다. `RESET`은 새 실험을 위한 명시적 예외다.

## 임시 수치와 미결정 정책

피해·쉴드 프로필은 `Unreal/OrbitalVanguard/Config/DefaultGame.ini`의 `[/Script/OrbitalVanguard.OVShipSystemsComponent]` 아래 `Tuning=(...)`에서 조정한다. 예를 들어 그 줄의 `ShieldRecoveryDelay`, `ShieldOverflowFraction`, `RecoveryPolicy` 값을 바꾼 뒤 에디터를 다시 시작해 적용한다. 프로젝트 내부 설정이며 전역 엔진 설정은 바꾸지 않는다. 이동은 `OVShip`, 입력/피해 크기는 컨트롤러 속성, 시설/장갑 기본값은 레이아웃 자산에서 조정한다. PIE 런타임 값 변경은 영구 저장이 아니므로 실험 프로필과 검증 결과를 별도로 보존한다.

| 항목 | 현재 기본값 |
| --- | --- |
| 가속 / 제동 / 도착 반경 | 1700 cm/s² / 2200 cm/s² / 5 cm |
| 고도 드래그 / 가까운 투영 거부 | 10 cm/px / 350 cm |
| 시험 외부·무장 피해 | `TestDamage=150`. HIT 버튼에 현재 값 표시 |
| 시설 HP / 필요 인원 | 일반 시설 100, 함교 180 / 유인 시설 10명 |
| 전면 / 그 외 장갑 HP | 400 / 100 |
| 쉴드 기본량 | 300 × 쉴드 시설 효율 |
| 회복 딜레이 / 회복 속도 / 재가동 | 6.5초 / 최대량의 초당 3% / 50% |
| 비피격 회복 기준 | 15초. `Gradual` 기본 정책에서는 이후 점진 완충 |
| 쉴드 초과 피해 전달 | 25% |
| 최대 장갑 경감 | 전면 75%, 그 외 60%; 남은 장갑 비율에 따라 감소 |
| 장갑 마모 / 시설 경로 선체 전달 | 입력 피해의 30% / 전달 피해의 50% |
| 유폭 | 기본 70 × 해당 탄종 무장 슬롯 수 × 티어 × 계수 1 |
| 레이더 | 기본 거리 6000 cm, 명중 보정 기본 0.1 × 시설 효율 |

R11 쉴드 예외는 확정 규칙과 구분한다. 전투 구간에서 활성 쉴드는 회복하지 않고, 비활성 상태는 딜레이 후 회복해 50%에서 재가동한다. 무피격 15초 뒤의 완충은 기본 `Gradual`과 시험 대안 `FullAfterNoHitInterval`로 분리했다. 수동 쉴드 전환은 기본 비활성(`bAllowManualShieldToggle=false`)이며 UI 버튼도 없다. 시설 수리만으로 현재 쉴드를 무료 완충하지 않는다.

R14 개별 포탑 피해의 선체 전달은 미정이므로 `HIT GUN`은 무장 HP만 바꾼다. R13의 완성 핀 정책과 무장 그룹 기본키, R09 요격 확률은 이번 단계에서 확정하지 않는다. 실제 탐지 공유·포탑 추적·사격은 2B, PD·함재기·포드는 2C, 선내 이동·점령 시간·나포는 3단계다. 시설의 사용 가능 여부 데이터가 존재한다고 해당 전투/운용 시스템 전체가 구현된 것은 아니다.

## 짧은 직접 조작 확인 순서

아래는 실행자가 확인하고 결과를 기록할 체크리스트다. 현재 직접 화면 제어는 캡처 실패로 확인하지 못했으며, OS 키보드·마우스 조작 성공을 주장하지 않는다. 자동 검사나 PIE API 성공으로 이 목록을 대신 완료 처리하지 않는다.

1. PIE 시작 후 KESTREL/ATLAS/표적을 클릭한다. 빈 곳과 `DESELECT`로 창 숨김, `DETAILS`로 재열기, Shift 다중 선택과 Ctrl+숫자 부대 저장을 확인한다.
2. 전장과 프리뷰에서 각각 가운데 드래그/휠을 사용한다. 프리뷰 조작이 실제 함선 자세·전장 카메라·목적지를 바꾸지 않는지 본다. 창 이동·크기·최소화·닫기를 확인한다.
3. `V`로 XY→Shift 드래그 Z→XY를 반복하고 UI 위를 통과한다. 노란 목적지가 튀지 않는지, `Enter`로 XYZ 이동하는지, 가까운 목적지에서 계속 선회하지 않고 멈추는지 본다.
4. 이동 중 `X`, 이어 `AUTO`를 누른다. 관성 감속 후 다시 출발하지 않는지 확인한다. `PORT/STBD` 또는 `H`로 방향을 정한 뒤 이동해 명시한 자세가 유지되는지 본다.
5. `T` 또는 적 오른쪽 클릭으로 표적만 지정한다. 선택/목적지/수동 모드가 바뀌지 않고 실제 사격도 일어나지 않는지 확인한다. `CLEAR`로 해제한다.
6. `F1/Space`로 정지한 채 카메라·창·명령을 조작하고, `F2/F3/F4` 후 재개한다. 시뮬레이션 시간·이동·쉴드 회복만 배속의 영향을 받는지 본다.
7. DEV 도구로 장갑·시설·무장 각각을 손상시키고 해당 ID/HP를 확인한다. 여러 번 HIT 후 쉴드 회복, 중복 엔진 인원 손실, 전후면 장갑 예외, 시설 수리와 인원/점령의 독립성을 비교한다. 실험 사이에는 RESET한다.
8. 1/2/3층 전환과 외부 14/26/38 구획을 확인한다. DEV OFF에서 적 내부가 숨는지 본다. 코어를 파괴한 뒤 일반 복구로 움직임이 부활하지 않는지 확인하고, PIE를 종료한다.

실패나 미확인 항목은 함선·시설/장갑 ID, 배속, 입력 순서, 창 크기와 `F9`/피해 로그를 함께 남긴다. 로그는 `Unreal/OrbitalVanguard/Saved/Logs`에 생성된다. 검증 범위와 근거는 [PHASE2A_VALIDATION.md](PHASE2A_VALIDATION.md)에 기록한다.
