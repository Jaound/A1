# 기획 문서 지도와 관리 원칙

> 정리일: 2026-11-17(KST). 이 문서는 기획의 입구와 담당 범위를 정한다. 게임 기능 구현 완료를 뜻하지 않는다.

## 폴더와 담당 범위

[폴더 안내](README.md)는 개요/분야 명세/수치/개발/분석/참조/과거 자료의 분류 기준을 정한다. 예전 경로는 [대응표](DOCUMENT_PATHS.json)로 찾는다. 이 문서는 계속 기획의 입구로 유지한다.

## D123 우주 환경 행동 규칙

[환경 명세](01_design/strategy/SPACE_ENVIRONMENTS.md)에 운석 충돌·파괴·지형 변화, 방사능 노출 피해·전투 판정, 플레어 부분 엄폐·정지, 블랙홀 실제 견인·중심부 완파·FTL 외력 예외를 채택했다. D124는 이동·무장·요격 등 작동 기능 일시 중단을 확정하고 [초기 정지시간 민감도](../reference/SpaceEnvironmentCalibration/README.md)에서3초/강한5초를 시험 후보로 제안했다. 수치·기능별 재개·인양은 R36에서 계속 설계한다. 현재UI/모델 작업에 환경 구현을 자동 추가하거나 기존 결과를 새 환경 검증으로 바꾸지 않는다.

## D121/D122 최신 제작 우선순위

항공모함 최대4격납고·항공순양함 최대8격납고/T4전용주포2문을 정식동기화한다. 실제장착/기체재고는별개다. [UI 명세](01_design/interface/UI_SYSTEMS.md)의 좌측중심지휘·자동상세·영웅/함재기이미지카드·이동/리사이즈창·무장라이브뷰·사건경보와 실제모델적용을 우선한다. [로컬 실행 지시](03_development/PLAY_UI_R2_PROMPT.md)를 따르며UE구현완료나캠페인확장을뜻하지않는다.

## D116 현행 통합 시험

[통합 수치v0.6](02_balance/INTEGRATED_COMBAT_BALANCE.md)·[결과](04_analysis/INTEGRATED_COMBAT_RESULTS.md)에서 새 쉴드/강습 보호·무장 무력화·관측 정보·함재기 연구/개조를 검토한다. 영웅/수리의 기본 수치는 v0.5를 계승하고 D116의 변경 필드는 v0.6 시험 프로필이 덮어쓴다. v0.3/v0.4 통계는 과거 비교다. 이번에는 사용자 요청으로 시뮬레이션 보류를 해제했으며 UE 완료를 뜻하지 않는다.

## D118 UE 작업 재개

현재 확인한 원격2B는 ca6e8e5이며 최초 제작을 반복하지 않는다. [구현 상태](03_development/IMPLEMENTATION_STATUS.md) → [2B-R v1](03_development/PHASE2_PLAN.md) → [로컬 실행 프롬프트](03_development/PHASE2B_REVISION_PROMPT.md)를 사용한다. D116확정 정책·시험 수치·D117환경 초안을 구분해 이번 적용/후속 범위를 정했다.

## D119 수송선 체급 변경

수송선은 [함대 전투](01_design/fleet/FLEET_COMBAT.md)의 현행 **중형 임무선**이다. 이전 소형 시험 수치/결과는 당시 버전 재현용이며 새 중형 수치는 [R37](00_overview/OPEN_QUESTIONS.md#r37)에서 정한다. 외형 시안은 실제 층수·무장·적재량·크기를 확정하지 않는다.

## 읽기 순서

1. [GDD](00_overview/GDD.md)로 게임의 정체성과 플레이 순환을 파악한다.
2. [결정 기록](00_overview/DECISIONS.md)에서 최신 변경과 근거를 확인한다.
3. 이번 작업의 **담당 명세**를 아래 표에서 찾아 읽는다.
4. [미결정 목록](00_overview/OPEN_QUESTIONS.md)에서 관련 정책의 결정 여부를 확인한다.
5. [구현 상태](03_development/IMPLEMENTATION_STATUS.md)와 [2단계 계획](03_development/PHASE2_PLAN.md)을 읽고 기존 코드를 보존하며 이어간다.

## 문서의 권한과 상태

- **현행 명세:** 위 담당 문서의 확정 규칙. 반복 요약보다 원 규칙을 관리하는 문서를 따른다.
- **미결정:** 상충하는 최신 문구나 미정 수치. 대안·추천을 자동 확정하지 않는다. `R` 번호로 관리한다.
- **설계 초안:** [기지·생산·연구 밸런스v0.1](02_balance/BASE_BALANCE_DRAFT.md)의 새 비용/시간/운영안. 사용자 요청으로 제안했지만 채택/실측 전이며 확정 규칙을 대체하지 않는다.
- **D113 운송/영웅 검토:** [개인별 포드·강습선·공방 영웅 수·코스트 원인](04_analysis/BOARDING_REVIEW.md). 초대형 화력 유지와 강습선 공격0/PD1은 확정, 새 절대 수치는 후보이며 기존v0.3 연동의PD/방어자 가정을 대체해 읽는다.
- **이전 장기전 후보:** [v0.3](02_balance/FLEET_ENDURANCE_BALANCE.md)·[전 함종/100·200·300 결과](04_analysis/FLEET_ENDURANCE_RESULTS.md). 사용자 목표는10~15분이며 새 수치/공간 근사는 제안이다. 이전v0.2는 비교/영웅L1 출발값으로 보존한다.
- **이전 전투 수치 초안:** [전투 수치v0.2](archive/balance/COMBAT_BALANCE.md)의 HP/무장/영웅/가격 제안. [축소 모형 분석](archive/analysis/COMBAT_SIMULATION.md)의 표본/범위와 함께 읽으며 UE 실측·전체 전투 밸런스 확정과 구분한다.
- **시험 기준값:** 프로토타입에서 채택한 밸런스 출발값. 원형·단위를 명시하며 전체 티어의 고정 규칙으로 확대하지 않는다.
- **임시 구현:** 로컬 코드를 작동시키기 위한 선택. 사용자 확정 기획과 구분하며 교체 가능한 설정으로 둔다.
- **과거/참조:** [프로토타입 개선 기록](05_references/PROTOTYPE_IMPROVEMENT_PLAN.md), [시행착오](03_development/DEVELOPMENT_PITFALLS.md), [PlayGame3 이식안](05_references/PLAY_GAME_3_CONTROLS.md), [후속FBX/함급/전장 보고](05_references/PROTOTYPE_FBX_UPDATE_RECORD.md), archive 및 검토 보고서. 이 문서가 현행 규칙을 덮어쓰지 않는다.
- **검증 기록:** 특정 커밋의 빌드·자동/API·실제 입력 결과. 테스트 통과가 미구현 기능의 완료나 기획 확정을 의미하지 않는다.

동일한 최신 근거끼리 다르면 [미결정 목록](00_overview/OPEN_QUESTIONS.md)에 남긴다. 코드에서 먼저 사용했다는 이유로 설계를 확정하지 않는다. 사용자 후속 확정은 해당 규칙을 대체하며 분야별 본문도 함께 갱신한다.

## 용어와 공통 경계

- `쉴드`, `장갑`, `전체 체력(선체 HP)`으로 통일한다. 과거의 갑판은 장갑을 뜻한다.
- `운영 승무원`은 방별 인원 게이지, `경비/강습 병력`은 전투 분대, `영웅`은 초능력자·강화인간인 개별 유닛이다. 능력 원천과 전투 유형/임무는 독립이다. `보안 시설`의 터렛·로봇은 승무원이 아니다.
- `물리 파괴`, `적 점령`, `인원 부족`은 독립 상태다. 하나의 수리로 다른 원인까지 제거하지 않는다.
- `시설 슬롯`, `장갑 구획`, `무장 장착점`은 서로 다른 ID다. 층수는 함급의 허용 범위 안에서 함체 데이터가 지정한다.
- UE는 +X 전방/+Y 우측/+Z 위, 내부 단위 cm·초다. 공간 판정의 상하·층은 대상 함선 로컬 좌표다.
- 게임 시간은 정지/1/2/3배속을 공유한다. 카메라·입력·창은 실제 시간으로 반응한다.

## 문서 변경 절차

규칙 변경 시 담당 명세 → 결정 기록 → 미결정 목록 → 요약/작업 계획의 관련 참조를 함께 정리한다. 같은 규칙을 ‘추가 확정’으로 본문 아래 다시 붙이지 않는다. 과거 원문은 Git 이력 또는 명시된 archive에 보존한다. 코드 브랜치의 진행/검증 기록은 기획 브랜치의 게임 규칙과 별도로 관리한다.

[5시간 캠페인 모형 분석](archive/analysis/CAMPAIGN_SIMULATION.md)은 경제/큐/가상 임무 작업량의 검토 자료다. 임무 구성·가정한 손실·배속 정책은 분석 입력이며 현행 캠페인 규칙이나 실제 전투 검증이 아니다.

D114 현행 설계: [영웅v0.5](01_design/boarding/HERO_SYSTEMS.md)·[수리v0.5](01_design/fleet/REPAIR_LOGISTICS.md). v0.5 설계 당시에는 시뮬레이션을 보류했고 D116에서 별도 v0.6 모형의 통합 시험을 재개했다. 과거 모형 입력은 재현용으로 유지한다.
