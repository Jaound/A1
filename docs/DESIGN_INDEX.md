# 기획 문서 지도와 관리 원칙

> 정리일: 2026-11-16(KST). 이 문서는 기획의 입구와 담당 범위를 정한다. 게임 기능 구현 완료를 뜻하지 않는다.

## 읽기 순서

1. [GDD](GDD.md)로 게임의 정체성과 플레이 순환을 파악한다.
2. [결정 기록](DECISIONS.md)에서 최신 변경과 근거를 확인한다.
3. 이번 작업의 **담당 명세**를 아래 표에서 찾아 읽는다.
4. [미결정 목록](OPEN_QUESTIONS.md)에서 관련 정책의 결정 여부를 확인한다.
5. [구현 상태](IMPLEMENTATION_STATUS.md)와 [2단계 계획](PHASE2_PLAN.md)을 읽고 기존 코드를 보존하며 이어간다.

## 문서의 권한과 상태

- **현행 명세:** 위 담당 문서의 확정 규칙. 반복 요약보다 원 규칙을 관리하는 문서를 따른다.
- **미결정:** 상충하는 최신 문구나 미정 수치. 대안·추천을 자동 확정하지 않는다. `R` 번호로 관리한다.
- **시험 기준값:** 프로토타입에서 채택한 밸런스 출발값. 원형·단위를 명시하며 전체 티어의 고정 규칙으로 확대하지 않는다.
- **임시 구현:** 로컬 코드를 작동시키기 위한 선택. 사용자 확정 기획과 구분하며 교체 가능한 설정으로 둔다.
- **과거/참조:** [프로토타입 개선 기록](PROTOTYPE_IMPROVEMENT_PLAN.md), [시행착오](DEVELOPMENT_PITFALLS.md), [PlayGame3 이식안](PLAY_GAME_3_CONTROLS.md), archive 및 검토 보고서. 이 문서가 현행 규칙을 덮어쓰지 않는다.
- **검증 기록:** 특정 커밋의 빌드·자동/API·실제 입력 결과. 테스트 통과가 미구현 기능의 완료나 기획 확정을 의미하지 않는다.

동일한 최신 근거끼리 다르면 [미결정 목록](OPEN_QUESTIONS.md)에 남긴다. 코드에서 먼저 사용했다는 이유로 설계를 확정하지 않는다. 사용자 후속 확정은 해당 규칙을 대체하며 분야별 본문도 함께 갱신한다.

## 용어와 공통 경계

- `쉴드`, `장갑`, `전체 체력(선체 HP)`으로 통일한다. 과거의 갑판은 장갑을 뜻한다.
- `운영 승무원`은 방별 인원 게이지, `경비/강습 병력`은 전투 분대, `영웅`은 개별 유닛이다. `보안 시설`의 터렛·로봇은 승무원이 아니다.
- `물리 파괴`, `적 점령`, `인원 부족`은 독립 상태다. 하나의 수리로 다른 원인까지 제거하지 않는다.
- `시설 슬롯`, `장갑 구획`, `무장 장착점`은 서로 다른 ID다. 층수는 함급의 허용 범위 안에서 함체 데이터가 지정한다.
- UE는 +X 전방/+Y 우측/+Z 위, 내부 단위 cm·초다. 공간 판정의 상하·층은 대상 함선 로컬 좌표다.
- 게임 시간은 정지/1/2/3배속을 공유한다. 카메라·입력·창은 실제 시간으로 반응한다.

## 문서 변경 절차

규칙 변경 시 담당 명세 → 결정 기록 → 미결정 목록 → 요약/작업 계획의 관련 참조를 함께 정리한다. 같은 규칙을 ‘추가 확정’으로 본문 아래 다시 붙이지 않는다. 과거 원문은 Git 이력 또는 명시된 archive에 보존한다. 코드 브랜치의 진행/검증 기록은 기획 브랜치의 게임 규칙과 별도로 관리한다.
