# 기지와 함대 공유 전장 검증

시작 코드 `eb5b99f`, 기획 `40bba6e`. 기지 버튼과 함대 버튼은 같은 전장의 입력과 HUD를 전환한다. 초기에는 코어 전방에 초계함 한 척이 있다. 두 화면에서 Home으로 기지와 함선을 다시 한 화면에 담을 수 있다.

## 배치와 건설

- 마우스로 가리킬 때와 예약을 확정할 때 같은 검사를 사용한다. 회전·높이를 적용한 점유 격자 및 소켓에 결합한 모델 외곽을 선체 메시의 방향성 경계 상자와 대조한다. 쉴드와 선택 표식은 검사 대상에서 제외한다. 선체 형상이 크게 파인 곳에서는 상자가 여유 공간을 보수적으로 잡을 수 있다.
- 건설 구역이 겹치면 함명과 이동 안내가 표시된다. 예약 후에 들어온 함선도 공사를 막는다. 함선을 옮기면 남은 게임 시간부터 이어간다. 해당 공사가 끝나야 연결되는 예약은 계속 기다린다.
- 충전·환불이 없는 무료 규칙은 이 시험장 인스턴스에만 적용한다. 일반 비용 정책은 별도 자동 검사에서 자원 부족, 취소 환불과 설치 한도를 검사한다.
- 공사 높이는 실제 남은 건설 시간에서 계산한다. 정지 중에는 같은 높이를 유지한다. 연결을 기다리는 예약은 기초만 표시하고 공사가 시작되면 원래 크기의 모델을 아래부터 드러낸다.

## 모델

[6종별 삼각형 및 텍스처 해상도](Models.json). 원본 FBX와 이미지 파일은 별도로 보존했다. 기존 메시 경로와 소켓을 유지하고, 근거리에는 원본 밀도의 LOD0, 원거리에는 기존 전장용 LOD1을 쓴다. 조선소와 도크에는 기존 팔각형 접합부가 포함된다. 화면 크기 전환 기준은 0.25다. 색상은 8192², 노멀·금속·거칠기는 각각 4096²이며 실제 GPU에 상주하는 밉 수준은 UE 스트리밍의 영향을 받는다.

재반입할 때 `OV_BASE_DETAIL`에 준비 출력 경로를 지정한다. Blender에서 `Tools/PrepareBaseTrial.py`를 `OV_BASE_STAGE=1`과 `2`로 각각 실행한 뒤 같은 경로를 지정한 UE 에디터에서 `-ExecutePythonScript=<프로젝트>/Tools/ImportBaseDetail.py`를 실행한다. 원거리용 FBX는 기존 준비 폴더 BaseTrial1·2에서 읽는다.

## 직접 확인 순서

1. 임무 선택에서 **기지 건설 시험장**에 출격한다. WASD, 휠 드래그, 휠 확대를 시험한다.
2. 함대 화면으로 바꾼 뒤 초계함을 코어의 연결구 바로 바깥 칸으로 이동한다. Space로 시간을 재개하고 도착하면 멈춘다.
3. 기지에서 일자 통로를 골라 초계함이 차지한 칸을 가리킨다. 붉은 윤곽과 함명을 확인한다. 같은 높이에서 함선을 옮긴 뒤 같은 칸이 초록색으로 바뀌면 예약한다.
4. 통로 끝에 창고를 예약한다. 정지, 1배속, 3배속에서 건설 단면을 본다. 공사 중에 두 화면을 왕복하고 Home으로 전체 구도를 확인한다.

## 실행 결과

구현 커밋 `57edbba`. UE 5.8.4 Win64 Development Editor와 Win64 Development 게임 타깃 빌드 성공. 전체 자동 검사 167개 성공, 실패 0개. 한국어 엔진 초기화의 기존 `Condition failed` 메시지는 프로젝트 검사 결과와 별도로 남아 있다.

ControlRange의 PIE 검사 83개 통과. 초계함 점유 중 예약 거부, 수직으로 비운 칸 예약, 함대 이동 명령으로 비운 뒤 재예약, 예약 뒤 진입한 함선에 의한 공사 대기, 일시정지와 1·2·3배속, 재시작·다른 임무 격리, 여섯 모델의 재질·두 LOD·텍스처와 실제 베이 출입로를 확인했다. [검사별 결과와 소켓 측정값](PIE.json).

DX11 PIE 1550×948에서 일시정지한 상태로 시점을 고정했다. 30프레임을 기다린 뒤 에디터 프레임 간격 120개를 측정했다. 코어 평균 10.16ms·p95 16.00ms, 조선소 평균 9.90ms·p95 16.00ms였다. 같은 PC에서 자동화와 빌드 작업이 겹쳤으며, GPU 단독 처리 시간이나 대규모 기지 성능은 측정하지 않았다. FBX 반입기는 일부 면의 탄젠트·스무딩 경고를 남겼다.

창고의 같은 카메라에서 왼쪽부터 연결 대기, 절반 완성, 완공이다. [실제 렌더 비교](Construction.jpg). 팔각형 접합부는 같은 조선소 시점에서 왼쪽이 기존 전장용 모델, 오른쪽이 복원된 근거리 모델이다. [조선소 접합부 전후](JointComparison.jpg).

재현은 `Build.bat OrbitalVanguardEditor Win64 Development <uproject>`, 에디터의 `Automation RunTests OrbitalVanguard`, ControlRange에서 `py <프로젝트>/Tools/ValidateBaseTrial.py` 순서다. 개별 PIE 실행은 게임 시뮬레이션 API를 사용한다.

## Windows 패키지와 실제 마우스 입력

Win64 Development DX11 패키징이 종료 코드 0으로 끝났다. 패키지 목록에서 기지 모델 여섯 종을 확인했다. 로컬 실행 파일은 `D:/OrbitalVanguardTests/BaseSharedField/Windows/OrbitalVanguard.exe`다. 실행 후 임무 목록에서 기지 건설 시험장을 선택하거나 실행 인자 `/Game/Maps/ControlRange -OVPlayScene=BaseTrial -dx11 -CustomConfig=HeroArtDX11`로 바로 진입한다.

1440×900 플레이 창에서 함대와 기지를 왕복했다. 초계함 01을 코어 연결구 옆으로 이동시킨 뒤 통로를 클릭하자 붉은 윤곽과 함명 경고가 뜨고 공사 0건이 유지됐다. 함대 화면에서 초계함을 다시 선택해 우클릭으로 이동한 뒤 같은 위치를 클릭했다. 연결 수가 0/24에서 1/24로 바뀌고 ‘연결 통로 · 공사 중 · 14.8초’가 표시됐다. 공간을 비워야 건설이 시작되는 흐름을 실제 입력으로 확인했다. 휠 버튼을 누른 채 회전하는 물리 입력은 이 도구에서 재현할 수 없어 직접 검증 대상으로 남긴다.
