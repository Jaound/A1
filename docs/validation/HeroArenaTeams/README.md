## 실제 시나리오에서 확인한 결과

DX11 에디터 플레이에서 동일한 시험장을 재시작하고 Lv.20 일반형 아군 영웅 4명과 일반병 8명으로 각 팀을 구성했다. 시험장 적은 Lv.1 일반형 영웅 10명과 일반 수비병 12명이다. A팀 출발 30.5게임초 후 B팀에 출발을 명령했다. 각 개인의 실제 진입 사건을 확인한 다음 두 팀에 철수를 명령했다. 진입을 마쳤을 때 싸우다 전사한 인원도 손실에 남는다.

## 검증과 재현

- Win64 Development Editor 및 게임 빌드, DX11 Windows 패키징. 엔진 경로 `E:\UE_5.8`. 프로젝트 루트에서 `Build.bat OrbitalVanguardEditor Win64 Development -Project=<절대경로>/OrbitalVanguard.uproject -WaitMutex`. 게임은 대상을 `OrbitalVanguard`로 지정한다.
- 자동 검사는 `Automation RunTests OrbitalVanguard`. 목표당 두 팀·다른 목표의 세 번째 팀, 출발 간격, 5영웅/13인 거부, 상주 한도와 일반병 독립 등록을 포함한다. 기존 세 재출발 시험은 30초 간격이 지난 뒤 원 포드·강습선 재사용과 보호의 기존 판정을 그대로 검사한다.
- PIE에서 `Tools/ValidateBoardingWaves.py`가 3경로, 패널 클릭 영역과 인원 보존을 검사한다. `ValidateHeroArena.py`는 고유 30명·일반형 4명의 실제 편성과 진입, 이리스 그림, 함교 승리와 배속을 검사한다. `ValidateHeroBoarding.py`는 보직과 포드 발사를 함께 시험하도록 항모를 사용한다. `ValidateHeroCards.py`, `ValidateHeroRoster.py`, `ValidateScenarioCommandAI.py`가 명단·저장·적 AI를 검사한다. 300코스트에서 두 시작 거리와 세 난이도의 여섯 사례 모두 적 영웅 15명이 일반형 G01~G04였고, 지휘 AI의 실제 강습 진입과 점령 명령도 검사했다. [난이도별 AI 결과](CommandAI.json). 기계별 절대경로와 무관한 집계는 [검증 결과](Results.json)에 남겼다.
- 실제 패키지의 마우스 입력으로 빈자리 채우기 → 혼합 선택 → A팀 포드 출발 → 3배속 → 30게임초 경과 → B팀 강습선 출발 → 재시작을 확인했다. 첫 실행에서 출발 버튼이 전장 클릭으로 새는 문제를 재현하고 수정 후 같은 클릭으로 확인했다. 이 직접 검사는 `395af72` 패키지에서 했다. 뒤이은 `9ebb947`은 이동 중 인원과 두 팀 출발 후 상태 문구를 추가했다. 세 방식의 완주와 사망·귀환 결산은 PIE API 검사다.
- 실행 로그는 프로젝트 `Saved/Logs/BoardingWavesBuild.log`, `BoardingWavesGameBuild.log`, `BoardingWavesPackage.log`, `BoardingWaveAutomation.log`, `ValidateBoardingWavesWavesRun.log`에 있다. Windows 방화벽 허용 설정은 변경하지 않았다.

## 기획 대조와 다음 플레이 개선

함선 상주·보직 한도와 강습선 예외는 [영웅 시스템](https://github.com/Jaound/A1/blob/6fb4ae948ff5a828047b94963d9cf66a05b588f8/docs/01_design/boarding/HERO_SYSTEMS.md)을 따른다. 고유 정의·이미지 명세, 결정 기록, 함재기·소형함 격납고 및 [강습·점령·공작·포로](https://github.com/Jaound/A1/blob/6fb4ae948ff5a828047b94963d9cf66a05b588f8/docs/01_design/boarding/BOARDING_COMBAT.md)를 대조했다. 최신 사용자 지시에 따라 시험에도 팀당 12명·영웅 최대 4명, 목표당 두 팀·출발 간격 30게임초를 적용했다. 10명은 두 시험 구축전함의 상주 특례다.

1. 지금은 편성 순서가 각 팀의 영웅을 결정한다. 출발 전 두 팀과 예비 명단을 나란히 보여 주고 영웅과 일반병 분대를 직접 옮길 수 있게 하는 것이 우선이다.
2. 접안과 포드 진입은 생존 결과가 달랐다. 발견한 구역만 사용해 팀별 진입층과 원 진입점을 표시하고, 결산에서 진입 전·선내·철수 중 손실을 나누면 원인을 비교하기 쉽다.
3. 여러 병사가 같은 순간에 진입해 알림 여러 줄을 차지했다. 같은 팀 진입을 한 줄로 묶고 개별 사망·구조 대기 기록은 펼쳐 확인하도록 개선할 여지가 있다. 포로는 생존한 적을 실제 확보하는 절차, 포로 교환·구조 캠페인은 별도 후속 작업이다.
