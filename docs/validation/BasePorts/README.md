# 기지 모델 13종과 독립 창 검증

작업 시작은 개발 브랜치 `codex/phase1-playground`의 `92ec23e`, 확인한 기획 브랜치는 `d07deb5`다. 실행 환경은 외장 SSD의 프로젝트, UE 5.8.4, Win64 Development Editor다.

## 실제로 맞춘 면

사용자 마킹이 없는 모델은 위임받은 기준대로 원본 외벽에서 팔각 연결부를 지지할 면을 골랐다. 25m 건설 격자와 원본 모델의 치수는 유지했다. 새 연결부는 별도의 중공 팔각 메시다. 뒤쪽의 안팎 테두리는 원본 삼각형에 각각 투사하고 앞면은 직선 통로와 같은 외곽 4.36m × 5.36m로 맞췄다. 통로 양끝 64개 표본에서 위쪽 홈이 최대 14.07cm 들어가 있어 접합면 안쪽에 16.07cm 깊이의 삽입부를 두었다. 외벽부터 접합면까지의 거리는 모델별 6.71~45.41m다.

| 원본 모델 | 원본 메시의 UE 소켓 | 검사 |
|---|---|---|
| 중형·대형·초대형 조선소 | 각각 YN, YP | 접합 24건, 초계함 왕복 12건 |
| 중형·대형·초대형 접안 모듈 | 각각 XN, XP | 접합 24건, 초계함 왕복 12건 |
| 물류 터미널 | XN, XP | 접합 8건 |
| 전략 연구소·영웅 아카데미·인원 지원소·기지 방어 모듈·기지 레이더·기지 방호 모듈 | 각각 XN | 접합 24건 |

X/Y는 모듈 로컬 축, N/P는 음/양의 바깥 방향이다. 로컬 위치 단위는 cm다. 소켓 위치·외벽 부착점은 [Sockets.json](Sockets.json), 통로 실측은 [CorridorRim.json](CorridorRim.json)에 있다. 시험장에서는 원본 몸체와 연결부가 함께 배치·회전·철거된다. 건설 중에는 진행 높이가 연결부에 도달하면 보인다.

## 시험장에서 확인한 결과

- 20개 소켓을 실제 통로에 0°, 90°, 180°, 270°로 예약한 80건 모두 접합면 중심 오차는 기록 정밀도 0.0001cm에서 0이었다. 법선 내적은 −1, 상향 벡터 내적은 +1이다. 팔각 테두리의 원본 LOD0 꼭짓점과 계산 기준점 최대 차이는 0.0031cm였다.
- 90°로 돌려 완공한 상태에서 20개 접합부를 UE로 렌더했다. 촬영에는 대상 모듈·어댑터·통로와 검사용 조명을 사용했다. 외벽 높이와 격자 중심의 차이가 큰 모델은 기울어진 연결부가 길게 보인다. 네 방향 전체의 위치·각도는 수치 검사를 사용했다. [접합부 20곳 사진](Seams.jpg)
- 원본 초계함 메시의 반폭을 측정해 앞뒤·좌우·높이 810.96 × 250.89 × 180cm의 상자로 각 베이를 왕복했으며 안쪽 바닥이 해당 모듈의 충돌면인지 확인했다. 6종 × 4방향 모두 통과했다. 출입로의 표시와 외곽 건설 차단도 베이별 통과 위치 및 초계함 폭에 맞췄다. 칸 경계에 걸치는 경우에는 양쪽 칸에 적용된다. 이 검사는 접안 공간을 검증하며 함선 조종·접안 명령은 후속 기능이다. [개별 접합 및 출입 충돌 기록](PIE.json)
- Win64 Development Editor 빌드 성공. 기지 C++ 자동 검사 2/2, 기존 기지 3단계 PIE 41/41과 공유 전장 PIE 83/83 통과. 공유 전장 검사에는 기존 소형 조선소·표준 도크의 초계함 진입과 바닥 검출이 포함된다. 기지 창 기본 상태·네 창 동시 열기·개별 최소화와 닫기도 새 PIE에서 확인했다.
- 1280×800 DX11 독립 게임 창에서 운영 창을 마우스로 152×60픽셀 옮기고 오른쪽 아래 모서리를 93×52픽셀 늘렸다. 핀을 누른 뒤 같은 제목줄을 끌어도 위치가 유지됐다. 운영을 최소화한 상태에서 건설·연구·저장 창을 동시에 열고 하나씩 닫았다. 모든 창을 닫으면 기지 양옆과 건설 격자가 비워진다. 상단에는 시간 배율과 자원 보유량/한도, 하단에는 네 버튼만 남는다.
- SSD로 복사된 종전 빌드 캐시가 D의 생성 파일을 가리켜 첫 빌드에서 D의 일부 중간 파일·바이너리가 갱신됐다. 이 결과를 제외하고 SSD에서 빌드 캐시를 분리·재생성해 소스·링크 출력 경로를 확인했다. 이번 변경의 패키징과 실제 초계함 수동 접안은 미검증이다.

## 재현

1. 직접 확인하려면 임무 목록에서 **기지 건설 시험장**을 시작한다. 아래 **건설**로 원하는 모듈을 고르고 **Q/E**로 회전한다. 중형 이상은 **연구**의 시험 선행 기술과 **운영**의 코어 등급이 필요하다. **Space**로 공사를 진행한다. [시험장 조작 안내](../../BASE_TRIAL3_GUIDE.md)
2. 에디터에서 기지 규칙은 `Automation RunTests OrbitalVanguard.Base`, 기지 3단계 회귀는 ControlRange에서 `py .../Tools/ValidateBaseStage3.py`로 실행한다.
3. 연결부 재제작 시 `OV_BASE_ASSET_ROOT`를 원본 프로젝트 자산 폴더, `OV_BASE_STAGE3_PREPARED`를 준비된 13종 FBX 폴더로 지정한다. 필요하면 먼저 `PrepareBaseStage3.py`로 외형을 준비한다. Blender 백그라운드에서 `MeasureCorridorRim.py`, `MeasureBasePorts.py` 순서로 측정한 뒤 UE 에디터에서 `ImportFittedBasePorts.py`로 반입한다. 일반 게임 실행에는 이 환경 변수나 외부 FBX가 필요 없다.
4. `OV_BASE_STAGE3_PREPARED`를 같은 폴더로 지정하고 ControlRange 에디터에서 `py .../Tools/ValidateFittedBasePorts.py`를 실행한다. `OV_PORT_PHOTOS=1`과 DX11 렌더러를 사용하면 포트별 90° 사진도 남긴다. 결과 경로는 해당 실행의 `Saved/Validation/BasePorts`다.
