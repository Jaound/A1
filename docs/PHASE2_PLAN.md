# 2단계 제작 계획 — 외부 함대전

> 2026-11-11. 최신 기획 수정본을 반영한 구현 순서 제안이다. GDD·결정 기록의 확정 규칙을 우선한다. 코드와 Windows 실행 환경은 이 클라우드 작업 공간에 없으며, 아래 1단계 결과는 사용자가 제공한 로컬 검증 문서 기준이다.

## 시작 상태와 기획 동기화

- 로컬 `codex/phase1-playground`에 미커밋 구현이 있다. 제공된 안내에 따르면 최초 기획 기준은 `77e21f6`이다. 7개 최신 수정 문서는 `ce073e4`에 반영됐다.
- 보고된 검증: Win64 Development Editor 빌드 성공, 프로젝트 자동 테스트 3/3 성공, 실제 PIE의 API 검사 20/20 성공. 직접 마우스·키보드 입력 경로는 화면 제어 시간 초과로 미검증이다.
- 기본 한국어 실행의 엔진 시작 자체 검사 15건 실패와 영어 비교 실행 성공은 프로젝트 테스트 결과와 구분해서 유지한다. 무조건 영어로 실행하거나 엔진·전역 설정을 바꿔 검증을 통과시킨 것으로 처리하지 않는다.
- 먼저 로컬의 소스·Config·필수 Content·안내·검증 기록을 확인하고 현재 작업을 체크포인트 커밋으로 보존한다. Binaries·Intermediate·Saved 등 생성물은 제외한다. 파괴적인 브랜치 초기화나 무조건 덮어쓰는 갱신을 하지 않는다.
- 최신 `work`의 기획 문서를 가져와 차이를 확인한다. shallow import 등으로 이력이 제한된 경우 억지로 이력을 재작성하지 말고 문서만 안전하게 동기화할 수 있다. 로컬 구현·PLAYGROUND 문서·검증 자료는 보존한다.
- 첫 호환 작업: 기존 휠 Z 입력에 추가 또는 대체하여 최신 기획의 **Shift/우클릭 유지 + 상하 드래그 고도 지정**을 지원한다. 미리보기, 취소, HUD 위 입력, 일시정지 중 명령도 확인한다. 입력 중 방식 전환으로 목적지가 튀지 않게 한다.

## 이번 로컬 작업 목표: 2A

### 데이터와 상태

- 기존 3D 조작 시험장 위에 추가한다. 카메라·선택·모드·시간 제어를 회귀 검증한다.
- `UShipLayoutDataAsset` 등 기획상 슬롯 그래프를 마련한다. 층 ID, 슬롯 ID, 고정 복도·문·수직 통로 연결 ID, 함선 로컬 좌표의 피격 박스와 시설 배치 제약을 둔다.
- 레이아웃 정의와 함선별 런타임 상태를 분리한다. 같은 데이터 자산을 쓰는 두 함선이 내구도·점령·인원 상태를 공유하지 않게 한다.
- 개별 시설 인스턴스를 슬롯 ID로 식별한다. 시설 종류당 변수 하나로 구현하면 중복 설치를 지원하지 못한다.
- 코어·함교 단일 설치, 코어 중앙·함교 외곽층 제약과 무장 연동 필수 시설을 데이터 검증에 포함한다. 레이아웃별 위치를 명시하고 2층 함선의 중앙층을 코드에서 임의로 계산하지 않는다.
- 격납고·함재기 운용·자원 적재실·보안 시설도 시설 종류로 확장 가능하게 한다. 격납고 도킹·생산·함재기 AI·자원 경제의 실제 플레이는 이번 완료 조건이 아니다.
- 물리적 파괴, 점령, 운영 승무원 게이지를 분리한다. 운영 불가 시설은 효율 합산에서 제외한다. 코어·무인 보안 시설은 인원 요구 예외다.
- 중복 효과는 최신 기획의 `가동률 최고 주 시설 × 100% + 나머지 시설별 가동률 × 50%`를 사용한다. 매번 기본 성능에서 재계산해 반복 수리·파괴가 버프를 누적시키지 않게 한다. 레이더 중복이 탐지 거리를 늘리지 않도록 성능별 효과를 구분한다.

### 피해 처리

- 전방향 쉴드 → 마지막 타격 초과 피해 일부 전달 → 부위별 장갑 경감 → 시설 피해 → 전체 HP를 한 경로에서 처리한다. 피해량을 단계마다 전체 HP에 중복 차감하지 않는다.
- 회복 딜레이 후 쉴드가 회복되고 50%에서 자동 재작동한다. 사용 가능한 제어실이 없으면 즉시 비활성·회복 중단한다. 제어실 일부 상실 시 최대량·회복량을 재계산하고 현재 게이지를 유효 범위로 제한한다. 파괴·수리가 공짜 완충을 만들지 않도록 한다.
- 1층·2층·3층의 상·하·측면 매핑을 기획대로 구현한다. 판정에는 함선 **로컬 좌표**를 사용해 선회·롤 후에도 올바른 시설에 맞게 한다.
- 외장 장갑 0 및 빈/파괴 슬롯을 통한 3층→2층 관통, 중층도 비었을 때 HP 직접 피해를 구현한다. 빈 슬롯은 유폭을 일으키지 않는다.
- 피해 원인(외부 포격·유폭·정밀 사보타주)을 구분한다. 외부·유폭 파괴는 해당 장갑도 파괴하고, 정밀 사보타주는 장갑을 보존한다. 실제 영웅 없이 시험 입력으로 검증할 수 있다.
- 적재실·축전기 파괴는 연쇄 피해 이벤트로 처리한다. 동일 파괴 사건에서 같은 시설이 재폭발하거나 코어 파괴·완파 보상이 여러 번 처리되지 않도록 한다.
- 전체 HP 0 또는 코어 파괴 시 완파하고 이후 행동을 정지한다. 내부 인원 전멸에 따른 중립 정지와 기능별 사용 가능 여부도 상태로 표현한다.
- 쉴드 초과 전달 비율, 회복 딜레이, 장갑 경감 곡선, 시설 피해의 HP 반영 비율, 유폭 계수 등은 조정 가능한 초기 설정으로 둔다. 아직 미정인 값은 문서에 임시값으로 명시한다.

### 화면과 시험 도구

- 1층·2층·3층 시험 레이아웃과 필요한 피격 표적을 준비한다. 고급 함선 해금과 무관하게 시험용 다층 표적을 배치할 수 있다.
- 선택 함선의 HP·쉴드·시설 효율과 선택 슬롯의 층·장갑·시설 내구도·인원·마비/파괴 상태를 보여준다. 테스트용 층 전환 패널을 만들면 이후 선내 UI에 재사용할 수 있다.
- 시험 피격·시설 파괴/수리·인원 감소/보충·상태 초기화 수단을 제공한다. 이는 정식 공격·기지 수리 기능과 구분한다.
- 실제 3D 탄착점과 피해를 받은 층·슬롯을 표시한다. 내부 이름·내구도를 공개하는 기능은 개발용 시험 모드로 제한하며, 실제 전투의 ‘강습 전 내부 구조 비공개’ 규칙을 제거하지 않는다.
- 시간 처리는 기존 공통 시뮬레이션 시간에 연결한다. 이동은 정지했는데 쉴드만 회복하거나, 3배속을 두 번 곱해 9배속으로 처리하지 않도록 한다.

## 2A 검증 기준

1. 기존 이동·선회·시간 자동 테스트가 계속 통과한다.
2. 정상·비활성·재충전·제어실 전부 상실·50% 자동 재작동을 확인한다. 정지 중 시뮬레이션이 진행되지 않는다.
3. 1/2/3층 피격, 함선 회전 후 로컬 피격, 빈 슬롯, 수직 관통을 확인한다.
4. 같은 레이아웃의 두 함선이 서로 독립적인 상태를 가진다.
5. 중복 시설 1/2/3개 효율 100/150/200%, 인원 부족 합산, 전부 운영 불가 시 기능 중단을 확인한다.
6. 외부/유폭 파괴와 사보타주 파괴의 장갑 결과 차이, 유폭 중복 방지, HP 피해 중복 방지, 코어 즉시 완파를 확인한다.
7. 빌드·자동 테스트·PIE API 검사·직접 입력 검사를 각각 보고한다. API로 명령을 호출한 성공을 실제 마우스 입력 검증으로 기록하지 않는다.
8. 최신 XYZ 입력의 클릭·드래그·HUD·포커스와 일시정지/배속은 직접 입력으로 확인한다. 도구가 다시 실패하면 재시도를 무한 반복하지 않고 사용자용 짧은 확인 절차를 제공한다.

## 작업 결과

`PHASE2A_GUIDE.md`와 `PHASE2A_VALIDATION.md` 또는 동등한 문서에 실행·시험 방법, 임시값, 검증 증거와 남은 제약을 기록한다. 2A를 실행 가능한 체크포인트로 마친 뒤 2B에 착수한다. 로컬 소스가 이 클라우드에 공유되기 전에는 여기서 코드 검토·빌드 성공을 주장하지 않는다.
