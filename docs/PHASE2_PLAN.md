# 2단계 제작 계획 — 최신 기획 통합판

> 2026-11-11. 기존 2A/2B/2C 순서를 유지하되 UI 전용 명세·6면 장갑·개별 포탑·관성 기동·프로토타입 회귀 사례를 반영했다. 사용자 확정과 미결정 대안은 [통합 검토](PLANNING_REVIEW.md), UE5 기술 기준은 [공통 구현 기준](UE5_IMPLEMENTATION_CONTRACT.md)을 따른다.

## 0. 현재 작업 보존과 기획 동기화

- 확인된 로컬 보고는 `codex/phase1-playground`의 3D 조작 시험장이다. Editor 빌드, 자동 테스트 3/3, PIE API 검사 20/20 성공이 보고됐고 직접 물리 입력은 화면 제어 시간 초과로 미검증이다. 한국어 환경의 엔진 시작 자체 검사 15건 오류는 별도 기록이다.
- 초기 계획 작성 시에는 이 클라우드에 엔진·로컬 게임 소스가 없었다. 2026-11-12에는 `codex/phase1-playground`의 UE 소스와 검증 기록을 받아 정적 검토했다. 이 환경에 UE 엔진은 없어 Windows 실행을 재검증하지 않았다. 다른 프로토타입 문서의 플레이 테스트가 본작 구현 완료를 증명하지 않는다. 사용 엔진·실행 버전·검사 방법이 다른 결과를 합산하지 않는다.
- 최초 로컬 구현 기준은 `77e21f6`, 이후 기획 갱신은 `ce073e4`, 이번 사용자 첨부 10개 원본 반영은 `d82d796`이다. 최신 `work`의 통합 정리까지 함께 확인한다.
- 로컬 미커밋 소스·Config·필수 Content·검증 기록을 먼저 체크포인트로 보존하고 최신 문서와 비교한다. Binaries·Intermediate·Saved 등 생성물은 제외한다. 브랜치 초기화·기존 프로젝트 덮어쓰기·계획을 이유로 한 무조건 재구현을 하지 않는다.
- 이미 2A 이후가 로컬에서 구현됐다면 아래 항목과 차이를 확인해 누락만 보완하고 기존 동작을 회귀 검사한다.
- **2026-11-12 후속 보고:** 로컬에서 2A-0~2A-2 구현·빌드·자동 15/15·PIE API 45/45 성공이 보고됐다. 직접 입력은 미검증이다. UE 소스와 검증 기록은 원격 `codex/phase1-playground`의 `6d67970`으로 공유됐고 정적 비교를 완료했다. 현재 다음 작업은 [2A 보고 검토](PHASE2A_REVIEW.md)의 증거 정합성 확인과 [프로토타입 조작 이식](PLAY_GAME_3_CONTROLS.md)이다. 기존 2A를 재구현하지 않는다.

## 1. 이번 단계에서 잡아야 할 의존 관계

`입력·선택·시간 → 이동·자세 → 함체/층/슬롯/장갑/무장 상태 → 피해 → 최소 관측 UI → 실제 무장·레이더 → 요격·함재기/포드 전이 → 강습·나포 → 경제`

UI는 사후에 데이터를 복제해 붙이지 않는다. 처음부터 읽기 전용 상태를 받아 같은 ID를 표시하도록 하되, 모든 UI 기능을 전투 로직의 선행 조건으로 만들지도 않는다.

## 3. 2A 구체 범위

### 입력·이동

- 현재 화면의 휠 고도 입력과 최신 Shift/우클릭 드래그의 차이를 해소한다. 전술 디스크와 실제 투영면을 UE5 Z축으로 일치시키고 얕은 레이·카메라 근접 목적지·HUD 위 드래그를 검사한다.
- 새 부대키·배속키·수리 R과 기존 F1/F2 선택·R 이동이 충돌하지 않게 액션을 분리한다. 무장 그룹 기본키와 핀/미선택 관계는 R13 결정을 남긴다.
- 속도·선회·감속을 명시 단위의 절대값으로 설정한다. 기존 시험장 수치는 임시 cm/s이므로 다른 프로토타입 m/s와 무조건 0.5배 합성하지 않는다.
- 이동·정지·FTL·수동 자세·자동 편대 정렬과 포탑 조준을 분리한다. 소프트 회피와 하드 분리를 같은 PairId로 처리해 양쪽 Tick이 동일 충각을 두 번 계산하지 않게 한다. 충각 완성은 실제 피해 경로가 준비된 뒤 연결한다.

### 데이터·피해

- `UShipLayoutDataAsset` 등으로 층·슬롯·문·복도·수직 통로·시설 제약을 정의한다. 레이아웃과 개체별 상태를 분리하고 같은 자산을 쓰는 함선 둘의 HP·점령·인원을 공유하지 않는다.
- 장갑 면·구획, 내부 층·슬롯과 개별 WeaponMount를 별도 ID로 둔다. 전면 1구획을 시설 하나와 동일시하지 않는다. 단위·좌표는 [공통 기준](UE5_IMPLEMENTATION_CONTRACT.md)을 따른다.
- 필수 4대 시설·무장 연동 시설·코어 중앙/함교 외곽·중복 배치 제약을 검증한다. 기지 UI가 아직 없어도 데이터 검증으로 잘못된 설계를 막는다.
- 중복 시설은 가동률 최고 주 시설 100%와 나머지 각 50% 합산이다. 기본 성능에서 재계산하며 승무원 0·적 점령·물리 파괴를 구분한다. 레이더 중복이 탐지 거리를 늘리지 않도록 한다.
- 쉴드 초과 피해·딜레이·재가동, 장갑 경감·시설 피해·HP, 빈 슬롯·층간 관통·유폭·사보타주·전후면 예외를 단일 피격 사건으로 처리한다. 개별 무장 HP는 데이터와 직접 시험 피해로 검증하되 정식 포탑 피격의 선체 전달은 R14 결정과 연결한다.
- 쉴드 비전투/수동 완충(R11), 무장 피해 전달(R14)의 미정 수치는 프로필·시험 모드로 격리하고 정식 확정처럼 문서화하지 않는다. PD 확률(R09)은 이 단계에서 임의 수정하지 않는다.
- 완파는 즉시 게임플레이에서 제거하고 표류 연출만 남긴다. 수리·재배치·나포로 부활하지 않게 한다. 중립 정지는 완파와 구분한다.

### 표시·검증

- 1·2·3층 시험 레이아웃으로 6면 구획, 실제 탄착점, 피격 층/슬롯과 시설 상태를 확인한다. 초기 단계의 시험 표적은 실제 해금·성장 순서와 별개다.
- 시험용 피해·시설 파괴/수리·인원 감소/보충·초기화 기능을 마련하고, 이것을 실제 보급수리·기지 편집으로 보고하지 않는다.
- 선택 목록·대표 함선·선택 무장·층·창 상태를 게임 규칙 상태와 분리한다. 프리뷰는 무장·AI·충돌이 없는 표시용 개체이며 게임 시뮬레이션은 한 번만 실행한다.
- 적함 내부 디버그 공개는 실제 강습 공개 조건과 분리한다. UI 숨김·최소화 시 캡처 작업을 멈추고 모델 클릭·드래그가 전장 명령을 만들지 않게 한다.
- 기존 이동·선회·시간 테스트와 [공통 회귀표](UE5_IMPLEMENTATION_CONTRACT.md)의 해당 단계 항목을 수행한다. 빌드·로직 테스트·PIE API·직접 입력 검증을 각각 기록한다.

## 4. 다음 단계에 넘길 결정과 산출물

- R09 요격 확률은 2C 전, R11 쉴드 완충 전이는 정식 회복 확정 전, R13 키/핀 정책은 UI 입력 고정 전, R14 포탑 피해 전달은 무장 피격 연결 전에 결정한다. 다른 기반 구현은 계속 진행 가능하다.
- `PHASE2A_GUIDE.md` / `PHASE2A_VALIDATION.md`에 실행법·임시 프로필·실제 검사 방법·증거·남은 미정 사항을 기록한다.
- 개별 프리뷰 두 개를 켜기 전후 동일 장면의 발사 수·피해량이 변하지 않는지 확인한다. 함선·포탑·함재기·포드 수와 배속·하드웨어를 기록하고 성능을 측정한다. 아직 측정하지 않은 수치를 보장하지 않는다.
- 로컬 소스를 보존하고 체크포인트를 만든 뒤 검토 가능한 커밋으로 공유한다. 여기서 실제 코드를 읽거나 Windows 실행을 하지 않은 기능을 완료로 판정하지 않는다.
