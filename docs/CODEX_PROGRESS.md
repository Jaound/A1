# 최신 진행: 원본 함재기 표시와 포탑 접합 작업

**LQ 도면 기본 설정·원본 UE 격리 반입 (진행 중):** 14종 302개 근사 충돌 상자와 도면 슬롯은 기본 활성, F6 요격 슬롯도 실제 시스템에 등록된다. 무장 무력화는 가려진 무장을 피하고 실제 접근 가능한 무장을 선택한다. 자동 임무 지휘는 강습 후 공격 무장 무력화를 한 번 지시하고 함재기 선체 공격을 보류하며 사용자의 후속 목표·수동 발사·강제 무장·기발사체를 보호한다. `AssaultDisarm_LM_Build.log` 성공, 자동 `AssaultDisarm_LM_Automation.log` 123/123, [최신 기본 2C PIE API 78/78](validation/PlayUIR2/LQ_2C_API.json). F6 정리 검사는 새 F6 PD를 이전 장면 잔여물과 구분하도록 원래 ID를 유지하며 강화했다. 초기 [LO](validation/PlayUIR2/LO_2C_API.json)는 과거 기대값, [LP](validation/PlayUIR2/LP_2C_API.json)는 검사 스크립트 변수 오류로 실패했고 LQ에서 수정·재실행했다. LH 코드의 통합 임무 대표 2사례·24검사는 성공했으나 최신 전체 29사례는 제한 없이 재실행 중이다. 원본 무장 9종의 전체 메시·원본 텍스처를 `/Game/Presentation/WeaponsFull/<id>`에 덮어쓰기 없이 격리 반입하고 새 에디터에서 9/9 재로드했다([상세·해시](validation/PlayUIR2/LP_원본무장9종_UE격리반입.json)). 54개 Git LFS 에셋 약 882.42MiB다. **정적 단일 원본 반입일 뿐 실제 포탑 회전부 분리·포구·장착·전장 적용은 미완료**다. 다음: 최신 29사례 완료 결과를 저장하고, 9종의 가동 축·메시 접합·포구와 원본 재질을 검증해 게임 무장에 연결한다. 원본 3D 전장 적용, 직접 입력/화면·패키징·대량 성능은 미검증이며 사용자 UI 미커밋 3파일은 보존한다.

**LM 도면·충돌 기본 적용 및 임무 대표 회귀 (원본 무장 미완료):** 도면 슬롯/선체별 근사 충돌을 기본 활성화하고 F6 요격 슬롯도 실제 PD에 등록했다. 측면 PD의 실제 `LocalSurfaceNormal`이 렌더 구성에서 누락되던 문제를 수정했다. 무장 무력화 명령은 새 충돌 상자에 가려진 첫 무장에 쏴 선체를 맞히지 않도록 실제 충돌 경로상 도달 가능한 관측 무장을 선택하고, 모두 가려졌으면 발사 대기와 한국어 이유를 표시한다. 기존 PC14 차폐 검사는 살아 있는 다른 무장을 선택하는 새 동작을 구분해, 유일한 무장이 가려질 때 발사와 선체 피해가 일어나지 않는지 유지 검증했다. 자동 강습 임무는 출발 시 공격 무장 무력화를 한 번 지시하고, 함재기의 목표 선체 공격을 보류한다. 사용자의 수동 사격·이후 목표 변경·강제 무장·발사된 공격을 보존하는 자동 검사가 있다. `AssaultDisarm_LM_Build.log` 성공, `AssaultDisarm_LM_Automation.log` 123/123. 이전 LH 코드의 [통합 임무 대표 2사례·24검사](validation/PlayUIR2/LH_Mission_API.json) 통과: 10명 진입·함교 점령·8명 실제 회수. 이후 추가된 표시 방향/상태 문구 변경이 적용된 최종 코드의 PIE는 재실행 필요. 최초 보류만 쓴 LB 전체 시도는 25/29사례에서 360초 제한으로 중단됐고 그 25사례에 나포 후 회수 성공은 없었다([미완료 결과](validation/PlayUIR2/LB_FullMission_API.json)). LD 무장 무력화 대안도 차폐 확인 수정 이전에는 실패했다([기록](validation/PlayUIR2/LD_Mission_API.json)). 이전 LJ 2C 실패는 F6에 실제 PD를 등록하게 된 의도된 변화와 검사 기대값 차이이며, 동일 F6 복구 ID를 유지하고 실제 등록 수를 추가 검사하도록 갱신했다. 변경된 검사로 최신 PIE 검증이 필요하다. 원본 9종 전체 메시·4종 텍스처를 별도 복사하고 Blender 재반입·원본 해시 검사는 [9/9 성공](validation/PlayUIR2/LF_원본무장9종_재반입검사.json)이다. 현재 `/Game/Presentation/WeaponsFull/`에 개별 격리 반입을 진행 중이며 원본 정적 에셋만으로 가동/전장 적용 완료가 아니다. **남음:** 반입 결과 보존, 9종의 회전부 분리·피벗·원본 포구·재질·성능 검증과 실제 무장 프로필 연결, 최신 코드의 2C/통합 전체 시드 및 직접 입력·화면 확인. 근사 충돌의 희소 표면/다른 각도·성능, 방공함 시험 구성의 일반 무장 2→1 변화, 수송선 미표시·강습선 제외는 별도 한계다. 사용자 미커밋 UI 3파일은 보존한다.

**LB 원본 무장 9종 준비:** `PrepareWeaponFullSources.py`로 BF120·LB30·CIWS-6·SHC400·RG200·플라즈마 중포·MM24·MM48·CIWS-B의 전체 메시와 각 4개 내장 텍스처를 사용자 문서의 `OrbitalVanguardAssets/Prepared/PlayUI_R2_WeaponFullSources_v1`에 별도 추출했다. 원본 FBX 해시는 9종 모두 변하지 않았고 총 준비본은 약 0.76GiB다([보고](validation/PlayUIR2/LB_원본무장9종_준비.json)). **이는 분리·가동·UE 반입·전장 적용이 아니며** 메시 대부분이 단일 연결 성분이다. 다음은 실제 피벗·베이스/회전부/포신 경계 및 각도 간섭을 보정하고 색·재질·성능·실제 포구와 무장별 연결을 검증한다. 변경된 게임 로직이나 새 빌드 검증은 없다. 도면/충돌과 자동 보류 기본값은 0으로 유지한다. 통합 임무 전체 시드 검사는 별도 실행 중이며 끝나지 않은 결과를 성공으로 기록하지 않는다.

**LA 통합 임무 회귀 후속 (미해결):** KX 코어 파괴를 막기 위해 시험 임무의 자동 지휘에서 강습 출발 후 목표에 대한 신규 자동 공격을 보류하고 함재기·함선이 다른 적을 찾는 대안을 시험했다. 수동 발사 요청·사용자 강제 무장·이미 발사된 공격과 자동화 설정을 보존하며 자동 보류 범위·실제 수동 발사 테스트가 통과했다. [KY](validation/PlayUIR2/KY_Mission_API.json)와 [KZ](validation/PlayUIR2/KZ_Mission_API.json) 대표 2사례는 쉴드 제거→10명 진입→함교 점령까지 이르렀지만 아군 항모와 수송선이 적 공격으로 완파돼 8명이 회수 대기했고 600초 내 실제 회수·승리 검사가 실패했다. KZ 로그의 적 항모 공격은 아군 항모의 `D2_X2_Y1` 코어를 파괴했다. 테스트 완화를 하지 않았으며 자동 지휘 대안 `ov.Mission.ExperimentalAssaultHold`와 도면/충돌 `ov.Calibration.MarkedMounts`는 기본값 0이다. 도면 시험 모드를 켠 F6에서도 실제 요격 제어 시설과 노란 슬롯을 생성하고 PD 시스템에 등록하도록 경로를 추가했다. `FOVMarkedEquippedMountsTest`가 시험 모드를 켜 F6의 실제 등록·무장 HP를 확인한다. `AssaultHold_LA_Build.log` 빌드 성공, `AssaultHold_LA_Automation.log` 자동 122/122(자동 보류 중 명시 수동 사격 포함), 최신 기본값 PIE [D116 79/79](validation/PlayUIR2/LA_D116_API.json), [2C 77/77](validation/PlayUIR2/LA_2C_API.json). 사용자 UI 미커밋 3파일이 빌드에 포함됐으나 커밋에서 제외한다. **남음:** 적 함대의 코어 파괴·강습선 손실 경로를 측정하고 정상 수동/자동 지휘와 실제 회수까지 기존 통합 검사를 통과해야 한다. 전용 자동 보류는 아직 검증되지 않았으므로 기본 적용하지 않는다. 양측 자동 설정·기발사체·강제 사격과 선내 보호를 유지한 해결책을 검증한 후 도면/충돌을 기본 활성화한다. 원본 무장 9종의 분리·피벗·재질·포구·적용과 사용자 화면 검증은 아직 미완료다.

**KX 임무 회귀 원인 추적:** `MarkedHit_KU_Mission.log`의 실패 직전 공격 `1258`은 아군 항모 `OVShip_0`의 `Weapon_1`이 적 항모 `OVShip_6`에 명중했고, `OVDamage event=658`은 하부 장갑 `Armor_F5_R1_C1`, 2층 중앙 `D2_X2_Y1`, 선체 피해 39, `wreck=1`로 기록됐다. `MakeTestLayout`에서 3층 함체의 코어는 `D2_X2_Y1`이고 `ApplyWorldHit`은 파괴된 상하 장갑/시설 뒤로 2층을 관통시킨다. 따라서 새 상자 접촉면으로 하부 관통·코어 파괴가 발생한 것이 목표 완파의 직접 경로라는 근거가 있다. 다만 상자 근사나 자동 교전 명령 중 어느 쪽을 조정해야 하는지는 다른 각도·기존 규칙·사용자 조작으로 추가 검증해야 하며, 피해를 일괄 낮추거나 회귀 검사를 약화하지 않는다. 도면 장착과 후보 상자는 기본 비활성으로 유지한다.

**KW 선체 충돌·피격 검증 (부분 완료, 기본 적용 보류):** KQ의 14종 302개 상자를 `GenerateHullCollisionData.py`로 런타임 데이터에 생성하고 도면 장착 시험 스위치와 연결했다. UE 실제 `RequestFire`와 발사체 시뮬레이션에서 표시점 129개 각각에 빔·포탄을 수직/사선 두 방향으로 발사한 516/516개 포탑 피격 사례가 통과했다(`MarkedHit_KT_Automation.log`). 14종 × 상하좌우 × 빔/포탄 112사례는 장갑·시설 슬롯·선체 피해 연결까지 통과했다(`MarkedHit_KW_HullDamage.log`). 이는 고정 2방향/4방향 시험이며 모든 각도·표면·성능을 보장하지 않는다. 선체별 후보와 표시점은 기존 데이터로 남고 시험 스위치 `ov.Calibration.MarkedMounts 1`로 적용한다. 기본값을 1로 둔 KU 코드의 전체 자동 121/121, [D116 PIE 79/79](validation/PlayUIR2/KU_D116_API.json), [2C PIE 77/77](validation/PlayUIR2/KU_2C_API.json)이 통과했다. 그러나 [통합 임무 대표 2사례](validation/PlayUIR2/KU_Mission_API.json)는 19검사 중 종단 나포·회수 검사에 실패했다. 같은 시드의 이전 KN 성공에서는 강습선 진입 후 회수됐지만 KU에서는 쉴드 제거 약 150.8초, 강습 출발 후 목표가 약 156.5초에 완파돼 진입 전에 패배했다. 피해 수치·체력을 인위적으로 조정하거나 검사를 약화하지 않았으며 기본 스위치를 0으로 되돌렸다. 재설계 시 실제 공격 궤적·포탑/선체/시설 명중 및 목표 완파 원인을 비교하고 플레이어 수동 사격·기발사 공격·내부 아군 보호를 보존해야 한다. F6 `OVCalibration::Start`는 공격 무장만 등록하며 노란 PD 장착/등록이 누락돼 별도 해결이 필요하다. 최종 기본값 KV 빌드 성공·전체 자동 121/121, 이후 시설 슬롯 확인만 강화한 KW 빌드와 해당 112사례 성공. **시험용 복합 함체 충돌 (GW/GX):** `CombatHullBoxes`가 비어 있으면 기존 단일 전투 OBB를 그대로 사용한다. 시험용으로만 기존 OBB 내부의 여러 상자를 명시하면 공격은 가장 먼저 닿은 상자/무장을 사용하고, 패인 면의 장갑 구분은 충돌 법선을 따른다. 선택과 아군 사선 차단의 기존 OBB는 변경하지 않는다. 상자는 양수·유한·기존 OBB 안·최대 32개로 검증한다. `OVShipLayout.*`, `OVShipSystemsComponent.*`, `OVShip.*`, `OVController.*`, `OVHUD.*`, `OVOrderInput.*`, `OVSystemsTests.cpp`, Config 2개, Content/Layouts 3개, Tools의 자산 생성/PIE 검사 스크립트를 추가·수정했다. 정의 자산과 개체 상태 분리, 단일 시뮬레이션 시간, 별도 장갑/슬롯/무장 ID, 표시 전용 프리뷰를 유지한다. 임시 수치는 DefaultGame.ini의 Tuning에 분리한다.

검사로 발견한 읽기 전용 Velocity 변경 오류는 테스트/DEV API 사용으로 고쳤다. 게임 결함인 Canvas 수명에 따른 입력 누출, 대표 함선 교체 시 배열 범위, 프리뷰 클리핑·리사이즈 상한, 부분 쉴드 재가동, 층별 장갑 파괴를 수정하고 해당 API/회귀 검사로 재확인했다. Blueprint/C++ 직렬화 이름은 유지하고 Python 이름 충돌만 ScriptName으로 분리했다.

## 미해결과 다음 순서

1. Windows computer-use 화면 캡처가 시간 초과하여 **직접 마우스·키보드 검증은 미실행**이다. 가이드의 8단계 체크리스트를 실행하고 결과를 별도로 추가한다. 렌더 화면은 엔진 Shot SHOWUI로 확인했다.
2. 한국어 엔진 자체 검사 오류 15건은 별도 기록하며 프로젝트 테스트 성공과 혼동하지 않는다.
3. R11/R13/R14와 1/2층 장갑 연동 임시 규칙은 정식 확정처럼 바꾸지 않는다. 실제 사격/탐지/포탑은 2B부터다.
4. 새 작업 전 Git 상태/소스 커밋/검증 증거를 비교한다. 기존 게임과 UE584BuildSmokeTest는 건드리지 않는다. 생성물은 커밋하지 않고 원격 push는 사용자 요청이 없으므로 하지 않는다.
