# 로컬 UE 채팅용 프롬프트 — 2B-R v1 / D118

아래 본문을 로컬 A1 저장소에 접근할 수 있는 채팅에 붙여넣는다. 이 파일은 실행 요청의 초안이며 이 기획 브랜치에서UE를 수정한 기록이 아니다. 모델은 선택 가능한 목록에 있다면 GPT-6.1 Terra/High를 구현 기본으로, Astra/High를 설계/판정 검토 대안으로 권한다. Ultra는 반복 재현이 어려운 상태 전이/충돌 문제의 집중 분석 때 선택한다. 이는 작업 성격에 따른 추천이며 속도/품질 보장이 아니다.

---

현재 로컬의 GitHub `Jaound/A1` UE 프로젝트를 이어서 수정해줘. **기존2B를 보존하면서 최신 기획에 맞추는 ‘2B-R v1’ 작업**이다. 계획만 쓰고 끝내지 말고 구현·빌드·검증·진행 기록까지 완료해줘.

1. AGENTS와 Git 상태/현재 브랜치·원격/로컬 최신 커밋/미커밋 변경, 코드 브랜치의 GUIDE·VALIDATION·WORK_STATUS·CODEX_PROGRESS를 먼저 확인해줘. 확인된 원격 기준은 `codex/phase1-playground`의 `ca6e8e5`(검증 소스 `3cdda73`)이지만 더 최신 로컬 작업을 보존해줘. 새프로젝트 생성·강제reset·무관한 사용자 변경 포함은 하지 마.
2. `work`를 fetch한 직후 기획SHA를 따로 기록하고 그SHA로 문서를 조회해줘(FETCH_HEAD는 다른 fetch로 바뀔 수 있다). 코드 원격도 fetch하고, 최신 `work`의 `docs/DESIGN_INDEX.md`와 `docs/03_development/PHASE2_PLAN.md`를 **병합 전에도 git show로 읽어줘**. 코드 브랜치에 기획을 안전하게 반영하고 문서 이동/수정 충돌은 `docs/DOCUMENT_PATHS.json`과 담당 범위로 해결해줘. 기존 실행 로그와 코드 문서는 보존해줘. 기준 기획SHA와 코드SHA를 기록하고 `work` 브랜치에는 게임 코드를 푸시하지 마.
3. 개정 계획의 R0→R1→R2→R3를 실행해줘. 아카이브/원시 결과JSON 전체를 한꺼번에 읽지 말고 이번 단계에 필요한 필드/절만 확인해줘. 관련 함대/함선/UI 명세, 미결정 목록, UE 공통 기준, D116 통합 기준, D117 환경의 상태를 읽고 적용/부분 구현/후속/임시값 차이표를 짧게 작성한 뒤 작업을 진행해줘. 이미 있는 이동/공격 독립 자동화·발사/탐지/포탑/피격은 재사용해줘.
4. 우선 쉴드의 활성 회복0·피격 회복 지연 없음·전투/비전투 차등·실제 인원 효율·50% 재가동을 맞춰줘. 새교정 후보는0.6%/1.8%/초·지연0·전환15초이고 최종 확정 밸런스와 구분해줘. 부분 인원 손실과 최대량/인원 계수 이중 적용·무료 충전도 검사해줘. 실제 물리 수리와 인원/점령을 합치지 마.
5. `선체 격파/무장 무력화` 명령을 구현해줘. 관측된 실제 장착점을 조준하되 기존 조준 오차·선회·궤적·충돌을 거치고, 무장 적중은 무장HP만/빗나간 선체 적중은 함체 피해로 처리해줘. 관측 무장이 없으면 대기/완료하며 자동 선체 공격으로 바꾸지 마.
6. 세력별 아군 내부 영웅/작전 상태를 받을 보호 인터페이스와 `계속/목표까지/내부 이탈까지 보류`, 명시적 `강제 무장 공격`을 연결해줘. 실제 영웅/포드 대신 명확한 DEV 입력으로 검증하되 새 발사·미발사 살보는 차단하고 기발사 공격은 유지해줘. 취소/나포/표적 변경의 상태 정리와 적 정보 비공개도 확인해줘.
7. D116 선택 필드로 버전이 붙은 새교정 프로필과 필요한 시험 장면을 마련해줘. m→cm는1회만 변환하고 함체/충돌·시설/무장 위치·간격·카메라/그리드/명령 범위를 함께 점검해줘. 기존 조작감과ControlRange 회귀 기반은 보존해줘. Python 집계 계수·옛global 호환값·가짜15명/기체/승률을UE 규칙으로 복사하지 마. 데이터 출처/해시와 적용·미지원 필드를 남겨줘. 초대형 화력을 자동 하향하지 마.
8. 기존31자동/2A57API/2B50API를 로컬에서 확인해 필요한 회귀를 실행하고 새규칙의 의미 있는 검사를 추가해줘. 정책 변경 기대값은 근거를 기록하고 기존 검사ID를 삭제해 숫자를 맞추지 마. 정지/1/2/3배속·동일 시드·실제 발사/충돌·소수 편대 비교를 포함해줘. 실제 입력을 못 하면 미검증으로 쓰고 API 성공과 섞지 마. Python 전체 함대와 지원 기능이 다른UE를 같은 실험이라고 비교하지 마.
9. 이번에는PD·함재기·실제 강습/영웅·기지/경제·환경4종·최종3D 모델을 만들지 마. D117 세부 효과는 초안이다. 실제UE에서 검증하며2B-R 범위를 지켜줘. 새밸런스 수치를 최종값으로 확정하거나10~15분을 강제로 맞추지 마.
10. 단계별 작은 커밋과 재개 체크포인트를 남겨줘. 컨텍스트가 부족하면 완료분·검사·미완료·정확한 다음 작업을 먼저 저장해줘. 최종에는 변경/적용 기획·코드SHA, 빌드/자동/API/직접 입력의 실제 결과·제약, 실행법과 짧은 직접 확인 목록을 정리하고 코드 브랜치에 커밋·푸시해줘.2C로 자동 확장하지 마.
