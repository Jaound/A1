## 4. 좌측 중심 지휘와 자동 상세

하단 전체 폭에 작은 버튼을 흩뿌리지 않는다.

- 기본 화면은 큰 핵심 행동, 나머지는 맥락 메뉴/보조 탭으로 정리한다.
- 함선 상세 / 선내 지도 / 영웅을 같은 지휘 영역에 인접 배치한다.
- 영웅은 개발 도구의 하위 기능이 아니다. 전투 화면과 선내 창에서도 바로 접근한다.

- 같은 함종 여러 척도 고유 실행 개체를 구분하고 선택·추적한다.

함선 클릭 시 함선 상세를 자동으로 연다.
- 다른 함선 선택 시 상세 대상이 즉시 바뀐다.
- 적은 관측된 외부 정보만 보여주고 내부·재고는 잠금 유지한다.
- 동일 함선 선택의 매 프레임 갱신이 닫은 창을 다시 열지 않는다.
- 명시 재선택/다른 대상 선택과 자동 갱신을 구분한다.
- 다중 선택은 대표 함선과 선택 수를 표시하고 모든 상세를 동시에 열지 않는다.
- 핀 대상은 일반 선택 변경으로 덮어쓰지 않는다.
- 빈 전장 선택 해제 시 비고정 상세를 숨긴다.
- 무장·인원·UI 클릭이 함선 선택/해제까지 중복 실행되지 않는다.

기획의 두핀은 실제 비교 가능한 상세를 목표로 완성한다. 외부 요약만을 독립 전체 상세창 완료라고 하지 않는다. 창을 모두 열 때 입력·레이아웃·캡처 비용을 검사한다.

## 5. 선내 작전/개발 창의 이동·크기 조절

선내 작전 UI와 Insert 개발 UI에 공통 창 프레임을 제공한다.
- 제목줄 드래그 이동
- 모서리/가장자리 크기 조절
- 최소 크기, 닫기·최소화·확대/복원
- 창 앞으로 가져오기와 포커스
- 화면 밖 창 복구와 배치 초기화
- 해상도/DPI 변경 시 화면 안으로 보정
- 최소 크기에서도 핵심 명령은 남고 목록/카드 영역만 스크롤

지도 크기가 바뀌면 그리기와 클릭 좌표를 함께 변환한다. 이동·확대 후 시설/영웅을 잘못 선택하지 않게 한다. 창 위 휠은 창의 스크롤/지도 조작에만 쓰고 전장 줌으로 새지 않는다.

드래그 시작 영역의 제스처 소유권을 유지하고 포커스 상실·창 밖 해제·Alt 선해제 시 종료한다. 전장 회전과 프리뷰 회전을 구분한다.

Insert는 기존 간소화 방향을 유지한다. 큰 이미지 카드·검색·함선/영웅 생성·무장 교체·최소 시험 제어를 기본으로 하고 긴 코드·로그·해시는 고급 진단/문서로 둔다. 기능 API와 회귀 검사는 삭제하지 않는다.

- 위치 찾기 → 실제 현재 위치

이동·공작·교전 상태와 애니메이션이 다른 경우 시각만 꾸미지 말고 상태 연결을 고친다. 수호가 자동 점령을 실행하던 결함을 되돌리지 않는다.

## 7. 함재기 현황과 격납고 개체 카드

기본 전투 화면에 선택 모함의 짧은 항공대 상태를 추가하고 필요 시 함대 전체 요약으로 전환한다.
- 현재 총보유/생존
- 보관
- 출격/교전
- 귀환/도킹 대기
- 관제 상실
- 실제 완파 손실
각 상태를 중복 합산하지 않는다. 시설 공간과 보유 기체 수를 혼동하지 않는다.

격납고는 실제 ID별 이미지 그리드로 보여준다.
- 기체1대마다 카드/아이콘
- HP색/게이지와 보관·비행·귀환·손실 상태
- 수납 소형함도 이미지 카드와 함종/HP/출격 조건
- 격납고별 용도와 가동/파괴 상태
- 출격·명시 복귀·상세 상태
- 생존·손상·손실 필터와 선택
- 대량 카드 가상화/스크롤/그룹화

함재기를 플레이어가 개별 비행 조종하는 기능으로 바꾸지 않는다. 클릭은 선택 정보·위치 찾기 중심이다.
기체 ID·HP·쿨타임은 카드 갱신·귀환·재출격으로 초기화되지 않는다. 다른 모함 나포/전환과 과거 소속 기록을 구분한다. 관측되지 않은 적 재고는 노출하지 않는다.

## 8. 선택 무장의 우하단 시각 패널

함선 상세에서 무장을 선택하면 창 내부 우하단에 해당 무장 전용 표시를 연다.
- 해당 종류/티어의 형태 썸네일
- HP수치/비율과 정상→손상→위험→파괴 색상
- 보조 아이콘과 짧은 작동 상태
- 현재 목표와 발사 차단 이유
- 실제 조준/발사/피격/파괴를 따라가는 실시간 근접 교전뷰

썸네일과 실시간뷰를 구분한다. 저장된 영상을 실시간처럼 재생하지 않는다.
공급 정지·관제 상실·재사용 대기·수동 대기는 HP색만으로 표현하지 않고 상태 아이콘을 함께 사용한다.

실시간뷰는 같은 무장ID의 표시 프록시/읽기 전용SceneCapture를 사용한다.
새 무장·공격·전투·피해·재고를 복제하지 않는다.
적 무장 상태는 관측 권한에 따라 미확인을 유지한다.
현재 전투가 없으면 정상 대기 모습을 보여주고 가짜 사격을 만들지 않는다.

팝업 이동/리사이즈 시 패널이 같이 재배치된다. 숨김·최소화·파괴 대상·FTL 이탈 시 캡처와 참조를 정리하고 업데이트 비용을 줄인다.

## 9. 실제 포탑·PD와 모델 연결

포탑은 실제 시뮬레이션의 로컬 조준각을 따른다.
- 상부/하부 좌표계와 기계 회전축
- yaw/pitch 제한 및 유한 선회
- 탐지 상실·목표 변경·함선 회전
- 개별 무장 파괴·복구·나포
- 같은 발사ID의 중복 효과 방지
- 실제 포구와 발사 원점·사선 검사 일치

PD 종류 교체 UI를 실제 PD 장착 상태와 연결한다. 일반 공격 무장 목록을 바꾸는 것으로 요격 무장이 교체됐다고 하지 않는다. 사거리·주기·피해·시설·HP·효과 연결을 확인한다.
PD의 기존 즉시 획득과 시각 선회를 혼동하지 않는다. 새로운 PD 정렬 제한으로 밸런스를 바꿔야 한다면 별도 변경으로 명시하고 비교 검증한다.

프리뷰/실제 전장/우하단 무장뷰에서 같은 조준·HP·발사 상태를 읽는다.

- 아군 영웅 피격
- 아군 쉴드 파괴/재가동
- 아군 장갑 구획 파괴
- 아군 시설 물리 파괴
- 아군 함선 완파
- 관측된 적 쉴드 파괴
- 관측된 적 장갑 파괴
- 관측된 적 시설 파괴
- 적 함선 완파
- 함재기 생존50%미만
- 함재기10%잔존
- 함재기 실제 전멸

추가로 이미 존재하는 상태에서 지원할 것:
- 영웅 사망/구조 대기
- 나포·탈환
- 강습선 상실·철수 수단 상실
- 격납고/관제 불능
- 초광속 회수 대기·잔여 기체 포기
이 사건을 표시하려고 미구현 구조 캠페인을 새로 만들지 않는다.

표시 계층:
1. 짧은 화면 토스트: 아이콘·대상·사건·위치 바로가기
2. 최근 사건 피드
3. 시간/유형/대상으로 볼 수 있는 상세 전투 로그
4. 아군 위급 사건의 붉은 화면 외곽 경고

일반 피격과 적 격파마다 붉은 외곽을 켜지 않는다. 영웅 위기·침입·아군 핵심 기능 파괴·함재기 극소수/전멸 등 실제 긴급도에 맞춘다. 점멸은 절제된 속도와 지속시간을 사용하고 강도/끄기 옵션을 둔다. 같은 프레임 여러 경고가 중첩되어 밝기가 폭증하지 않게 한다. 경고가 UI 입력을 가로막지 않는다.

구현 세부 제안:
- 같은 대상/유형의 반복 피격은 짧은 게임시간창에서 묶고 횟수를 남긴다.
- 파괴는 실제 정상→파괴 상태전이당1회다.
- 승무원 부족/점령/마비를 물리 파괴로 오표시하지 않는다.
- 시설 유폭→코어 파괴→함선 완파는 원인 연결을 보존하되 화면에는 최상위 결과 중심으로 묶는다.
- 낮은 우선순위는 적절히 묶고 중요한 사건은 놓치지 않게 우선 표시한다.
- 이벤트 저장/토스트 대기열은 유한하게 유지하고 잘린 기록/묶음 수를 명시한다.
- 지난 사건 버튼은 실존 개체 또는 마지막 확인 위치로 이동하며 숨은 현재 좌표를 읽지 않는다.
- 초기 로드/임무 재시작 시 모든 파괴 상태를 새 사건으로 재생하지 않는다.
- 이벤트 판정은 게임시간, 화면 표시/창 조작은 실제시간을 사용한다. 정지 중 중요한 내용을 읽고 로그에서 다시 찾을 수 있게 한다.
- 적 시설/영웅 정보는 실제 관측 권한이 있는 경우만 구체 이름/위치를 보여준다.

함재기 경보의 분모를 반드시 정해 문서화한다.
우선 교전 시작 시 실제 소유 기체ID 집단을 기준으로 하며, 도킹/출격/귀환은 분모나 생존 수를 바꾸지 않는다. 신규 생산·편입·이송·나포는 별도 조정 사건으로 처리한다.
50%는미만,10%는이하,0은실제완파전멸로 구분한다. 함대 전체와 모함별 경보 범위를 표시한다.
관제 상실·모함 나포·FTL 이탈로 보이는 기체가0이 됐다고 전멸이라 하지 않는다.
낮은 기체 수에서 같은 순간 임계치 여러 개를 통과하면 최상위 토스트로 묶고 로그에는 근거를 남긴다.
분모0에서 나누지 않고, 카드 열기/재출격/선택 변경으로 임계치 경보를 재발동하지 않는다.
이 분모와 재알림 정책은 시험 구현안이며 실제 시나리오로 확인한다.

## 11. UI·성능·직접 플레이 검증

UI 확인:
-1920×1080 기본,1280×720 작은 창,가능하면2560×1440
-한국어/DPI/긴 이름/스크롤/작은 버튼/고급진단 접힘
-함선 선택 즉시 상세,닫기/재선택/다중선택/핀
-선내/개발창 이동·크기 조절 후 클릭 좌표
-영웅/함대/무장/함재기 이미지와 실제 상태
-대량 기체 카드와 무장 라이브뷰
-알림 클릭·창 제스처가 전장으로 투과하지 않음

기능 확인:
- 기존 자동85개 및 관련API를 실제 최신 상태에서 재실행
- 상한/장착/재고와 주포2문 동기화
- 실제 모델 적용·무장 교체·피격/조준/발사
- 1/2/3배속과 일시정지
- 실제 진입/피격/쉴드/장갑/시설/함선 파괴 알림
- 함재기 임계치와 분모/소속/도킹/재시작 경계
- 반복 창 열기·닫기·생성·삭제의 참조/메모리/이벤트 누적

이전 검사 ID와 의미를 보존한다. UI가 바뀌어 fixture가 달라지면 원인을 기록하고 정상 입력 경로를 검사한다. 실패 기대를 지우거나 판정을 약화해 통과시키지 않는다.

직접 OS 입력이 실패하면 한정 재시도 후 미검증으로 기록한다. API/렌더를 직접 입력으로 포장하지 않는다. 사용자5~10분 체크리스트를 작성하고 나머지 독립 구현을 계속한다.

성능은 실제 모델·카드 대량 표시·두핀·우하단무장뷰·경고 폭주 조건을 구분해 측정한다. 같은 편성/시드/해상도/배속으로 전후 비교한다. 평균/p95/최대·CPU/GPU·메모리·객체 수를 기록한다. 10분 실행의 생존자 감소를 최대부하 유지로 표현하지 않는다.300코스트는 실제 측정 없이 보장하지 않는다.
