# UE5 제작 공통 기준

> D118 개정(2026-11-16). 최신 담당 명세를 UE5로 구현하기 위한 기술 기준과 검증 항목이다. 원격2B `ca6e8e5`의 실제 구현/기록과 최신 작업은 [2B-R](PHASE2_PLAN.md)에서 구분한다. 기획 충돌의 대안을 확정한 문서는 아니다. 미결정 게임 규칙은 [미결정 목록](../00_overview/OPEN_QUESTIONS.md)의 관련 R항목를 확인한다.

## 1. 문서 읽기 순서와 적용 범위

[문서 지도](../DESIGN_INDEX.md)의 담당 범위·상태 구분을 따른다. 읽는 순서는 GDD/결정 기록 → 관련 분야 명세 → [미결정 목록](../00_overview/OPEN_QUESTIONS.md) → [구현 상태](IMPLEMENTATION_STATUS.md)/단계 계획이다. 게임 판정은 분야 명세, 이 문서는 UE 기술 적용·검증을 관리한다.

동일한 최신 근거의 충돌은 R항목으로 남기고 임의 선택하지 않는다. 프로토타입/과거 리뷰의 해결안이나 임시 코드값은 현재 기획을 대체하지 않는다. 문서 아래에 새 확정 추록을 누적하는 대신 담당 본문과 결정 기록을 갱신한다.

## 2. 단위·좌표·프로토타입 이식

- UE5 내부 기본 단위는 cm, 시간은 초, 고도는 **+Z**, 함선의 논리적 전방은 **+X**, 우측은 **+Y**로 통일한다. 메시 임포트 방향 차이는 표시 변환으로 보정한다.
- 프로토타입의 Y-up·Z-forward, `half_extents.z` 길이 가정과 `basis` 행렬을 그대로 쓰지 않는다. 6면 판정과 강습 고도는 함선 **로컬 좌표**로 변환한 뒤 처리한다.
- 미터→cm는 경계에서 한 번만 변환한다. 예: 포드 165m/s=16,500cm/s, 요격 사거리 111m=11,100cm. rad/s→deg/s도 한 번만 변환한다. 혼합 단위 프로필을 허용하지 않는다.
- ‘이전 대비 50%’ 대신 최종 절대값과 원형 프로토타입 버전을 기록한다. 새로 로드할 때마다 너프·버프를 누적하지 않는다.
- 프로토타입의 PD 185→111m와 210→126m는 **60% 유지**다. 함수 이름이나 툴팁에 60% 감소라고 적어 74m/84m를 만들지 않는다.

## 3. 시뮬레이션과 표시의 소유권

- 전투 규칙은 하나의 런타임 시뮬레이션에서만 계산한다. 카메라·UMG·SceneCapture·프리뷰는 그 결과를 읽는다.
- 함선·시설·슬롯·장갑 구획·무장·함재기·포드·작전 웨이브에 안정적인 ID를 둔다. 레이아웃 정의 자산과 개체별 상태를 분리한다.
- 데이터 자산 변경 없이 서로 다른 함선이 같은 레이아웃을 독립적으로 사용해야 한다. 복제 뷰어·여러 핀 창이 게임 개체를 추가 생성하지 않는다.
- 공통 시뮬레이션 시간에만 일시정지·1/2/3배속을 한 번 적용한다. 조작·창 드래그·카메라는 정지 중에도 반응한다. 무장 재사용·살보·요격·쉴드·FTL·점령·충각 쿨타임은 게임 시간 기준으로 동작한다.
- 고속 투사체와 회전·접촉은 충분히 작은 시뮬레이션 스텝이나 Sweep/연속 판정으로 처리한다. 렌더 프레임이 떨어지거나 3배속이어도 함선을 관통해 지나치지 않게 한다.

## 4. 데이터 구조의 최소 분리

| 데이터 | 담당 정보 |
| --- | --- |
| 함체·층 레이아웃 | 1~3층 슬롯·고정 복도·승강 통로·배치 제약·로컬 피격 영역 |
| 장갑 레이아웃 | 6면과 가변 구획 ID, 정규화 범위, 내부 슬롯 매핑, 전후 단일 면 예외 |
| 시설 인스턴스 | 종류·내구도·점령·인원 게이지·가동률 |
| 무장 인스턴스 | 계열·종류·티어·장착 위치·개별 HP·로컬 포탑 각도·발사 상태·표적 |
| 명령 상태 | 이동 목적지·공격 표적·발사 요청·자세·정지 유지·독립 이동/공격 자동화·FTL |
| 소유·운용 상태 | 세력·중립·완파·모함/수납 관계·관제 가능 여부 |
| 화면 상태 | 선택 목록·대표 함선·선택 무장·층·창 위치·핀·입력 모드 |

장갑 구획 ID와 내부 슬롯 ID를 같은 값으로 가정하지 않는다. 전면 장갑 하나가 여러 방에 대응할 수 있다. 2층 **26**, 3층 **38**은 데이터 구성 결과를 검증하며 모든 함선에 38개를 고정 생성하지 않는다. 외장 무장 피격은 쉴드 이후 해당 무장 HP만 차감하며 장갑·시설·선체로 중복/초과 전달하지 않는다(D089/R14).

## 5. 입력·명령·자세 상태

- 이동 자동화와 공격 자동화는 독립된 지속 상태다(D101). 전체수동/전체자동은 두 상태의 프리셋이며 혼합을 허용한다. 이동 목적지/표적/발사/방향/수리 지정은 별도의 입력/명령 상태이며 단일 bManual만으로 두 자동화를 대체하지 않는다.
- UI가 소비한 입력은 전장으로 전달하지 않는다. 떠 있는 창의 드래그·리사이즈·모델 회전·무장 클릭이 전장 이동·줌·발사로 이어지지 않아야 한다.
- 공격 표적 지정과 발사 요청을 분리한다. 수동 모드에서 표적을 고를 수 있어야 하고 표적 변경만으로 자동 모드가 되거나 발사 제어를 빼앗지 않는다. 요격은 자동 운용 규칙을 유지한다.
- 빈 공간 선택 해제는 이동 확정·공격 대상 선택 모드가 소비한 클릭 뒤에 실행하지 않는다. 모드 취소와 PIE 종료 입력을 구분한다.
- 이동 레이의 실제 기준면과 표시 디스크는 동일하다. Z 오프셋은 입력 시작 기준면에서 계산하고 커서 재투영으로 목적지가 카메라 앞으로 튀지 않게 한다. 수평에 가까운 레이·음수 교차 거리·카메라 근접 교차는 유효성을 검사한다.
- 본작 최신 부대키 1~9, Ctrl+1~9 저장, 시간 제어 키를 입력 액션으로 분리하고 사용자 리바인딩을 허용한다. 무장 그룹·기존 F1/F2 선택·R 이동과의 동시 바인딩을 금지한다. 현재 키는 코드 가이드, 미확정 추가키/핀은 R13에서 관리한다.
- 이동/가속/제동과 선체 자세·포탑 조준을 분리한다. 이동 정지는 감속 후 Hold 상태이며, 자동 AI가 다음 틱에 이동을 다시 시작하지 않는다. 수동 자세·측면 포격을 자동 표적 추적으로 덮어쓰지 않는다.
- 포탑은 장착 부모 기준 로컬 yaw/pitch·회전 속도·발사각 조건을 사용한다. 탐지 상실 후 마지막 확인 위치를3.5게임 초만 유지하며 숨겨진 현재 위치를 읽거나 새로 발사하지 않는다(D084/R20). 표시상 조준 유지가 표적 무효·사거리·탐지·사각·기능 정지 조건을 무시하는 발사 권한은 아니다.

## 6. 피해·정지·수리의 규칙

- 쉴드는 전투/비전투 모두 파괴 비활성 상태에서만 차등 속도로 점진 회복한다. 50% 재가동 즉시 회복 중단, 활성 비전투 완충 경로는 금지한다. D116에 따라 피격 회복 지연/대기 갱신은 없으며 실제 쉴드 운영 인원 효율을 적용한다. 회복 기준 최대량과 인원 계수를 분리해 이중 보정/무료 재가동을 검사한다.0.6%/1.8%/초·전환15초는 새 시험 후보이며 최종 수치가 아니다.
- 무장 무력화 명령은 관측된 장착점을 실제 조준/충돌로 공격한다. 무장 적중은 해당HP만·초과분 미전달, 빗나간 함체 적중은 정상 피해다. 아군 내부 잔류 보호는 세력별 실제 상태 질의와 신규 사격/살보에 적용하고 기발사 공격은 유지한다. 본문 세부/강제 예외는 담당 명세를 따른다.
- 빔은 확률, 포탄/미사일은 조준 오차+실제 궤적/충돌을 사용하며 별도 회피를 이중 적용하지 않는다. PD 확률은 명중×(1−회피)다.
- 살보 매 탄 발사 가능 조건과 아군 사선을 재검사한다. 조건 상실 시 미발사 잔여탄 취소·이미 발사한 탄 유지. 일반 미사일 곡선은 각 탄 발사 시 고정한다.

- 한 피격 사건에 `EventId`, 공격자·소속, 무장, 원인, 로컬 탄착점·방향, 장갑 구획, 내부 슬롯을 기록한다. 피해·HP·유폭·완파 처리는 한 번만 적용한다.
- 외부 포격·유폭·정밀 사보타주·충각은 원인을 구분한다. 전후 단일 면 장갑 예외와 사보타주 장갑 보존을 다른 구획에 잘못 확장하지 않는다.
- 유폭은 큐와 처리한 시설 ID 집합을 사용한다. 같은 피해 연쇄에서 이웃 시설을 거쳐 같은 탄약고가 재폭발하지 않는다. 집합은 사건별로 초기화하고 복구 후 별도 피격에 의한 재폭발은 허용한다. 시설 중복 수가 한 사건의 유폭 횟수를 무제한 증가시키지 않는다.
- 완파는 즉시 게임플레이 상태에서 제외한다. 이후 표류·폭발 연출은 표시 전용이며 무장·나포·도킹·수리가 계속 동작하지 않는다.
- 수리는 물리 손상을 복구한다. 적 점령·인원 부족·개별 포탑 고장·제어실 고장·탄종 공급 중단을 각각 해소하기 전에는 발사를 재개하지 않는다.
- 중복 시설 효율은 원래 성능에서 재계산한다. 100/150/200%를 실행 중 속성에 반복 곱하지 않는다. 현재 쉴드와 HP는 최대치 변경 후 제한하되 임의 완충하지 않는다.
- 최저 장갑 마모는 수치가 미정이다. 적용 위치(장갑 내구도/시설/HP)를 정하지 않은 채 모든 층에 최소 피해를 중복 추가하지 않는다.

## 7. UI와 실시간 3D 뷰어

- UE5에서는 UMG/Slate 입력 소비, SceneCaptureComponent2D·RenderTarget 또는 런타임 격리 프리뷰 등으로 구현한다. `SubViewport`, `own_world_3d`, `accept_event`, `MOUSE_FILTER_STOP`를 UE API로 사용하지 않는다. `MultiMesh`도 UE에서는 ISM/HISM 등 목적에 맞는 방식을 검토한다.
- 스튜디오 뷰는 표시 프록시, 전장 캠은 읽기 전용 전투 시점이다. 프록시는 충돌·AI·무장·피해·소유량을 계산하지 않는다. 에디터 전용 PreviewScene 모듈을 게임 런타임 의존성으로 무조건 추가하지 않는다.
- 함선 자세·포탑 각도·HP·장갑 색·피격/발사 이펙트의 **읽기 전용 스냅샷/이벤트**를 전달한다. 프리뷰의 사용자 회전은 실제 함선의 자세 명령을 바꾸지 않는다. 표시 이펙트가 실제 발사 함수를 부르지 않는다.
- 최소화·숨김·닫힌 창의 SceneCapture 갱신을 중단한다. 최대 2핀·선택 전환·함선 파괴 시 자원을 정리한다. 두 프리뷰가 함선·투사체 수에 합산되지 않음을 검사한다.
- D116의 미공개 적 영웅 수/레벨·함재기 재고·수리 화물을HUD/AI가 조회하지 않는다. 자기 세력 정보·관측된 상태와 개발용 전체 진단을 분리한다.
- 실제 플레이의 적함 내부 정보는 강습 공개 상태를 거친다. 3D 뷰어·층 버튼·툴팁·피격 리포트가 숨겨진 시설명·승무원 수를 유출하지 않는다. 디버그 노출은 별도 권한/플래그다.
- 다중 선택은 선택 ID 목록과 대표 함선을 분리한다. 대표 사거리만 표시하고 죽거나 해제된 함선의 포인터를 UI가 계속 참조하지 않는다.

## 8. 함재기·격납고·포드의 소유량

- 격납고1개당 소형함1척 또는 기본 함재기20대이며 D116의 연구로 함재기 공간만 소폭 증가한다. 단계당+2/최대3단계는 시험안이다. 공간 증가와 실제 기체 구매·연구/개조·수리/보유량을 분리하며 무료 기체/회복을 생성하지 않는다. 별도 공통100대 상한을 넣지 않고 설치 가능 체급과 함체별 상한은 D126(대형 이상, 항공순양함6/항모4/구축전함4/전함2/전략 미사일함1)을 따른다. 함재기 운용은 항모·항공순양함만 허용한다.
- 함재기는 명시적 복귀 명령으로 수리하며 정기 귀환/탄약고갈을 필수화하지 않는다. FTL은 회수 대기가 기본이며 명시적 포기 도약을 지원한다.
- 강습선 진입자는 생존 강습선 회수와 상실 시 비상 탈출을 구분하고 새강습 포드를 무료 생성하지 않는다. 진입 층은 대상 로컬 실제 도달면/높이 구역, 공작 체크포인트는 진행률1/3·2/3, 함교 소유권은 무인/유예만료로 자동 반환하지 않는다.

- 소유 기체 ID가 `보관/출격/귀환/도킹 대기/정지/완파` 중 하나의 실제 상태를 갖도록 한다. UI 재고 숫자를 줄였다가 자동 생성하는 방식으로 소유량을 계산하지 않는다.
- 완파된 기체는 재출격하지 않는다. 모함 변경·나포·격납고 파괴 시 내부/외부를 구분하고 소속 변경과 물리적 수리를 분리한다.
- 소형함 수납 시 외부 전투·충돌·센서에서 제외하고 컨테이너 안의 동일 개체로 보존한다. 수납한 함선이 모함을 다시 수납하는 순환 관계를 막는다.
- 포드는 탑승자 개인1명마다1기다(D113). 영웅/병사 개인ID·원 소속 분대ID·원래 귀환 슬롯·웨이브ID·개별 발사 시각/HP/결과를 기록한다. 분대4명을1포드로 합치지 않으며 부분 손실은 분대 잔존 인원에 반영한다. 보직·수호 병력은 자동 차출에서 제외하며 명시 선택 시 전환 규칙을 사용한다.
- 요격·쉴드 충돌·귀환·목표 이탈·모함 상실·내부 완파를 다른 전이로 처리한다. 구조 중인 영웅이 동시에 납치·귀환되거나 죽은 영웅이 구조되지 않도록 동일 대상의 결과를 한 번만 확정한다.

## 10. 후속 프로토타입의 표시 구조 참조

[후속 업데이트 기록](../05_references/PROTOTYPE_FBX_UPDATE_RECORD.md)은 사용자 보고 자료다. 모델 도입은 보류하되, 장착 기준→Yaw→Pitch→포구 계층·표면 법선/함교keepout·부모 로컬 회전·읽기 전용 뷰어 동기화를 후속 구현에서 고려한다. Godot의중앙선X=0/+Y상향을UE의전방축으로 그대로 복사하지 않는다. 에셋 시각배율을화력배율로 사용하지 않고bounds변경 시 충돌/피격/카메라/기지접안 출입을 함께 검증한다. 백터급/바스티온급의 기획 분리는D110으로 확정됐다. 그 외R30 수치·새무장 채택과FBX도입은 별도 결정이며2B의필수 선행조건으로 추가하지 않는다. Godot의422검사/웹스모크가UE결과를 대신하지 않는다.

## 11. D118 데이터 교정과 환경 범위

D116 선택 필드를 버전 있는 교정 프로필로 이식하고 단위/소스/해시/미지원 목록을 기록한다. 집계용 관통/추적/표적 가중치·그룹PD/함재기·선내 승률·옛global 호환 필드를UE의 실제 물리 규칙으로 복사하지 않는다. 실제 장면의 충돌/크기·시설/무장·카메라/명령 범위와 함께 검증한다.2C/3단계 없이 모든Python 함대전과 지원 기능이 같다고 주장하지 않는다.

임시 내부 배치는 논리ID/레이아웃 버전을 유지하고 향후 함선/기지 에셋별로 다시 제작한다. D123으로 환경 행동 규칙을 채택했다. 운석 충돌/파괴/지형 변경, 방사능의 노출 부위 피해·전투 판정, 플레어의 부분 엄폐/정지, 블랙홀의 실제 견인·중심부 완파·FTL 중 외력 변위를 지원해야 한다. FTL 충전 시간/사용 조건은 유지한다. D124의 정지는 이동·무장·요격 등 작동 기능을 일시 중단하며 지속 시간은 시뮬레이션으로 찾는다. D125의[환경E1](../02_balance/SPACE_ENVIRONMENT_BALANCE.md)은Python설계시험을통해준비한초기값이다. 실제UE단위·시설/쉴드·질량/추력·메시노출·정지중기능별재개는후속검증대상이며 임의 관통/기체 사망/무료 구조를 추가하지 않는다. [환경 명세](../01_design/strategy/SPACE_ENVIRONMENTS.md)를 따른다. 이는 새 환경 구현 계약이며 과거2B-R나 환경 없는 결과의 완료 기준을 소급 변경하지 않는다.

## 최신 변경 적용 — D126

최신 기획이 과거 작업 계획·코드 프로필보다 우선한다. [D126 통합표](../02_balance/GRID_HULL_OUTPOST_DECISIONS.md)의 내부 슬롯·격납고·함종별 문수/속도·교전 시간 기준을 적용한다. 기존 v0.6/환경E1 입력은 재현용으로 보존하고 새 버전 프로필로 이관한다. 층당15개 시험 슬롯과14/26/38 장갑 구획을 혼동하지 않는다. 변경 후 경로·유폭·강습·수리·격납·저장 이관·1대1/함대전 검증이 필요하다. 메뉴 구현은 [시작·메뉴 명세](../01_design/interface/START_SCREEN_AND_MENU_SPEC.md)를 따르며900초 고정 제한을 기본값으로 재도입하지 않는다.
