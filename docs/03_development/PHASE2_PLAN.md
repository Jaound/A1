## 이번 작업의 범위와 완료 순서

### 2B-R0 — 안전한 동기화와 차이표

1. 로컬 AGENTS·Git 상태·브랜치/원격·최신 실행 기록을 확인한다. 기존 사용자 변경을 보존하고 필요하면 별도 작업 공간/체크포인트를 사용한다. 새UE 프로젝트를 생성하지 않는다.
2. 최신 `work`와 코드 브랜치를 fetch한다. 코드 브랜치에서 기획을 안전하게 병합/반영한다. 문서 이동/내용 충돌은 [경로 대응표](../DOCUMENT_PATHS.json)와 담당 범위로 해결한다. 일괄 ours/theirs·강제reset·무관한 변경 포함을 하지 않는다.
3. 코드 브랜치의 `docs/PHASE2B_GUIDE.md`, `PHASE2B_VALIDATION.md`, `WORK_STATUS.md`, `CODEX_PROGRESS.md`, 검증 원본은 보존한다. 분야 기획은 새 폴더를 사용하고 이 가이드들의 관련 링크/상단 기준만 최신화한다. 과거 커밋의 증거/수치를 새 결과로 고쳐 쓰지 않는다.
4. 이번 계획/코드 차이를 적용/부분 구현/후속/임시값으로 표시한다. 최신 소스에서 이미 일치하는 항목은 재구현하지 않는다. 차이표만 쓰고 멈추지 않고 아래 구현을 진행한다.

### 2B-R1 — 정책·명령·피해 경계

**쉴드:** 활성 상태는 전투/비전투 모두 회복0, 비활성은 피격으로 대기 시간이 생기거나 갱신되지 않는다. 레거시 지연 필드는 폐기/무효화하고 새 시험 기본값은0초·전투0.006/비전투0.018/초·상태 전환15초로 명시한다. 쉴드 제어실의 실제 승무원 효율을 양쪽 회복에 적용한다. 공격/피공격 사건과 단순DEV 피해를 구분하고 발사 측의 전투 상태도 갱신한다.

부분 인원 감소로 회복속도가 바뀌는 실제 경로를 연결한다. 인원 손실 곡선/적용 원인은 설정으로 격리한다(v0.6의0.20은 후보). 시설HP·승무원·점령·개별 무장HP를 합치지 않는다. 물리 수리로 승무원을 생성하지 않으며 실제 수리/충원 경제는 이번 범위가 아니다.

`MaxShield`를 줄여 회복률이나 재가동 시간을 맞추지 않는다. 회복의 기준 최대량과 인원 효과를 따로 기록해 같은 인원 보정을 두 번 곱하지 않는다. 단일 제어실 교정 프로필은 가동 중 부분 인원이 줄어도 명목 최대량을 유지하고 회복에 인원 비율을 곱하는 v0.6 가정을 채택한다. 전부 파괴/점령/인원0이면 쉴드 소멸/회복 불가다. 다중 제어실의 최대량 합성은 R23의 제안/기존 기능과 구분해 별도 설정으로 남기고 단일실 가정을 전체 게임의 최종 규칙으로 확대하지 않는다.

**무장 무력화 명령:** 선체 격파/무장 무력화 의도와 명령 상태를 분리한다. 탐지·관측된 적 장착점의 위치를 조준하되 실제 포탑 선회/조준 오차/궤적/충돌을 거친다. 클릭한 무장에 직접 피해를 꽂지 않는다. 다른 무장/선체에 맞을 수 있으며 무장 적중과 함체 적중을 중복 처리하지 않는다. 알려진 살아 있는 무장이 없으면 완료/대기하고 자동 선체 공격으로 바꾸지 않는다. 탐지 상실 후 숨은 현재 위치를 읽지 않는다.

**아군 내부 잔류 보호:** 사격하는 세력을 기준으로 아군 영웅 존재와 작전 목표 완료를 질의하는 인터페이스를 둔다. 세력 공용 boolean으로 적 영웅까지 보호하거나 적 전체 로스터를 읽지 않는다. `계속 사격/목표까지/내부 이탈까지 보류`와 기본 이탈까지를 구현한다. 자동 표적 선정·명시 표적의 자동 사격·미발사 살보를 같은 판정으로 차단한다. 이미 발사된 공격은 유지한다. 보호된 표적의 `강제 무장 공격`은 명시한 명령/표적/공격 무장에만 적용하고 취소·표적 변경·나포 때 초기화한다. HUD에 상태/위험을 표시한다.

실제 영웅/포드를 만들지 않고 DEV에서 세력별 내부 영웅/목표 상태를 주입해 검증한다. 기본 입력은 실제 영웅 없음이며 DEV 주입은 명확히 표시한다. 미래 함재기/강습 소비자도 같은 판정을 사용할 수 있게 하나의 권한 있는 상태를 사용한다. 승무원0 중립화와 미래 생존 영웅/병력 조건도 연결 가능한 질의 경계를 두며 아직 없는 병력을 가짜로 생성하지 않는다.

**상태 경계:** 공격자/목표 나포·완파·이탈·표적/모드 변경 때 기존 명령/미발사 살보를 정리한다. 기발사 공격의 소속·무장 스냅샷은 바꾸지 않는다. 엔진 물리 파괴와 인원/점령 효율0을 구분해 기존FTL 시험 조건을 R12/R25와 대조하고, 미정 전이는 임시 정책으로 명시한다. 실제 성계 여행을 구현하지 않는다. 외부 시설 파괴의 장갑 연동·전후 단일 면/정밀 공작 예외·피해 연쇄당1회·복구 후 새 사건 재유폭은 기존UE 구현을 회귀 확인한다.

### 2B-R2 — 데이터·공간 교정

새 프로필은 `Calibration_D116_v06` 등 버전/출처가 명확한 이름으로 두고 현재 소규모ControlRange의 카메라/조작 회귀 기반을 보존한다. 필요하면 별도 교정 맵/프리셋을 만든다. 레거시 형상/수치가 최신 게임의 기본 밸런스로 보이지 않게 표시하고, 확정된 쉴드/명령 정책은 모든 프로필에서 일관되게 적용한다.

| 이식 분류 | 입력/처리 |
| --- | --- |
| 함체/무장 후보 | `reference/IntegratedCombat/profile.json`의 `ships`/`weapons`/`radar`/`tier_damage`에서 이번 외부전에 필요한 선택 필드. 프로필ID/단위/채택·미지원 목록 기록 |
| 쉴드 후보 | `integration.combat_regen/noncombat_regen/noncombat_after/shield_delay`를 이름을 바꿔 명시 매핑 |
| 후속 메타데이터 | PD/격납고·영웅/기체/수리/건조비는 식별자/원본 보존 가능. 이번에 실제 기능이 작동한다고 표시하지 않음 |
| 자동 이식 금지 | 옛 `global` 호환 필드, 집계용 관통/추적 계수·표적 가중치·그룹PD/함재기·선내 승률 표본·시간제 재탈환·강제집중상한·원형 명중반경 |

미터→cm와속도 m/s→cm/s는1회만 변환한다. 보장 근거리250m→25000cm, 속사 빔 기본700m→70000cm가 새 후보이며 이전1600/6000cm와 섞지 않는다. Python의 `radius`는 명중 근사 반경이므로 함선의 전장/전폭/높이로 그대로 쓰지 않는다. UE 임시 레이아웃·외부 형상/충돌·장착점·층·시설 매핑·간격·카메라 줌/클리핑·그리드/명령 범위를 함께 점검한다. 기존 마우스 제스처 감각은 보존하고 공간 범위만 설정으로 조정한다.

백터1F/공격3/PD2와 바스티온2F/공격5/PD4의 식별을 데이터에서 유지한다. 가능한 함체16종의 후보 등록/지원 여부를 표시하되 이번 완료 조건에16종의 완성 모델/AI/모함 기능을 요구하지 않는다. 소형/중형 대표와 무장 계열로 실동작을 검증하고 초대형 데이터/전용 주포를 가져올 때 수치를 자동 하향하지 않는다. 혼합 티어 유폭이 준비되지 않은 레이아웃은 검증기로 차단하거나 미지원으로 명시한다.

UE의 실제 포탑/탄도/충돌을 Python의 집계 명중률로 바꾸지 않는다. 빔은 확률, 포탄/미사일은 연속 조준 오차+실제 충돌이며 추가 회피 주사위를 넣지 않는다. 변환/미지원 규칙과UI의 조준 품질·실측 명중률을 구분한다.

### 2B-R3 — 회귀·비교·기록

- 로컬 최신 기준으로 빌드/기존 자동31개·2A API57개·2B API50개를 발견하고 필요한 회귀를 실행한다. 번호를 맞추려고 검사를 삭제하지 않는다. 정책 변경 기대값은 근거와 함께 갱신하고 기존 검사ID/기능 보장을 보존한다.
- 추가 검사는 아래 인수표를 기준으로 구성한다. DEV 준비는 허용하지만 실제 발사→궤적/충돌→피해로 결과를 확인한다.
- 우선1대1·소수 편대의 같은 편성/시드/단위/지원 기능으로 로그를 대조한다. 2C/3단계 없는UE 결과를 PD·함재기·영웅이 포함된Python 전체전과 같은 조건이라고 주장하지 않는다. 필요하면 지원하는 무장/소수 함체만의 별도 대조 입력을 만든다. 전체1328회 모형 재실행은 필수가 아니다.
- 시작/주력 교전/종료·최초 완파, 발수·피격 부위·무장 손실·기능 마비·보류 사유를 구분한다.10~15분은 방향이며 타이머·강제공격상한·초대형 하향으로 시험 결과를 맞추지 않는다.
- 각단계 실제 수행·미실행·미지원·코드/기획 SHA·설정/데이터 해시·빌드/검사로그를 기록한다. 직접 입력 도구 실패는 API 성공과 분리하고 재시도를 무한 반복하지 않는다. 짧은 사용자 직접 조작 체크리스트를 남긴다.
