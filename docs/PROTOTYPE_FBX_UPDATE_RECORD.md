# 후속 Godot 프로토타입 — 함급·포탑·전장 확장 기록

> 접수: 2026-11-16(KST). **사용자가 전달한 과거 프로토타입 변경 보고의 참조 기록**이다. 새 소스/FBX/텍스처/빌드 ZIP/원본 검증 로그는 이번에 제공되지 않았으며 독립 재검증하지 않았다. 실제 작업일·커밋·파일 해시는 미확인이다. 모델명에 포함된 날짜를 빌드일로 간주하지 않는다.
>
> 사용자 요청은 **모델링 도입을 보류하고 기록을 보관해 후속 구현에서 고려**하는 것이다. 아래 모델·함급 변형·슬롯·밸런스·월드 범위·특수 무장·배포 결과를 UE에 즉시 적용하거나 현행 확정으로 승격하지 않는다. 적용 판단은 [문서 지도](DESIGN_INDEX.md), [R30](OPEN_QUESTIONS.md#r30)을 따른다.

## 3. 포탑 관절·배치·발사 표현 — 보고 내용

FBX 파츠를 나누고 다음 논리 계층을 사용했다고 보고됐다.

```text
MountBase   선체 표면 위치/법선에 정렬한 고정 장착 기준
└─ TurretYaw   표면 법선 축을 중심으로 선회
   └─ BarrelPitch   포신 고저각
      └─ MuzzleFlash   발사 이벤트의 표시 효과
```

- MountBase는 선체 메시 레이캐스트와 표면 법선(+Y 상향, ±X 측벽 등)에 따른 직교 기저로 표면에 밀착한다.
- TurretYaw는360도 선회를 지원하고 BarrelPitch가 고저각을 별도 구동한다. **기계 관절360도와 게임 규칙상 전방위 발사 허용은 별개**다.
- 전함 상부 주포/빔/펄스/PD는 함교 탑 keepout을 피해 전방 갑판 중앙선 `X≈0`에 일렬 배치한다.
- 대형/초대형 함체 폭 증가에 따른 무장 과대 확대를 막기 위해 점증 완충 계수0.16·스케일 상한3.85를 적용했다고 보고됐다. 원래 함수/단위·적용 기준 없이 UE 배율로 복사하지 않는다.

## 4. 함체 크기 조정 — 보고 수치 보존

| 대상 | 보고된 변화 |
| --- | --- |
| 소형 초계/호위 | 1.00 유지 |
| Vector DD | 소형과 순양함 사이 크기 |
| Bastion DD | Vector 대비+30% |
| 순양함 | 기존 대비+30%, `half_extents.z=28.6m` |
| 대형 전함/항모 | 기존 대비+50%, `1.21×1.50`, `half_extents.z=50.82m` |

표기는 Godot 원형의 반경/반크기다. `half_extents.z`가 길이 축인 해당 관례에서는 순양함 전체 길이57.2m·대형101.64m·초대형 약260m로 읽어야 한다. 실제FBX 크기/피벗/변환과 수치 일치는 아직 확인하지 않았다. 앞선+10% 체급 배율에 또 반복 곱하지 않고 버전별 최종 크기를 비교해야 한다(R16).

‘맵2배’는 이 보고의 좌표/반경 변경을 뜻한다. 수평 두 축 범위2배면 면적4배이며 고도 pan 범위는 유지됐다. 모든 거리/속도/우주 전체 크기를2배 하라는 의미가 아니다. 카메라 pan·목적지 범위·기준면·드래그 상대고도·무장/레이더 사거리·클리핑은 각각 분리한다.

기존 첨부 카메라의 고도 오프셋 참조(±180)와 이번 보고의 이전값(±160)이 다르므로 같은 원형/중간 버전이라고 가정하지 않는다. 이번 수치로 현행 UE의 카메라/이동 입력을 바로 덮어쓰지 않는다.

## 6. UI·뷰어 동기화 — 보고 내용

상세뷰어 far2000으로 대형/초대형 잘림을 줄였고 `tick_ship_animations()`를 연결해 RD-37 돔을 인스펙터에서도 회전시켰다고 보고됐다. 6면 장갑 그리드 및3D포탑 클릭 상세 연동은 유지됐다.

후속 UE에서는 원 시뮬레이션의 선체 자세/포탑각·표시 애니메이션 위상을 읽고 프리뷰에서 다시 전투 계산하지 않는다. 레이더 돔 회전은 탐지 효율과 독립인 시각 효과이며, 카메라 far를 늘렸다는 사실이 실제 프레이밍/깊이/성능 문제의 완전 해결을 증명하지 않는다.

## 8. UE 후속 구현에서 고려할 것

1. **표시 계층부터 분리:** 선체 장착점→Yaw→Pitch→포구의 로컬 Transform 계층을 설계하고 테스트 메시로 관절/사각/부모 회전을 검증한다. FBX 도입은 보류한다.
2. **축/단위 변환:** Godot +Y위/±X측면과 UE +Z위/+X전방을 구분한다. 기존 예시변환 `UE=(-GodotZ,GodotX,GodotY)`를 사용할 때 원형 중앙선X=0은 UE Y=0이다. 에셋 임포트 축/피벗은 별도 보정하고 m→cm는 한 번만 변환한다. 0.45rad/s는 약25.78deg/s다.
3. **배치와 사격은 별개:** 표면 법선 스냅·함교 keepout·포탑끼리 겹침·포신 자기 선체 관통·포구 위치를 검증한다. 측면 장착의 발사각은 현재 상/하 반구 규칙에 임의로 끼워 넣지 않고 별도 결정한다.
4. **새 함체 변형의 데이터화:** Vector/Bastion은 같은 중형 내 함체별 층/무장/방어/가격·연구 해금을 분리하는 후보로 둔다. 현재 중형PD3 기준과2/4 예외의 채택은 R30에서 결정한다.
5. **표시 배율≠게임 스탯:** 포탑 크기1.5배를 피해1.5배로 해석하지 않는다. 새 무장 이름은 실전 계열/티어/탄도/공급/개별HP를 따로 정의한 뒤 연결한다.
6. **스케일 변경 영향:** 최종 함체 bounds 기준으로 충돌·회피·선회 여유·6면탄착·카메라 최소/최대줌·선택박스·포드 접촉·접안/조선 출입공간을 함께 검사한다. [기지50m격자](BASE_BALANCE_DRAFT.md)는 초안이므로 큰 함체를 기준으로 재검증한다.
7. **전장 확장 영향:** 실제 레이 기준면과 표시 디스크·입력 클램프·그리드·배경·far를 같은 프로필로 관리하되 각각의 의미는 분리한다. 사거리/탄속/임무 이동시간을 근거 없이 같은 배수로 늘리지 않는다. Godot의 `cam.far`를 UE의 투영/가시거리/컬링 속성과1:1 대응한다고 가정하지 않는다. 경로/왕복시간이 달라지면 [캠페인 모형](CAMPAIGN_SIMULATION.md)의 순반입/임무 시간도 새로 가정해야 한다.
8. **읽기 전용 뷰어:** 본체/프리뷰의 포탑·돔·발사 효과를 같은 상태/이벤트에서 읽는다. 숨김 캡처 중단, UI 제스처 소유권, 전투 이벤트 중복 방지·적함 정보 비공개를 유지한다.
9. **증거 재확보:** 실제 채택/이식 시 버전/파일 해시·단위·테스트 명단/로그·렌더러·배포 산출물을 해당 엔진에서 새로 기록한다. 본 문서만으로 테스트 통과를 재사용하지 않는다.

## 9. 현재 적용 범위

이번 작업은 기록과 후속 고려사항 연결뿐이다. UE 게임 코드/맵/자산·현행PD수·무장슬롯·기지 격자·배포 대상을 변경하지 않는다. [2B 계획](PHASE2_PLAN.md)은 먼저 기존 기반의 실제 교전을 구현하며 이번FBX/새모델 도입을 필수 선행조건으로 추가하지 않는다.
