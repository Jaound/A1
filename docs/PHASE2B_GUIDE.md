# 2B 함대 전투 시험장 안내

> 최신 R2·R3 실행은 [D116 교정 및 종합 검증](PHASE2BR_D116_CALIBRATION.md)을 확인한다. 아래는 이전 단계의 실행/검증 기록이다.

> 최신 R1 목적 명령·보호 구현 및 별도 검증은 [PHASE2BR_COMMANDS](PHASE2BR_COMMANDS.md), 전체 미완료와 다음 R2 작업은 [2BR_PROGRESS](2BR_PROGRESS.md)를 따른다. 아래는 기존 2B 기록이다.

> 2B-R / D118 작업 진행 중: [최신 부분 구현·재개 기록](2BR_PROGRESS.md)을 먼저 확인한다. 아래 내용은 ca6e8e5 당시 2B 기준이며, 쉴드 3%/6%·6.5초 지연은 최신 구현에서 0.6%/1.8%·무지연으로 대체됐다. 목적 명령/보호/교정 전체 완료를 뜻하지 않는다.

기준: UE 5.8.4, 코드 브랜치 `codex/phase1-playground`, 최신 기획 `cac0a6f`(병합 `505e424`). 2A 조작 보완 기준 `be544d7` 이후 사용자가 직접 조작을 확인하고 2B 진행을 승인했다. 2026-11-16 확정 D083~D102를 현재 사격·피해·자동화에 반영한다. 이 문서는 사용법과 정책/시험값을 구분하며, 실제 실행 결과는 [PHASE2B_VALIDATION.md](PHASE2B_VALIDATION.md)에 별도로 기록한다.

갱신: 2026-11-16 KST. 빔·함포·일반/유도 미사일, 탐지·로컬 포탑·이동/공격 독립 자동화와 기존 피해 경로 연결을 설명한다. 빌드·자동 테스트·PIE API·직접 입력의 성공 여부는 위 검증 문서에서 구분한다. 이 가이드는 직접 조작을 실행했다는 증거가 아니다. `COMBAT_BALANCE.md` v0.2는 후보 수치이며 기존 시험장 수치를 일괄 교체하지 않았다.

## 실행

기존 `ControlRange` 맵에서 PIE를 시작한다. 처음에는 기존 2A 조작 시험장이고, **F5 또는 전투 시험장 버튼**을 누르면 2B 배치를 만들고 일시정지한다. F5는 현재 PIE 전투의 HP·명령·공격 기록을 초기화하는 개발용 재시작이며, 디스크의 Content 자산을 저장하거나 덮어쓰지 않는다.

PowerShell:

```powershell
$repoRoot = 'C:\Users\user\source\repos\A1'
$engineRoot = 'E:\UE_5.8'
$projectPath = Join-Path $repoRoot 'Unreal\OrbitalVanguard\OrbitalVanguard.uproject'
$toolsPath = Join-Path $repoRoot 'Unreal\OrbitalVanguard\Tools'
& "$toolsPath\Build.ps1" -EngineRoot $engineRoot
& "$toolsPath\RunEditor.ps1" -EngineRoot $engineRoot
```

에디터에서 `/Game/Maps/ControlRange`를 열고 Play를 누른다. DLL을 사용하는 에디터가 있으면 저장이 필요한 작업을 확인해 종료한 뒤 빌드한다. 도구 설치나 엔진·전역 설정 변경은 필요하지 않다.

전투 배치는 기존 임시 함선 3척을 사용한다. 아군 두 척은 수동 상태, 적 한 척은 자동 교전 상태로 시작한다. Kestrel은 T1 함포·빔 2문, Atlas는 T2 속사 함포·속사 빔·일반 미사일·유도 미사일 4문과 T2 레이더 지원 시험 역할이다. Atlas의 유도 미사일은 하부 장착이다. 적은 T2 함포·빔·일반 미사일을 상부에 장착한다. 재시작 직후 Atlas와 빔이 선택된다. 초기 배치는 아군 `(-1400,-700,300)`, `(-1600,800,300)`, 적 `(1600,0,300)` cm다. 레이아웃은 기존 생성기를 이용한 PIE 전용 독립 데이터이며, 이동 속도·선회 속도·카메라 감도는 2A 값을 유지한다.

## 기본 교전 조작

| 입력 | 동작 |
| --- | --- |
| F5 / 전투 시험장 버튼 | 2B 시험장 시작 또는 재시작. 일시정지, 시드 `260112` |
| 아군 왼쪽 클릭 | 조작할 함선 선택 |
| T → 적 왼쪽 클릭 | 공격 표적만 지정. 수동 상태와 발사 제어를 유지 |
| 적 위 우클릭 짧게 누른 뒤 해제 | 기존 표적 우선 입력으로 공격 표적 지정 |
| N / 무장 선택 | 다음 무장을 선택 |
| B / 선택 무장 발사 | 선택한 무장에 1회 살보 발사 요청 |
| L / 전체 무장 발사 | 선택 함선의 공격 무장들에 각각 1회 살보 요청 |
| MOVE: AUTO/MANUAL 버튼 | 이동 자동화만 전환. 공격 자동화·Hold·수동 자세 유지 |
| FIRE: AUTO/MANUAL 버튼 | 공격 자동화만 전환. 이동 자동화와 이동 명령 유지 |
| AUTO 버튼 | 이동·공격 자동화를 둘 다 켬. 기존 Hold·이동·수동 자세 유지 |
| AUTO FREE 버튼 | 두 자동화를 켜고, 진행 중 이동·수동 자세·FTL 충전이 없을 때만 Hold를 명시적으로 해제 |
| MANUAL 버튼 | 이동·공격 자동화를 둘 다 끔. 플레이어가 경로·자세·발사 요청 제어 |
| X / 정지 버튼 | 관성 감속 후 Hold. 정지한 채 사격 가능 |
| F1 또는 Space | 일시정지 전환 |
| F2 / F3 / F4 | 1배 / 2배 / 3배속 |

수동 발사 요청은 즉시 명중을 실행하는 버튼이 아니다. 시뮬레이션이 진행되고 사거리·탐지·시설·개별 무장 HP·사각·포탑 조준·쿨다운 조건을 통과할 때 실제 발사한다. 일시정지 중 입력한 요청은 시뮬레이션 재개 후 처리한다. 표적 지정과 발사 요청은 별도 상태다.

이동 수동+공격 자동, 이동 자동+공격 수동을 포함한 네 조합을 지원한다(D101). XYZ 이동 주문은 **이동 자동화만 끄며 공격 자동화는 유지**한다. 공격 자동이면 유효 표적 선정·발사를 수행하고, 공격 수동이면 표적 지정만으로 발사하지 않는다. MOVE AUTO만 켜는 것은 Hold 해제가 아니다. 기존 전체 MANUAL/AUTO 버튼은 두 설정을 함께 바꾸는 프리셋이다.

AUTO FREE는 일반 AUTO와 달리 사용자가 정지 유지 해제를 직접 요청하는 시험 조작이다. 소형·중형 시험 함선은 아군이 사선을 가리면 Z 오프셋 이동을 한 번 요청하고, 도착하면 기존 이동 규칙에 따라 다시 Hold한다. 사선이 열려 있으면 선체 피치·요를 제한 속도로 표적에 맞춘다. 대형 시험 함선은 Z 재배치를 하지 않는다. 전략적 추격·편대·자동 재배치 반복 AI는 구현하지 않는다. X 정지, 명시적 이동, 수동 자세, FTL 제한이 이 보조 동작보다 우선한다.

PlayGame3 궤도 회전·휠 줌·F 추적·우클릭 고정 XY/드래그 고도·V/Enter 정밀 이동, 상세 창 회전 제스처 소유권을 유지한다. `P` 프로필 비교, `R` 수리 예약 입력(실제 보급 수리는 미구현), `1~9` 부대 선택과 `Ctrl+1~9` 저장도 기존 그대로다. 자세한 이동은 [2A 가이드](PHASE2A_GUIDE.md#playgame3-기본-조작)를 따른다. 새 B/L/N/F5는 `DefaultInput.ini`의 독립 액션으로 분리했다.

## 전투 상태 읽기

HUD는 선택 함선·표적·무장, 탐지 출처, 발사 가능 여부와 차단 이유, 재사용 대기, 요청·발사·피해 결과를 표시한다. 표시에서 사용하는 준비 상태와 실제 발사 판정은 같은 전투 API에서 계산한다. HUD와 상세 프리뷰는 결과를 읽으며, 선이나 탄착 표시를 그리는 과정에서 발사·피해를 다시 실행하지 않는다.

시설 파괴·점령·운영 인원 부족, 개별 무장 파괴, 사거리 밖, 탐지 없음, 상하 사각, 조준 중, 재사용 대기는 서로 구분한다. 개별 무장을 수리해도 무기제어실이나 공급 시설이 정지돼 있으면 발사할 수 없다. DEV 피해·복구 버튼은 시험 상태를 준비하는 도구이며, 실제 교전은 B/L/AUTO 발사 경로를 사용한다.

## 데이터와 피해 경로

`OVCombatSubsystem`이 발사와 공격 수명을 소유한다. `FOVWeaponProfile`에 계열, 종류, 티어, 사거리(cm), 발사 간격(게임 초), 피해, 탄속(cm/s), 정확도, 로컬 포탑 속도·가속·허용각, 살보 수·간격, 공격 수명과 유도 회전 속도를 분리했다. 장착 위치·개별 HP는 기존 레이아웃의 무장 ID에 연결한다. 시설·장갑·레이아웃 코어는 기존 경로를 재사용한다.

한 공격은 발사 순간 공격자 ID·소속·무장 ID·프로필·피해·유도 추적 제한 시간을 보존한다. 이후 공격자가 완파되거나 소속이 바뀌어도 이미 발사한 공격을 삭제하거나 재귀속하지 않는다. 탐지 상실은 신규 발사 가능 조건에 반영하며 비행 중 공격을 취소하지 않는다. 유도 미사일은 목표 완파, 초광속 이탈, 추적 시간 종료를 각각 다른 결과로 종료한다. 포탄은 고정 직선, 일반 미사일은 발사 시 고정한 VLS 곡선과 이후 접선 경로를 유지하며 다른 유효 대상과 충돌하거나 자체 수명이 끝날 때 종료한다. 이탈·완파 함선은 충돌 수신 대상에서 제외한다. 초광속 이탈 통지는 수명 경계 시험 API이며 성계 이동·FTL 여행 전체 기능은 이번 범위가 아니다.

공격의 이동 구간과 회전된 함체·외장 무장 충돌 영역 중 가장 먼저 닿은 대상을 선택한다. 함체 피격은 기존 `ApplyWorldHit`의 쉴드 → 장갑 → 내부 시설 → 전체 HP·유폭·완파 경로를 사용한다. 외장 무장 피격은 `ApplyWorldWeaponHit`으로 쉴드 처리 후 해당 무장 HP에만 적용한다(D089). 무장에 남은 HP보다 큰 피해도 장갑·시설·선체로 넘기지 않는다. 동일 공격이 두 경로를 동시에 실행하거나 피해·유폭을 반복 적용하지 않는다.

외장 무장 충돌체는 장착 로컬 위치의 **반지름 18 cm 구**를 함선 변환으로 옮긴 시험 형상이다. HP가 0인 무장의 충돌체는 제외한다. 형상·반지름·파괴 후 충돌체 제거는 임시 모델 정책이며, 무장 단독 피해 원칙 자체는 확정이다. 실제 함체·포탑 모델 도입과 정밀한 메시 충돌은 별도 작업이다.

빔은 높은 명중 확률 추첨을 사용하되 빗나갈 수 있다. 함포·일반/유도 미사일은 **연속 조준 오차를 한 번 샘플링한 뒤 실제 궤적·충돌**로 판정하며 별도 명중 성공/회피 주사위를 굴리지 않는다(D085). 유도 미사일은 발사 시 오차를 보존한 채 제한 회전 속도로 목표를 추적한다.

빔은 발사 순간 사거리 끝까지 한 번 Sweep하는 즉시 도달 시험 구현이다. 빔 프로필의 `Speed`는 비행 시간에 사용하지 않는다. 다른 공격은 1/120 게임 초 고정 스텝마다 이동 구간을 Sweep한다. 발사 전 아군 사선 차단을 검사하지만, 발사 후 아군이 탄도에 들어오면 실제 충돌 피해를 받을 수 있다. 이것은 물리 충돌 시험 동작이며 최종 아군 피해 정책 확정과 구분한다.

## 임시 프로필과 미결정 정책

단위는 cm·게임 초·도다. 확정 정책을 적용하되 아래 거리·피해·형상·분포 등 **2B 시험 수치는 최종 밸런스가 아니다**. `OVCombatSubsystem.h/.cpp`의 `UOVCombatSettings` 기본값을 기준으로 하며, 프로젝트 `DefaultGame.ini`의 `[/Script/OrbitalVanguard.OVCombatSettings]`에서 설정할 수 있다. 실험 중 변경한 런타임 설정은 저장 자산이나 전역 설정에 반영되지 않는다.

| 설정 | 시험 기본값 | 의미 |
| --- | --- | --- |
| GuaranteedRange | 1600 cm | 레이더가 없어도 사격 가능한 보장 근거리 |
| OrdinaryShareCoefficient | 0 | D090의 확정 초기 공유율. 일반 아군은 탐지 자격만 공유하며 추가 조준 보정 없음 |
| SupportShareCoefficient | 0.8 | D090의 확정 초기 레이더함 추가 조준 보정 공유율 |
| GuidedTrackingSeconds | 8 게임 초 | 미결정 유도탄 최대 추적 시간의 시험값. 공격 자체 수명과 별도 |
| MissOffsetRadiusFactor | 2.5 | 빗나간 빔 조준점 오프셋 계수 |
| ControlAccuracyBonus | 0.02 | 무기제어실 효율에 따른 보정 계수 |
| AutoClearanceHeight | 600 cm | 자동 사선 확보용 Z 오프셋 시험값 |
| bDevelopmentOmniscient | false | 최종 시험장은 정식 근거리·레이더 탐지 경로 사용 |

잔여 살보는 매 탄 직전 발사 조건을 재검사하고, 조건을 잃으면 미발사분을 취소한다(D087). 이 정책은 선택 가능한 임시 플래그가 아니다. 이미 발사한 탄에는 영향을 주지 않는다. 재사용 대기와 살보 탄간 대기는 조건 상실과 구분한다.

무장 표의 `t`는 티어 1~4다. 아래는 시설 효율·레이더 보정 전 절대 기본값이며, 모든 함선이 T4까지 장착할 수 있다는 의미는 아니다. 무장 종류·티어 조합은 `Weapons` 배열에서 별도 프로필 ID로 선택한다.

현재 시험 함체의 기본 장착 상한은 소형 T1, 2층 T2, 3층 T3다. 초대형 시험 함체를 별도로 만들 때만 `RegisterShip`의 네 번째 인수 `WeaponTierCap=4`로 T4를 명시한다. 층수만으로 모든 3층 함체를 초대형으로 취급하지 않는다. `SetWeaponProfile`은 같은 계열·같은 장착 티어에서 종류를 바꾸는 API다. 다른 티어 장착은 개별 무장 티어와 기존 유폭용 `Layout.WeaponTier`가 함께 일치하는 레이아웃을 새로 구성해야 한다. 현재 시험장의 함선별 무장 티어는 모두 같으며 혼합 티어 유폭 계산을 임의 확정하지 않는다.

| --- | --- | --- | --- | --- | --- | --- |
| 속사 빔 `BeamRapid_Tt` | `6000+800×(t-1)` | 0.9 | `45×t` | 즉시 Sweep | 0.94 | 1 |
| 중량 빔 `BeamHeavy_Tt` | `7000+800×(t-1)` | 2.2 | `95×t` | 즉시 Sweep | 0.94 | 1 |

살보 탄 간격은 0.18초, 재사용 대기는 살보 첫 발에서 시작한다. 함포 자체 수명은 8초, 미사일 자체 수명은 15초, 유도 회전 속도는 75°/s다. 포탑 `(속도 °/s, 가속 °/s²)`는 속사 빔 `(100,400)`, 중량 빔 `(35,100)`, 속사 함포 `(70,220)`, 중량 함포 `(22,65)`, 미사일 `(60,180)`이다. 발사 허용 오차는 3°, 상하 중립 각은 ±15°다. 포탑은 유효 목표를 계속 추적하며, **탐지 상실 순간부터 마지막 확인 위치만 3.5게임 초 유지**한 뒤 프로필의 대기 자세로 제한 속도·관성 회전한다(D084). 숨겨진 현재 표적 위치를 읽거나 유지 시간 동안 새로 발사하지 않는다.

실제 피해는 `기본 피해 × 해당 공급 시설 효율`, 발사 간격은 `기본 간격 / max(0.05, 무기제어실 효율 × 공급 효율)`이다. 기본 조준값에 `최선 탐지 보정 + 0.02×(무기제어실 효율-1)`을 더해 0~1로 제한한다. 빔은 상한 0.995의 확률로 사용한다. 함포·미사일은 이 값을 조준 품질로 사용하고 `분산 반각 = 기본 분산각 × (1-조준 품질)`로 오차를 줄인다. 기본 분산각은 함포 5°, 일반 미사일 8°, 유도 미사일 6°다. 발사 시 `tan(분산 반각)×조준 거리` 반지름의 원판에서 면적 균등 오차를 샘플링한다. 이 분포와 변환식은 R21/R22 시험값이며 HUD 조준 품질은 실측 명중률이 아니다.

일반 미사일은 발사 위치·해당 장착면의 로컬 상/하 방향 300 cm 제어점·오차가 반영된 고정 조준점의 이차 곡선을 사용한다. 발사 순간 16구간으로 근사한 길이와 명목 탄속으로 도달 시간을 정하며, 곡선 끝을 지나면 끝 접선 방향으로 계속 비행한다. 발사자나 표적이 움직여도 이미 저장한 곡선을 수정하지 않는다. 곡선 형태·높이·속도 분포는 임시값이며, 발사 시 고정한다는 원칙은 D088 확정이다.

레이더 티어의 거리·명중 보정은 `Radars` 데이터에서 결정한다. T1~T4 기본 범위는 `6000/7500/9000/10500 cm`, 보정은 `0.04/0.06/0.08/0.10`이다. 각 유효 정보의 보정은 `티어 보정 × 정보원 레이더 시설 효율 × 공유 계수`이며 자체 정보 계수는 1이다. 레이더실 중복과 승무원 효율은 보정에만 반영하며 티어 탐지 거리를 늘리지 않는다. 여러 자체·아군 레이더가 유효하면 가장 유리한 보정을 선택한다. 탐지 정보원의 시설 정지·중립·완파·이탈은 즉시 다음 발사 조건에 반영한다.

쉴드 회복은 D083에 따라 **파괴되어 비활성인 동안에만** 진행한다. 전투·비전투 모두 활성 회복은 0이며 50% 재작동 직후 멈춘다. `OVShipSystemsComponent.Tuning`의 임시값은 전투 `ShieldRegenFraction=0.03`, 비전투 `ShieldNonCombatRegenFraction=0.06`(각 최대 쉴드/게임 초), 지연 6.5초, 비피격 15초의 비전투 전환이다. 외부 피격마다 지연을 초기화하는 정책도 아직 시험값이다. 수동 소등 중에는 회복하지 않으며, 기존 `RecoveryPolicy` 필드는 호환용으로 보존하되 활성 완충 경로를 선택하지 않는다.

남은 결정과 제외 범위는 다음과 같이 분리한다.

- **R10:** 고정 VLS·매 탄 조건 검사·조건 상실 시 미발사 취소는 확정이다. 곡선 수치·탄간 간격·쿨다운 기산점은 시험값이다. 표적 변경과 공격 자동→수동 전환은 미발사 자동 살보를 취소하며 이미 발사한 탄에는 영향을 주지 않는다.
- **R14:** 쉴드 이후 외장 무장 HP 단독 피해·선체 전달 없음은 확정이다. 18 cm 구와 파괴 무장 충돌체 제외 등 실제 모델 전의 충돌 형상은 임시값이다. DEV 시험 피해와 실제 무장 충돌 검사를 구분한다.
- **유도 수명:** 추적 시간은 `GuidedTrackingSeconds`, 공격 자체 수명은 무장 프로필의 `Lifetime`이다. 추적 만료 시 공격을 종료하는 것이 이번 시험 정책이다. 최종 수치·추적 만료 정책은 별도 결정 대상으로 남긴다.
- **R11:** 활성 회복 금지·비활성 차등 회복·50% 재작동은 확정이다. 두 회복률·비전투 전환·지연과 재피격 시 지연 초기화는 아직 시험값이다. 과거 2A 활성 Gradual/15초 후 완충은 최신 정책으로 대체됐다.
- **R23:** 혼합 티어 유폭 합산은 미구현이며 동일 티어로 구성한 시험 레이아웃만 사용한다. 수치 후보 v0.2를 근거로 기존 시설·피해 코어를 전면 교체하지 않았다.
- **제외 범위:** 미사일 요격·함재기·강습 포드는 2C, 선내 작전은 3단계다. 전략 AI·편대 운용·최종 밸런스·FTL 여행·최종 함체/포탑 모델은 이 시험장 완료와 구분한다. 백터·바스티온의 기획상 구분은 보존하며 현재 임시 3척을 완성 함급 목록으로 주장하지 않는다.

## 자동 재검증

위 실행 예시의 PowerShell 변수를 정의한 뒤 실행한다. 기존 2A 검사와 새 2B 검사는 별도 PIE 실행으로 구분한다.

```powershell
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" $projectPath -unattended -nullrhi -nosplash '-ExecCmds=Automation RunTests OrbitalVanguard' '-TestExit=Automation Test Queue Empty' '-LogCmds=LogAutomationTest Log'
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor.exe" $projectPath '/Game/Maps/ControlRange' -NoSplash "-ExecCmds=py $toolsPath\ValidatePhase2A.py"
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor.exe" $projectPath '/Game/Maps/ControlRange' -NoSplash "-ExecCmds=py $toolsPath\ValidatePhase2B.py"
```

PIE API 검사는 실제 월드의 API를 호출하지만 OS 마우스·키보드 전달이나 조작감을 검증하지 않는다. 한국어 엔진 시작 자체 검사 오류도 프로젝트 자동 테스트 결과와 별도로 기록한다. 빌드·기존 17개 자동 테스트·기존 57개 PIE 검사·새 전투 검사·직접 입력 결과는 [검증 문서](PHASE2B_VALIDATION.md)에서 각각 확인한다.

## 짧은 직접 입력 확인

1. PIE에서 **F5**, 아군 선택 → **T**, 적 클릭. 표적 표시만 바뀌며 수동 모드가 유지되는지 확인한다.
2. **N**으로 빔을 선택하고 **B**를 누른 다음 **F1**로 재개한다. 포탑이 맞춰진 뒤 발사되고 적 쉴드·피격 결과가 바뀌는지 확인한다. 같은 요청이 끝없이 반복되지 않는지 확인한다.
3. **MOVE**와 **FIRE**를 각각 전환해 네 조합을 확인한다. FIRE AUTO 상태에서 XYZ 이동을 주문해 이동만 수동으로 바뀌고 공격 자동은 유지되는지 확인한다. **AUTO/MANUAL**은 두 설정을 함께 바꾸며 일반 AUTO가 **X** Hold나 수동 자세를 깨지 않는지 확인한다. 이동·수동 자세·FTL이 없는 별도 상황에서 **AUTO FREE**의 명시적 Hold 해제도 확인한다.
4. **F1/F2/F3/F4**, 카메라 회전·줌·F 추적, 상세 창 조작을 함께 확인한다. UI 위 클릭이 전장 명령으로 새지 않는지, **F5** 재시작으로 다시 일시정지·시드 초기화되는지 확인한다.

문제가 있으면 입력 순서, 선택 함선·무장 ID, 표적, HUD 차단 이유, 배속과 `Saved/Logs` 로그를 남긴다. 직접 입력을 실행하지 못한 경우에는 이 절차를 미검증으로 남기며 API 성공으로 대체하지 않는다.
