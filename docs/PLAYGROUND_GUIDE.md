# 3D 조작 시험장 실행·조작 안내

이 문서는 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)의 **첫 제작 단계: 3D 조작 시험장**을 위한 로컬 구현 안내다. 정식 전투·성장 규칙은 [GDD](GDD.md)와 [결정 기록](DECISIONS.md)을 우선한다. 아래 속도·선회 수치와 입력 방식은 시험을 위한 임시 값이다.

실제 빌드·에디터 실행·PIE 조작의 검증 결과는 별도 문서 [PLAYGROUND_VALIDATION.md](PLAYGROUND_VALIDATION.md)에 기록한다. 이 안내에 기능이 기술되어 있다는 사실만으로 모든 실행 검증이 완료되었다는 뜻은 아니다.

## 프로젝트 위치와 기준

- 저장소: `https://github.com/Jaound/A1`
- 기획 기준: `work`의 `77e21f61d5bb508cb9920bebe1ae6f858189d877` 스냅샷. 인증된 GitHub API로 가져온 로컬 shallow import를 기준으로 제작했다. 기존 `origin` 주소를 변경하지 않았으며 원격으로 push하지 않았다.
- 프로젝트: `Unreal/OrbitalVanguard/OrbitalVanguard.uproject`
- 기본 모듈: `OrbitalVanguard`
- 엔진: UE **5.8.4**, 로컬 설치 경로 `E:\UE_5.8`
- 기본 맵: `/Game/Maps/ControlRange`
- 기존 게임과 `C:\Users\user\UE584BuildSmokeTest`는 별도 프로젝트이며 이번 시험장에 사용하지 않는다.

기본 맵과 프로젝트 설정은 저장소 안에 포함한다. 다른 컴퓨터에서는 저장소의 소스·Config·Content·프로젝트 파일을 함께 받아 빌드한다. `Binaries`, `Intermediate`, `Saved`, `DerivedDataCache`는 생성물이므로 복사하거나 버전 관리할 필요가 없다. 엔진 경로가 다르면 아래 `EngineRoot` 인수만 바꾼다.

## 빌드와 에디터 실행

UE 5.8.4와 호환되는 MSVC C++ 빌드 도구 및 Windows SDK가 설치된 Windows 환경에서 수행한다. VS Code만 설치한 상태는 C++ 빌드 환경을 의미하지 않는다. 스크립트는 도구 설치나 전역 설정 변경을 하지 않는다.

저장소 루트에서 PowerShell로 실행한다.

```powershell
.\Unreal\OrbitalVanguard\Tools\Build.ps1 -EngineRoot 'E:\UE_5.8'
.\Unreal\OrbitalVanguard\Tools\RunEditor.ps1 -EngineRoot 'E:\UE_5.8'
```

PowerShell 실행 정책 등으로 스크립트를 실행할 수 없다면 전역 정책을 바꾸지 않고 아래 명령을 직접 실행할 수 있다. 현재 디렉터리는 저장소 루트여야 한다.

```powershell
$engineRoot = 'E:\UE_5.8'
$projectPath = Join-Path (Get-Location) 'Unreal\OrbitalVanguard\OrbitalVanguard.uproject'
& "$engineRoot\Engine\Build\BatchFiles\Build.bat" OrbitalVanguardEditor Win64 Development "-Project=$projectPath" -WaitMutex -NoHotReloadFromIDE
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor.exe" $projectPath
```

빌드가 실패한 경우 에디터를 실행하기 전에 빌드 로그의 첫 오류를 확인한다. 소스 수정 후 재빌드할 때는 PIE를 종료하고 에디터도 닫으면 DLL 잠금이나 Live Coding 상태의 영향을 피할 수 있다.

에디터가 열리면 다음 순서로 실행한다.

1. 기본 맵 `ControlRange`가 열렸는지 확인한다. 아니라면 Content Browser의 `Content/Maps/ControlRange`를 연다.
2. 상단 Play 버튼으로 **Selected Viewport** PIE를 시작한다. `Simulate`는 이 안내의 기준 모드가 아니다.
3. 게임 뷰포트를 클릭하여 입력 포커스를 준다. 왼쪽 패널에 `ORBITAL / VANGUARD`와 함선 선택 버튼이 표시된다.
4. 게임 중 `Esc`는 PIE 종료, `Shift+F1`은 에디터로 마우스 포커스를 돌려주는 UE 기본 조작이다. 다시 조작하려면 게임 뷰포트를 클릭한다.

가독성을 위해 게임 뷰포트 1280×720 이상을 권장한다. 더 작은 뷰포트에서는 HUD와 클릭 영역이 함께 축소되며, 카메라는 왼쪽 패널을 제외한 영역에 기준점을 배치한다. 프로젝트 설정에서 F1·F2·F9의 엔진 기본 디버그 명령을 제거하여 아래 게임 조작과 겹치지 않도록 했다.

PIE를 종료하고 다시 시작하면 임시 함선과 카메라가 초기 상태로 돌아온다. 저장·불러오기 기능은 이번 단계에 포함되지 않는다.

## 시험장 구성

| 함선 | 소속·용도 | 임시 이동 속도 | 임시 선회 속도 |
| --- | --- | --- | --- |
| KESTREL / Escort | 아군 소형 호위함 | 850 u/s | 90°/s |
| ATLAS / Cruiser | 아군 중형 순양함 | 420 u/s | 24°/s |
| RED SIGNAL / Target | 적 정지 표적 | 이동 없음 | 회전 없음 |

`u`는 Unreal 월드 단위이며 기본 단위 체계에서는 1 u = 1 cm다. 실제 우주 함선 규모·속도를 확정한 값은 아니다. 청록색 선택 상자, 위치에서 기준 평면까지 내려가는 고도선, 목적지 연결선을 통해 입체 이동을 구분한다.

함선은 목표 방향으로 제한된 속도로 선회한 뒤 이동하며, 목적지에 가까워지면 정확한 목적지에서 정지한다. ATLAS가 KESTREL보다 느리게 이동·회전하도록 설정되어 있다.

## 카메라와 선택

| 입력 | 동작 |
| --- | --- |
| `W A S D` 또는 방향키 | 현재 카메라 방향 기준 평면 이동 |
| `Q` / `E` | 카메라 기준점 하강 / 상승 |
| 마우스 가운데 버튼 드래그 | 카메라 회전 |
| `Z` / `C` | 카메라 좌우 회전, 한 번에 15° |
| `T` / `G` | 카메라 내려다보는 각도 변경, 한 번에 10° |
| 마우스 휠 | 줌. 이동 명령 입력 중에는 목적지 고도 변경으로 전환 |
| `F` 또는 `FOCUS` 버튼 | 선택 함선 위치로 카메라 기준점 이동 |
| `Home` | 초기 카메라 위치·각도·거리 복원 |
| 함선 왼쪽 클릭 | 함선 선택 |
| `F1` / `F2` 또는 KESTREL / ATLAS 버튼 | 아군 함선 선택 |

적 표적도 클릭하여 선택할 수 있지만 이동·모드 명령의 대상은 아군 함선이다. 왼쪽 패널은 선택 함선 이름, 현재 XYZ 좌표, 속도·선회 값, 수동·자동 상태를 표시한다. UI 문구는 현 단계에서 영어로 표시하는 기술 시험용 UI다.

## XYZ 이동 명령

1. 아군 함선을 선택한다.
2. `R`, 월드의 마우스 오른쪽 클릭 또는 `MOVE XYZ` 버튼으로 목적지 입력을 시작한다.
3. 월드 위에서 커서를 움직여 **X·Y**를 정한다. 입력 시작 시 선택 함선이 있던 고도의 고정 평면과 마우스 광선의 교점을 사용한다.
4. 휠 또는 `Z -250` / `Z +250` 버튼으로 목적지의 **Z**를 변경한다. 한 단계는 250 u이며, Z를 바꿔도 X·Y 계산의 기준 평면은 바뀌지 않는다.
5. 노란 목적지 표시·수직 고도선과 패널의 `DEST X / Y / Z`를 확인한다.
6. 월드 왼쪽 클릭, `Enter` 또는 `CONFIRM`으로 확정한다. 오른쪽 클릭, `Backspace` 또는 `CANCEL`로 취소한다.

명령 입력 중 커서는 계속 X·Y 목적지를 갱신한다. HUD 위에서는 X·Y 미리보기가 고정되므로 고도 버튼과 확인 버튼을 사용할 수 있다. 입력 범위는 임시로 X·Y 각각 −6000~6000 u, Z −1500~4000 u다. 이동 명령 확정 시 선택 함선은 수동 모드로 전환한다.

`Esc`는 이동 입력 취소 키가 아니라 PIE 종료 키다. 이동 중 새 명령을 확정하면 기존 목적지를 대체한다. 현재 시험장에는 경로 큐·장애물 회피·함선 간 충돌 회피가 없다.

## 수동·자동 모드

- **MANUAL:** 사용자가 지정한 목적지로 이동한다. 도착 후 정지해도 수동 상태를 유지하며 자동 행동으로 돌아가지 않는다.
- **AUTO:** 기존 이동 명령과 입력 중인 목적지를 취소하고, 제자리에 머무르며 높이가 다른 적 표적을 향해 체급별 선회 속도로 방향을 맞춘다.
- 수동 이동 명령을 새로 확정하면 자동보다 우선하며 수동 모드로 바뀐다.

AUTO의 제자리 표적 추적은 이번 조작 시험을 위한 임시 행동이다. 전투 기획의 진형·호위·자동 재배치·사격·퇴각 AI를 구현했다는 뜻이 아니다. 공격 무장과 수동 발사는 다음 단계의 작업이다.

## 일시정지와 배속

| 입력 | 동작 |
| --- | --- |
| `Space` 또는 `PAUSE` / `RESUME` | 함선 시뮬레이션 일시정지 / 재개 |
| `1` / `2` / `3` 또는 `1x` / `2x` / `3x` | 함선 시뮬레이션 배속 선택 |

일시정지 중에도 카메라, 선택, 모드 버튼, XYZ 명령 입력이 동작한다. 정지 중 입력한 이동 명령은 재개한 뒤 실행된다. 배속을 선택하는 것만으로 일시정지가 해제되지는 않는다. 카메라는 함선 배속과 독립적인 속도로 움직인다. 패널의 `SIM`은 함선에 적용된 누적 시뮬레이션 시간을 표시한다.

## 검증용 기록과 범위

`F9`는 선택 함선 좌표·모드·이동 여부, 카메라 기준점·각도·거리, 정지 상태·배속·시뮬레이션 시간을 `OV VERIFY:`로 로그에 기록한다. 에디터 Output Log 또는 프로젝트 `Saved/Logs`에서 확인할 수 있다. 수동 확인 시 정지 전후 F9 기록을 비교하면 함선 정지와 카메라 이동을 구분하기 쉽다.

다음 사항은 별도 결과 문서에서 각각 확인한다.

- Development Editor 컴파일·링크 성공 여부와 실제 컴파일러·SDK
- 실제 에디터의 `ControlRange` 열기
- PIE 입력에 의한 선택, XYZ 이동, 체급별 선회와 도착 정지
- 수동 상태 유지, AUTO 전환, 정지 중 명령과 재개
- 배속 변경과 카메라 독립성
- 직접 확인한 조작과 자동 테스트·코드 확인에만 해당하는 항목

이번 단계에는 공격·피해·쉴드·레이더·함재기·선내 전술·영웅·성계 경제·저장 기능이 없다. 세 함선은 엔진 기본 도형을 조합한 임시 표현이며, 기존 게임의 에셋이나 규칙을 가져오지 않는다.
