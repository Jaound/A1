## 요격과 함재기

PD는 비행 중 미사일·함재기·포드에만 작동한다. 강습선을 포함한 일반 함선은 PD 대상이 아니며 함포·빔·미사일의 피격 대상이다. 각 장착점은 실제 거리, 생존·비행 상태, 개별 무장 HP, 요격 제어실 인원·점령·파괴 상태를 확인한다. 주변 아군을 향한 공격도 사거리 안에서 방어한다. 한 발의 성공 확률은 `명중률 × (1−대상 회피율)`이고 추가 회피 추첨은 없다.

기본 시험값은 빔 111m·72%, 실탄 126m·62%, 피해 12·주기 0.5게임초다. 대상 회피 시험값은 미사일 25%, 함재기 62%, 포드 40%다. 장착 수는 후보 함체 데이터의 PD 수를 사용한다. 두 PD 종류를 장착 순서에 따라 교대로 배치한 것은 임시 시험 장착 방식이다.

함재기는 보관·출격·귀환·도킹 대기·관제 상실·완파 상태와 고유 ID를 가진다. 출격은 기존 재고 이동이며, 교전 중 가용 기체는 자동 출격한다. 비행은 개별 돌입·이탈·재돌입 AI이며 플레이어가 기체를 직접 조종하지 않는다. 일반 대함 무장은 함재기를 선정하지 않고 PD·적 함재기가 상대한다. 이미 발사한 기체 공격은 모함 완파·나포 뒤에도 원래 소속 정보를 유지한다.

- **명시 복귀** 후에는 도킹한 생존 기체가 보관으로 돌아간다. 재출격에 같은 ID·손상·재사용 대기를 사용한다. 탄약 소진이나 주기적 강제 귀환은 없다.
- 귀환만으로 수리되지 않는다. Insert의 **DEV 시험 공급 수리**는 정상 격납고의 보관 기체에만 적용하는 시험 공급이며 자원 경제가 아니다.
- 격납고 정지는 출격·도킹을 막는다. 파괴된 격납고 내부의 실제 보관 기체는 완파되며 외부 기체를 재차 차감하지 않는다. 같은 모함의 다른 가동 격납고에 빈자리가 있으면 대체 도킹한다.
- 관제 시설 정지·모함 상실은 외부 기체를 관제 상실로 멈춘다. 시설 복구와 기체 소속 변경은 별개다. 나포 시 살아 있는 기체는 새 소속으로 바뀌되 HP나 관제가 무료로 회복되지 않는다.
- 격납고 용도는 함재기 20대 또는 소형함 1척이다. 추가 함재기 용량 API는 재고·HP를 생성하지 않는다. **독립 소형함의 실제 격납·출격·수리·나포 운용은 미구현**이며 용도·배타 용량 구조까지만 준비했다.

## 개인 포드와 강습선의 복귀

DEV 승객은 실제 영웅 성장·스킬·선내 전투 유닛이 아니다. 영웅형 4명과 병사형 6명의 개인 ID·소속·운송 결과만 시험한다. 개인 1명당 포드 1기이며 발사 시설·거리·개별 발사 시각을 매번 확인한다. 취소된 미발사 인원은 원함에 남고 이미 출발한 포드는 발사 시설을 잃어도 비행한다.

포드는 적 활성 쉴드를 통과하지 못한다. 쉴드 없는 목표의 실제 로컬 외곽에 도달하면 진입 이벤트를 한 번 전달한다. 로컬 상면은 최상층, 하면은 1층, 측면은 해당 높이의 층으로 매핑한다. 확률로 진입을 실패시키거나 선내 작전·함교 점령을 자동 완료하지 않는다. 도착·이탈·사망은 기존 세력별 내부 잔류 보호에 연결되며, PD 방어와 기발사 공격까지 취소하지 않는다.

1. 비행 중에는 **비행 포드 회항**으로 돌아올 수 있다. 회항 중에도 PD에 노출된다.
2. 내부 진입자는 **DEV 원 진입점 복귀 확인**을 누른다. 이는 아직 없는 선내 경로 이동을 실제로 수행했다는 의미가 아니다. 미래 선내 시스템이 ‘원 진입점에 도착’ 이벤트를 보낸 상황을 명시적으로 입력한다.
3. 포드 진입자는 그 장소의 원래 포드를 사용해 실제 귀환 비행한다. 돌아온 포드는 다음 출발에도 같은 ID와 남은 HP를 쓴다. 다른 함선으로 승객만 옮겼다고 포드까지 순간 이동하지 않는다.
4. 강습선 진입자는 동일한 생존 강습선으로 회수한다. **수송선 회수** 뒤 접안 준비와 재탑승을 거쳐 귀환한다. 존재하지 않았던 포드를 새로 만들어 돌아오지 않는다.

강습선은 소형·공격 무장 0·PD 1이다. 진행 중 강습선을 수동 XYZ로 이동시키거나 H·X를 사용하면 `SuspendShuttle`로 자동 운송만 일시 중단한다. 승객·진행 상태는 유지하고, 완파·소속 변경 처리는 계속한다. **수송선 회수**가 중단을 해제해 귀환/회수를 진행한다.

포드 격추·쉴드 충돌과 강습선의 이송 전 완파는 일반 병력 사망 / 영웅형 토큰 구조 대기로 나뉜다. 내부에 이미 진입한 인원은 원 강습선 상실로 원격 사망하지 않는다. 내부 잔류 중 목표 완파는 두 유형 모두 사망이다. 귀환 포드는 모함이 완파·이탈·적 소속이 되면 유효한 아군 함선으로 실제 추가 비행하고, 아군이 없으면 정지·구조 대기한다. 생존 강습선은 유효한 아군 함선 쪽으로 귀환하며, 다른 아군 함선이 전부 없으면 기록된 출발 위치로 돌아가 탑승자를 자기 선체에 유지한다. 이는 포드의 우주 구조 대기와 다른 시험 경계다. 구조·납치·포로 확보·비상탈출·대체 강습선 회수는 아직 수행하지 않는다.

## FTL 시험 경계

항모의 **FTL 시험 충전**은 10게임초와 긴급 함재기 회수를 시작한다. 충전 완료 후 **회수 후 이탈**을 누르면 회수 완료 여부를 확인한다. **미귀환 기체 포기 선택**은 남은 기체를 그대로 두고 이탈할 수 있게 하는 명시적 선택이며, 충전 완료를 생략하거나 기체를 삭제하지 않는다. 외부 잔여 기체는 관제 상실로 남는다. 소유 변경 시 이전 FTL 충전은 취소한다. 이것은 시험용 이탈 이벤트이고 성계 여행·경로·연료 시스템은 아니다.

## 재검증과 직접 플레이 확인

다음은 재실행 명령이다. 결과 숫자는 [검증 기록](PHASE2C_VALIDATION.md)에서 빌드·자동·PIE API·직접 입력을 따로 확인한다. 기존 종합 API 79개에는 이전 2B/R1 검사가 포함되므로 중복 합산하지 않는다.

```powershell
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" $projectPath -unattended -nullrhi -nosplash '-ExecCmds=Automation RunTests OrbitalVanguard' '-TestExit=Automation Test Queue Empty'
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor.exe" $projectPath '/Game/Maps/ControlRange' -NoSplash "-ExecCmds=py $toolsPath\ValidatePhase2A.py"
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor.exe" $projectPath '/Game/Maps/ControlRange' -NoSplash "-ExecCmds=py $toolsPath\ValidateD116Calibration.py"
& "$engineRoot\Engine\Binaries\Win64\UnrealEditor.exe" $projectPath '/Game/Maps/ControlRange' -NoSplash "-ExecCmds=py $toolsPath\ValidatePhase2C.py"
```

PIE API는 실제 월드의 명령·발사·충돌·피해·재고를 확인하지만 OS 마우스·키보드 전달이나 조작감까지 검증하지 않는다. 직접 입력은 미검증으로 남기며 다음 절차로 확인한다.

1. F5/F6에서 Insert 켜기·끄기와 상세 창 열기·닫기를 반복한다. 좁은 창에서도 함선 선택·공격 버튼이 보이고 UI 클릭이 전장 이동으로 새지 않는지 확인한다.
2. 아군 선택 → 우클릭 드래그로 XY·고도 이동 → F 추적 → Home 전체 보기 → T 표적 → B 발사를 수행한다. F1/F2/F3/F4에서 카메라 반응과 발사·탄착 표식을 비교한다.
3. F7의 두 호위 장면에서 요격 우선순위와 방어 범위를 확인한다. 항모 장면에서는 출격 → 명시 복귀 → 도킹 → 재출격 후 수량·손상이 보존되는지 확인한다.
4. 포드 장면에서 부분 격추·진입 → DEV 진입점 복귀 확인 → 실제 귀환을 관찰한다. 강습선 장면에서 이송·같은 수송선 회수와 X/H/XYZ 수동 중단을 확인한다.
5. 혼성 장면에서 항모/강습선을 번갈아 선택해 명령한다. 상세 창을 연 채 장면 전환·재시작을 반복하고, F5로 돌아가 기존 조작이 유지되는지 확인한다.

개선 전후 이미지·영상은 표시와 진행 상황의 증거이며 정지 화면만으로 타격감·조작감을 합격 처리하지 않는다. 성능 또한 실제 측정 편성·화면·시뮬레이션 조건에 한해 해석하며 미측정 대규모 전투를 보장하지 않는다.
