최종 성능3조건과600초는 중복 HitBox 경고와 Error/Fatal이0건이었다. 엔진 EditorDataStorageUI 시작 경고21건/실행은 별도 유지된다. Slate의 U+25BE 누락과 화면의 네모 표시를 확인해 한국어 펼치기/접기/설정으로 바꾸고 N 렌더에서 글리프 경고0을 확인했다. 성능 측정 코드 a0d0915 이후 이 세 문자열만 바뀌며 동작·프리뷰·전투 판정은 같다.

600초에서는96,155프레임, 객체53633→53537(최고53775), 물리1912.699→1911.484MB(시계열 최고1942.434MB)를 기록했다.601표본의 유닛/개인/포드 ID 중복·초기 유닛/개인 누락0, 유닛60·개인60·기체 레코드80을 보존했다. 기체 개별 ID의 중복은 이 성능 시계열 필드에 없으므로 레코드 수 보존과 구분한다. 실제 진입/회수10명, 포드10기였다.

비행 기체는80→60초52→120초28→180초16→약205초부터12기로 줄고 최종68기가 완파됐다. 약300초 이후 생존 함선4척·비행기체12기·비행 공격0으로 낮은 부하다. 기체피격기록 최대256, 요격128, 대함피격128, 선내이벤트125, 작전2였지만 완료 공격 ID집합은14→2181로 누적한 뒤 약296초부터 고정됐다. 모든 기록이 고정상한이라고 주장하지 않는다. 이10분 표본만으로 계속 교전하는 초대규모·무제한 세션의 메모리/성능을 보장하지 않는다.

프로파일 종료구간 `사례-1_단계-1`에는 Fleet3x 표시 타이머의 비정상 표본1개가 있다. 원시 CSV/요약을 보존하고 정상 측정 단계0/1/2만 비교했다. 종료까지 포함한 전체 프로파일 평균은 근거로 사용하지 않는다. CPU 추적 파일은 Saved/Profiling/Trace에 있으며 큰 원본은 Git에 넣지 않았다.

동일 조건의 기본 화면, 영웅창, 상세 프리뷰 비용과 600초 반복 열기·닫기, 3배속 함대 출격·교전·귀환을 나눠 기록했다. CPU/렌더/GPU 시간과 중첩 구간을 중복 합산하지 않는다. 실제 생존 개체 수는 전투에 따라 감소하며 200/300코스트 대규모 보장은 하지 않는다.

## 모델·기획 한계

- 실제 확인 원형은 Play_Game_3.zip SHA256 `bc65912ae558c70ef163ee68e2d6ac767c16de25497cc4e38d197c64f8a80c25`이다. 후속 FBX 프로토타입을 확인한 것으로 주장하지 않는다. 원본 조사 보고서도 함께 참조한다.
