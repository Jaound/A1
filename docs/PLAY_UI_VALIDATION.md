# 최근 검사: BF120 양포구와 상하 장착

**PC14 무장 3방향 실사격 (HD):** 표면 장착 후보를 기존 단일 OBB, 초기 5상자, 측정 기반 27상자와 비교했다. 빔·포탄 각각 상방/전방/측면에서 실제 발사한 시험에서 27상자는 세 방향 모두 무장에 닿았다. 기존 OBB는 세 방향에서 함체가 먼저 맞았고, 초기 5상자는 상방만 무장에 닿고 전방/측면은 함체가 가렸다. 최초 HC 검사는 5상자의 세 방향 성공을 잘못 기대해 실패했으며, 이를 숨기지 않고 관찰된 가림을 명시하는 비교로 수정했다. `PlayUI_R2_HD_Build.log` 성공, `PlayUI_R2_HD_Automation.log` 전체 자동 102/102. 특정 단일 장착점·세 직선 방향의 시험으로 하부·사선·전체 장갑/시설과 대량 성능은 남아 있다. 기본 모델 적용은 아직 하지 않았다.


**PC14 측정 기반 충돌 후보 (HA/HB):** UE의 1,073개 수직 표본 중 Y 10cm 간격으로 27개 상자를 구성하고 Y 5cm 중간 표본을 별도로 비교했다. [후보·원본 SHA·방법](validation/PlayUIR2/HA_PC14충돌후보.json): 중간 표본에서 메시가 있는 190개 지점의 상하면 190개를 포함했지만 메시가 없는 328개 지점 중 28개 XY 위치도 상자에 포함된다. 수직 표본과 동일 X열을 사용한 결과이며 전체 표면의 정확도나 모든 방향 명중률이 아니다. `BuildPC14CollisionCandidate.py` 재실행 결과 SHA256 `0965ee5f04e54f7f220efcb35654af6ec3e8f4bc77c8113d90c5046c2bf44907`로 일치했다. 시험장에서는 [PIE API 13/13](validation/PlayUIR2/HA_PC14측정충돌_API.json), [화면](validation/PlayUIR2/HA_PC14측정충돌_1280.png), HB 실사격 시험에서 해당 27개 상자에 대한 빔/포탄의 위쪽 무장 명중을 확인했다. HB 빌드 성공, 전체 자동 102/102. 측면·하부·비스듬한 피격, 내부 장갑/시설, 충돌 형상 성능과 직접 입력은 미검증이다. 기본 장면에는 적용하지 않았다.


**PC14 UE 표면 추가 측정 (GY/GZ):** 반입된 시험 메시의 UE 렌더 삼각형을 상하 수직 레이로 직접 검사하는 자동 시험을 추가했다. [65개 지점](validation/PlayUIR2/GY_PC14_UE표면65점.json) 중 상·하면 각 29개, [1,073개 지점](validation/PlayUIR2/GZ_PC14_UE표면1073점.json) 중 상·하면 각 378개에서 표면을 찾았다. 나머지 표본에는 메시가 없어 기존 OBB와 시험 5상자가 외형보다 넓은 곳이 있음을 보여준다. 이는 수직 표본이지 전체 삼각형의 연속 충돌 형상을 확정한 것은 아니다. GZ 빌드 및 표면 단독 시험 성공; GY 전체 자동 102/102는 65점 버전 기준이다. 다음: 이 표본과 실제 삼각형을 근거로 보수적인 복합 형상 후보를 만들고, 누락/오차·상하/측면 발사·장갑 매핑을 비교 검증한다. 기본 장면에는 적용하지 않는다.


**시험용 복합 함체 충돌 (GW/GX):** `CombatHullBoxes`가 비어 있으면 기존 단일 전투 OBB를 그대로 사용한다. 시험용으로만 기존 OBB 내부의 여러 상자를 명시하면 공격은 가장 먼저 닿은 상자/무장을 사용하고, 패인 면의 장갑 구분은 충돌 법선을 따른다. 선택과 아군 사선 차단의 기존 OBB는 변경하지 않는다. 상자는 양수·유한·기존 OBB 안·최대 32개로 검증한다. PC14 상부 한 지점을 시험값인 다섯 상자로 근사했을 때 기존 형상에서 가려지던 무장을 실제 빔/포탄이 다시 명중했다. 함체 표면 전체를 측정해 만든 최종 충돌 형상은 아니다. `PlayUI_R2_GW_Build.log` 성공, 전체 자동 101/101, [PC14 시험장 API 13/13](validation/PlayUIR2/GW_PC14충돌상자_API.json), [2B API 50/50](validation/PlayUIR2/GX_2B회귀_API.json). 추가 형상 시각 [렌더](validation/PlayUIR2/GW_PC14충돌상자_1280.png). 실제 마우스 입력·패키징·다수 함선 성능·모든 각도 및 장갑/시설 피해 매핑·하부 장착은 미검증이다. 기본 장면에는 시험 충돌 형상과 원본 무장을 적용하지 않았다. 다음: 실제 선체 표면을 여러 지점·방향에서 측정해 상자 후보를 생성하고, 상하/측면 실사격과 장갑 매핑·기존 OBB 대비 차이를 확인한다.


**PC14 무장 가림 실사격 확인 (GU):** 신규 `OrbitalVanguard.Combat.PC14TrialMountOcclusion`은 기존 OBB와 PC14 후보 장착점 높이로 구성한 시험 함체에 실제 빔·포탄을 각각 요청한다. 기존 Z=42cm에서는 두 공격이 무장에, 표면 후보 Z=3.606cm에서는 두 공격이 먼저 선체에 맞는 것을 확인했다. 이는 해당 수직 방향의 통제된 비교이며 모든 각도의 결과는 아니다. `PlayUI_R2_GU_Build.log` 빌드 성공, 신규 시험 성공, `PlayUI_R2_GU_Automation.log` 전체 자동 101/101 성공. 표면 후보는 여전히 기본 모델에 적용하지 않았다. 다음: 원본 선체 표면에 맞는 충돌 형상 후보를 별도 데이터/시험으로 만들고 상하·측면 실제 발사와 장갑/시설·선택·기존 OBB 회귀를 비교한다.


**PC14 표면 장착 실험 및 충돌상 문제 (GT):** F6 임시 레이아웃만 변경해 BF120 받침대 밑면을 측정된 선체 표면 Z=-2.551cm에 맞췄다. 장착점 Z=42→3.606cm, 발사 원점도 이동했으며 긴 임시 받침대는 시험에서만 숨겼다. [PIE API 12/12](validation/PlayUIR2/GT_PC14표면_API.json), [화면](validation/PlayUIR2/GT_PC14표면_1280.png): 실제 발사·쉴드 명중을 확인했다. 그러나 발사 원점 높이 12.906cm는 기존 선체 OBB 상단 30cm 아래이고, 무장 피격 구체의 상단도 21.606cm로 OBB 아래다. `SweepAttack`은 OBB와 무장 구체 중 먼저 맞는 표면을 선택하므로 외부 상방 피격에서 이 무장 구체가 가려질 우려가 있다(직접 피격 실험은 미실행). 이 배치를 기본값에 적용하지 않았다. 다음: 각도별 실제 포탄/빔의 무장·장갑 충돌을 시험하고 OBB-외형 차이와 별도 충돌 형상 대안을 비교, 기존 피해·선택·저장 호환성을 검증한다. 예제 실행은 `$env:OV_BF120_PC14='1'; $env:OV_BF120_FLUSH='1'; powershell -ExecutionPolicy Bypass -File Unreal/OrbitalVanguard/Tools/RunPlayUIValidation.ps1 -Label PlayUI_R2_GT -Validators ValidateBF120LiveTrial.py -Resolution 1280x720`. 직접 입력·대량 성능·모델 최종 적용은 미검증이다.


**PC14·BF120 결합 시험 (GQ):** F6 초계함의 원본 기반 선체 및 BF120 시험 포탑을 함께 표시하고 API 12/12로 실제 발사·쉴드 명중을 확인했다. [시험 결과](validation/PlayUIR2/GQ_PC14전장_API.json), [별도 PIE 화면](validation/PlayUIR2/GQ_PC14전장_적정거리.png). 첫 화면은 적 함체가 카메라를 가렸고([GN](validation/PlayUIR2/GN_PC14전장_가림.png)), 두 번째는 카메라가 시험 선체에 지나치게 가까워 포탑이 과장되어 보였다([GO](validation/PlayUIR2/GO_PC14전장_근접.png)). 거리 교정 후 포탑 크기는 확인됐으나 기존 물리 장착점과 표면 간 차이로 긴 임시 받침대가 노출된다. **원본 모델의 정상 접합·기본 적용 완료가 아니다.** 다음: 원본 면에 맞는 신규 장착점을 시험 레이아웃에서 교정하고 발사 원점·사선·피격·상하 설치 및 기존 물리/세이브 영향 비교, 적절한 어댑터 형상/재질 검증.
