# 제작 순서와 로컬 개발 안내

> 제작 착수안이다. 확정된 게임 규칙은 GDD와 결정 기록을 우선한다. 아래의 첫 구현 범위는 전체 게임의 기능 축소를 뜻하지 않는다.

## 확인된 환경과 현재 상태

- **사용자가 제공한 로컬 빌드 보고:** Windows 10 빌드 19045, UE 5.8.4(CL 58902052), 엔진 경로 `E:\UE_5.8`.
- 최소 C++ 테스트 프로젝트 `C:\Users\user\UE584BuildSmokeTest`의 Win64 Development Editor 빌드 성공. UCLASS·UPROPERTY 코드 생성, 컴파일과 DLL 링크를 완료했다고 보고받았다.
- 사용된 도구: MSVC 14.51.36260(설치 폴더 14.51.36231), Windows SDK 10.0.26100.0. 최신 컴파일러 관련 경고가 있었지만 성공했다. 이 보고만으로 실제 게임 에디터 실행·PIE·패키징까지 검증된 것은 아니다.
- 이 클라우드 작업 공간에는 언리얼이 없으며 위 로컬 검증을 직접 실행한 것은 아니다. 현재 저장소에는 기획 문서만 있다.
- 게임 코드는 엔진이 있는 로컬 챗에서 빌드·실행하며 검증하는 방식을 권장한다. 이 저장소의 문서가 챗 사이 공통 기준이다.

## 저장소와 프로젝트

- 저장소: `https://github.com/Jaound/A1`, 현재 기획 문서 브랜치: `work`.
- 로컬에 기존 체크아웃이 있으면 원격 주소와 미커밋 변경부터 확인한다. 기존 게임 파일·테스트 프로젝트·브랜치를 초기화하거나 덮어쓰지 않는다.
- 신규 프로젝트 위치 제안: 저장소 아래 `Unreal/OrbitalVanguard/OrbitalVanguard.uproject`. 프로젝트와 기본 C++ 모듈 이름은 `OrbitalVanguard`.
- 엔진은 실제 설치된 5.8.4를 사용한다. 이미 빌드에 성공한 도구를 우선 사용하고 실패 원인 없이 컴파일러 교체·전역 설정 변경부터 하지 않는다.
- 소스, Config, 프로젝트 파일, 필요한 Content 자산을 버전 관리하고 Binaries·Intermediate·Saved·DerivedDataCache 같은 생성물은 제외한다. 로그는 검증 요약에 필요한 부분만 남긴다.

## 첫 제작 단계: 3D 조작 시험장

작은 우주 시험 맵에서 아군 임시 함선 2척과 적 표적 1척을 배치한다. 실제 함선·영웅 에셋은 이후 교체한다.

필요한 동작:

1. RTS 카메라 이동·회전·줌, 함선 선택과 선택 표시.
2. X·Y·Z 위치를 지정하는 이동 명령. 입력 중 목적지·고도를 시각화하고 조작법을 화면에 표시한다. 2D 바닥 이동만으로 완료 처리하지 않는다.
3. 함선의 속도·선회 성능에 따른 이동과 회전. 목적지 도달 후 정지.
4. 명시적인 수동·자동 모드 버튼. 수동 모드는 자동으로 복귀하지 않는다. 선택 상태와 모드를 HUD에 표시한다. 발사 기능은 다음 단계에서 같은 모드에 연결한다.
5. 일시정지·1배·2배·3배 버튼. 함선 이동은 게임 시간에 따르고, 일시정지 중에도 카메라·UI·명령 입력과 재개가 작동한다.
6. 다른 컴퓨터에서 저장소를 받아 재현할 수 있는 프로젝트·맵 설정과 실행 안내.

검증 기준:

- Win64 Development Editor 빌드 성공.
- 실제 에디터에서 시험 맵이 열림.
- PIE(Play In Editor)에서 선택·3D 이동·회전·모드 전환·일시정지와 배속을 확인.
- 검증 결과에 빌드·에디터 실행·PIE 조작을 각각 구분한다. 컴파일만 성공한 경우 플레이 검증 성공으로 기록하지 않는다.
- 에디터·PIE 자동 조작이 도구상 불가능하면 구체적인 제한과 사용자에게 필요한 최소 조작을 적는다.

## 이후 구현 단계

| 단계 | 주요 기능 | 플레이 검증 목표 |
| --- | --- | --- |
| 2. 외부 함대전 | 공격 무장·레이더·사거리·사격 방향·요격, 전방향 쉴드와 장갑·시설·전체 체력 | 적 탐지와 무장 차이가 실제 교전 결과에 반영됨 |
| 3. 강습과 선내 전술 | 고정 슬롯·복도, 영웅·병력 자동 전투, 포드 진입·시설 점령·파괴·나포·탈출·구조 | 실드실 침투 → 쉴드 해제 → 포격 → 포드 귀환 한 작전 완료 |
| 4. 지속형 전략 코어 | 성계·채굴·기지·전초기지·보급, 기초 AI 세력, 저장·불러오기 | 원정·귀환·손실 복구·성장 순환과 저장 재개 |

각 단계는 이전 단계의 실행 가능한 프로젝트 위에 추가한다. 규칙 데이터와 3D·2D 표현을 분리하되, 아직 필요하지 않은 대규모 시스템은 첫 조작 시험장의 선행 조건으로 만들지 않는다.

## 로컬 챗 작업 결과 기록

완료한 기능, 조작법, 빌드 명령, 실제 검증 결과, 남은 제약을 짧은 문서로 저장한다. 기획 변경이나 임시 규칙이 필요했다면 확정 규칙과 구분해 기록한다. 이후 챗은 실제 파일과 검증 결과를 읽고 이어간다.
