# 제작 순서와 로컬 개발 안내

> 제작 착수안 최신본이다. 확정된 게임 규칙은 `GDD.md`와 `DECISIONS.md`를 우선한다. 아래의 첫 구현 범위는 전체 게임의 기능 축소를 뜻하지 않는다.

> 최신 UI 분리·6면 장갑·프로토타입 시행착오를 반영한 세부 진행 순서는 [2단계 계획](PHASE2_PLAN.md)을 따른다. 문서 적용 순서·엔진 이식 기준은 [UE5 제작 공통 기준](UE5_IMPLEMENTATION_CONTRACT.md), 충돌과 미정 선택은 [통합 검토](PLANNING_REVIEW.md)를 먼저 읽는다. 아래 2단계 표는 전체 범위이며 한 번에 모두 구현하는 완료 조건이 아니다.

## 첫 제작 단계: 3D 조작 시험장

작은 우주 시험 맵에서 아군 임시 함선 2척과 적 표적 1척을 배치한다. 실제 함선·영웅 에셋은 이후 교체한다.

필요한 동작:

1. RTS 카메라 이동·회전·줌, 함선 선택과 선택 표시.
2. **X·Y·Z 위치를 지정하는 3D 이동 명령 (방식 A 채택):** 마우스 **우클릭 유지(또는 `Shift` 누른 상태)에서 상하 드래그로 기준 평면으로부터 Z축 고도 오프셋을 지정**한 뒤 확정한다. 입력 중 목적지·고도 기둥을 시각화하고 조작법을 화면에 표시한다.
3. 함선의 속도·선회 성능에 따른 이동과 회전. 목적지 도달 후 정지.
4. 명시적인 수동·자동 모드 버튼. 수동 모드는 자동으로 복귀하지 않는다. 선택 상태와 모드를 HUD에 표시한다.
5. 일시정지·1배·2배·3배 버튼. 함선 이동은 게임 시간에 따르고, 일시정지 중에도 카메라·UI·명령 입력과 재개가 작동한다.
6. 다른 컴퓨터에서 저장소를 받아 재현할 수 있는 프로젝트·맵 설정과 실행 안내.

검증 기준:

- Win64 Development Editor 빌드 성공 및 실제 에디터에서 시험 맵 열림.
- PIE(Play In Editor)에서 선택·3D 이동(`Shift/우클릭` Z축 드래그)·회전·모드 전환·일시정지와 배속 확인.
- 검증 결과에 빌드·에디터 실행·PIE 조작을 각각 구분해 기록한다.

## 이후 구현 단계 (아키텍처 선행 설계 반영)

| 단계 | 주요 기능 | 플레이 검증 목표 |
| --- | --- | --- |
| **2. 외부 함대전** | 공격 무장·레이더·사거리·적도면(±15도) 사격 방향·3종 요격 우선순위, 쉴드(초과 피해 관통·50% 자동 재작동)·가변 층수(1~3F) 장갑·층간 관통·시설·전체 체력.<br>**[선행 데이터 구조]** 2단계부터 함선 내부를 **가변 1~3층 슬롯 그래프(`UShipLayoutDataAsset`: 층·슬롯 ID, 수직 통로 ID, 3D 피격 박스 매핑, 시설 상태)**로 정의해 3D 피격에 사용 | 적 탐지, Z축 사선 회피, 3층 피격 및 층간 관통이 실제 교전 결과에 반영됨 |
| **3. 강습과 선내 전술** | 2단계에서 구축한 `UShipLayoutDataAsset`을 그대로 2D `1F/2F/3F` 전환 미니맵 UI에 연결. 수직 통로 이동, 영웅·병력·터렛/로봇 자동 전투, 포드(수동 회항·고도별 층 진입)·점령(18s/36s)·파괴(30s, 장갑 보존)·나포(함재기 즉시 아군화)·비상 탈출 | 실드실 침투 → 쉴드 해제 → 포격 → 포드 귀환 및 나포 작전 완료 |
| **4. 지속형 전략 코어** | 성계·채굴·기지·전초기지·보급(3단계 자원, 격납고+보급수리함+자원적재실), 기초 AI 세력, 자동 일시정지, 저장·불러오기 | 원정·귀환·손실 복구·성장 순환과 저장 재개 |

각 단계는 이전 단계의 실행 가능한 프로젝트 위에 추가한다. 규칙 데이터와 3D·2D 표현을 분리하되, 아직 필요하지 않은 대규모 시스템은 첫 조작 시험장의 선행 조건으로 만들지 않는다.
