# 제작 순서와 로컬 개발 안내

> 현행 작업 안내: 2026-11-16. 게임 판정은 [담당 명세](DESIGN_INDEX.md), 완료 여부는 [구현 상태](IMPLEMENTATION_STATUS.md)가 관리한다. 아래는 제작 순서이며 전체 UI/기획이 이미 구현됐다는 뜻이 아니다.

## 환경과 저장소

사용자 로컬은 Windows10 빌드19045, UE5.8.4(CL58902052, E:\UE_5.8), MSVC14.51.36260(폴더14.51.36231), SDK10.0.26100.0이다. 최소 테스트와 게임 Editor 빌드 성공 기록이 있다. 이 클라우드에서는 UE 빌드/PIE를 재실행하지 않았다.

저장소는 `https://github.com/Jaound/A1`, 기획 `work`, 코드 `codex/phase1-playground`다. 게임은 `Unreal/OrbitalVanguard/OrbitalVanguard.uproject`에 존재한다. 새 프로젝트를 다시 생성하지 않는다. 소스·Config·필수 Content·도구·검증 자료를 버전 관리하고 Binaries/Intermediate/Saved/DerivedDataCache 등 생성물은 제외한다.

| 단계 | 범위 | 플레이 검증 목표 |

가변1~3층 레이아웃/슬롯 그래프는 2A부터 재사용하며 선내 기능 때문에 별도 피해 시뮬레이션을 만들지 않는다. 정확한 2B 순서는 [2단계 계획](PHASE2_PLAN.md)이다. 전략/선내 기능을 2B의 선행 완료 조건으로 추가하지 않는다.

## 매 작업의 절차

1. AGENTS·현재 Git 상태·코드/기획 원격 변경을 확인하고 로컬 변경을 보존한다. 강제 reset/브랜치 덮어쓰기를 하지 않는다.
2. 분야 명세와 관련 R항목을 확인한다. 임시 정책은 별도 프로필로 표시한다.
3. 기존 코어를 재사용해 실행 가능한 작은 단위로 구현·커밋한다.
4. 빌드·자동/API·직접 입력을 구분해 필요한 검사를 수행한다. 사용자 확인과 도구 자동 입력도 구분한다.
5. 코드 브랜치의 CODEX_PROGRESS/WORK_STATUS와 단계 GUIDE/VALIDATION에 커밋·완료·제약·재실행 명령·다음 작업을 남긴다. 토큰/세션 종료 전에 재개 가능한 체크포인트를 만든다.

현재 완료 단위와 실제 실행 안내는 [구현 상태](IMPLEMENTATION_STATUS.md)가 연결하는 코드 커밋의 문서가 기준이다. 역사적 테스트 수나 재개 메모를 최신 상태에 섞지 않는다.
